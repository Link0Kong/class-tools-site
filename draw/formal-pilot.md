# 班内正式抽签 · 离线试点草案

同班审核者持有事前抄录的活动编号、承诺和指定未来轮次，轮次发生后再取得随机材料。试点在一台离线机器上模拟这两个时间点。候选只使用五个虚构编号，公开图只含允许展示的编号；成员绑定以摘要表示。班内授权查询沿用普通抽签的成员边界。[现有普通模式](CONTRACT.md)

场次 `demo-001` 冻结了候选映射、等权无放回、抽取两人、算法版本与未来第 81 轮。输入采用 UTF-8、对象键排序、无额外空格；冻结前按参与编号排序，冻结后逐字节核对。用承诺摘要、轮值及从 0 起的 8 字节大端计数器生成 SHA-256 字节流。每步剔除超出最大整倍区间的字节后执行 Fisher–Yates 洗牌，取前两个 ID。此版仅定义样例中的 5 人，单字节映射不适用于超过 256 人的场次。

运行 `python draw/tests/formal_pilot.py` 对[固定输入、事件及两次导出](tests/formal_pilot.json)复算。事前见证只含清单承诺与预定时间。离线测试另保存事后材料摘要以验证损坏。数值时刻与轮值均为虚构，实际来源签名和独立见证的保管人尚待产品确定。平台能证明其保存的记录和导出关系；证明事前约定需要审核者独立持有材料。本试点不能据此判断组织者是否曾私下试抽。

| 原报告用例 | 本次证据与剩余门槛 |
|---|---|
| T01–T03 | 规范顺序和固定摘要、同 ID 改参数或绑定、重复 ID 校验。冻结后原名单不可改写；跨语言一致性见 T07 |
| T04–T06 | 缺见证、晚见证、换来源/轮次和损坏均有独立状态；真实信标签名与见证渠道留待产品选定 |
| T07–T10 | 固定输出、2–8 个选项的接受区间穷举、连续拒绝、未知版本和活动重放。第二种独立语言实现属于正式协议退出条件 |
| T11–T14 | 纸面规则要求同一活动+同一清单返回原结果，不同清单报冲突。断网等待同一轮，恢复后复用固定材料。生产并发、崩溃恢复待正式持久化协议验证 |
| T15–T17 | 重复导出同结果，继任关联与证据状态分列。旧结果可同时呈现“复算一致”和“已作废” |
| T18–T20 | 本试点只生成离线材料，未生成二维码。读屏、真实同班访问与在线作废查询需要产品界面；离线包只陈述保存时状态 |

决定进入正式实施前，班级须选定谁在开奖前独立保存公告、可访问候选绑定的角色，以及固定随机来源与撤销方式。验证者须能复查该场次和旧场次。停止试点只需收起草案入口，普通模式和历史图片仍可查。
