一句话结论：福中医宿舍电费走的是完美校园「缴费 → 用电支出（预付费）」，其背后是 新开普云支付网关。查询剩余电量只需要「学校码 + 缴费项目 ID + 房间 ID」，完全不需要登录； 只有「充值」才需要账号与支付密码。因此「获取电费」这件事本身可以做得非常轻、非常稳。

1.1 先说清楚：为什么不是「智能水电」

完美校园体系里其实有两条互不相通的产品线，很多网上的教程混着讲，容易踩坑：

产品线长什么样鉴权本校实测
智能水电 完美校园首页 →「智能水电」，看绑定房间余额/日用电 免 token，只需学校码 + 学号（部分学校还要房间号） 不可用 返回 8099「body 格式错误」；对照学校（桂电北海 759）同请求正常
云缴费（本校走这条） 完美校园 →「缴费」→「用电支出 / 预付费」→ 选缴费房间 → 显示剩余电量 网页端要登录态；但底层云支付网关的查询接口免登录 已跑通 查到 17 间宿舍真实剩余电量

佐证：福建中医药大学 2025-05 学生宿舍 4G 电表采购项目由「福建新开普信息科技有限公司」中标 （学校官网公示）， 与完美校园同属新开普生态。学校 2021 年前的「今日校园 → 购电查询」属于旧入口，现在我们实测确认电费数据在完美校园缴费体系内。

2.3 结论：值得抄什么、不该抄什么

✅ 值得抄
  • cyqmq 的 B2 云支付网关调用：samllProgramGetRoom / GetRoomState 参数与字段，是本校唯一免登录入口。
  • jialiangh 的工程结构：SQLite 台账 + 差值统计 + 低电节流 + 推送适配，做监控很成熟（本次工具沿用其思路）。
  • zuwei522 的学校编码表：福中医 769 三源一致（多份仓库 + Apifox 文档）。
  • ReaJason 的登录协议：将来若需要登录（例如充值），这是最干净的实现参考。
⛔ 不要抄
  • 老引擎（A 线）代码：本校返回 8099，抄了也用不了。
  • 批量扫楼/高并发：lswlc33 的 128 线程会被网关「频繁请求」拦截，也有越权风险。
  • 充值链路：涉及真实支付与支付密码，且需要登录态，自动化风险太高，不做。
  • GitHub Actions / 云服务器定时：完美校园曾对云厂商 IP 返回 405/WAF 拦截，本项目建议本机/家宽运行。

3接口协议（可复现）

本校电费走的云支付网关，全部接口都是同一个端点，用 method 区分动作。 请求格式固定，所有查询接口都不需要登录。

3.1 四个接口

# 端点（所有请求同一地址）
POST https://cloudpaygateway.59wanmei.com:8087/paygateway/smallpaygateway/trade
Content-Type: application/json
Origin / Referer: https://cloudpaygateway.59wanmei.com:8087(/pay/index.html)

# 统一请求体
{
  "method": "<方法名>",
  "bizcontent": "<业务参数 JSON 字符串>",
  "timestamp": "2026-11-05 22:38:19",
  "sourceId": 2
}
方法名作用关键参数（bizcontent）
smallProgramPayPro列本校本生的缴费项目（拿 payproid）schoolcode, idserial(学号), channelno:"30"
samllProgramGetRoom 拼写就是 samll房间树逐层下钻：optype=1 校区 / 2 楼栋 / 3 楼层 / 4 房间schoolno, optype, payproid, areaid, buildid, unitid, levelid, businesstype:"2"
samllProgramGetRoomState查剩余电量（核心）payproid, schoolcode, roomverify, businesstype:"2"
smallProgramUserAuth学号 + 学校码校验（返回是否已认证，可省略）schoolcode, idserial

三个必须知道的坑： ① 方法名 samllProgramGetRoom 里的 samll 是官方拼写错误，写成 small 会失败； ② 楼栋分属两个生活区：13/16 号楼在 areaid=1，23A/23B 在 areaid=4，而 areaid=4 里也有同名的 13/16 号楼（只有 6 个房间，是干扰项）； ③ 所有楼层都返回「虚拟楼层 id=-1」，查房间时直接 levelid=-1，别自己拼 roomverify（房间 id 直接就是 roomverify）。

3.3 鉴权与限制

项目结论
登录 / 密码 / 短信查询不需要；只有充值与账单详情需要登录态（本方案不涉及）
频率限制网关有「频繁请求，等待 60s」的软限制；短时间过量会返回 WAF 拦截页（HTTP 405 / code_:9004），几分钟自愈。建议每轮查询间隔 ≥1s，全量刷新每小时 1 次即可
数据新鲜度接口实时返回电表剩余量，与完美校园缴费页一致
稳定性非官方接口，厂商随时可能改协议；目前（2026-11）实测可用

5班级工具站集成设计（方案二）

5.1 架构

本机 Windows 计划任务（每小时，pythonw 隐藏窗口）→ 读取 17 间宿舍房间 ID，串行请求完美校园云支付网关
↓ 17 个 GET 级请求，约 20 秒，间隔 ≥1 秒
完美校园云支付网关（cloudpaygateway.59wanmei.com:8087）→ 返回每间宿舍 quantity 剩余电量(度)
↓ 携带管理员身份 token 写入
CloudBase PostgreSQL · public.power（行级安全：登录班级成员可读，仅管理员可写）
↓ 浏览器原生 fetch（现有 PostgREST 通道）
班级工具站「全部」页 → 宿舍电费卡片 → 下拉选择「关注宿舍」→ 只显示该宿舍的大字剩余电量 + 低电标红

5.2 数据契约

字段类型说明
idtext PKroomverify（稳定主键，如 4-23B---423），改宿舍名不影响主键
labeltext规范显示名，如 23号楼B座423（统一格式：{楼号}号楼{座}{房间号}）
building / roomtext规范楼栋名（13号楼 / 16号楼 / 23号楼A座 / 23号楼B座）/ 房间号

updated_attimestamptz本次同步时间

另有一张采样表 public.power_history(id, roomverify, quantity, unit, ts)：同步脚本每小时追加 17 行、保留 30 天，用于「近 24h 趋势 / 估算可用天数」；RLS 同为「登录可读、仅管理员可写」。

不存姓名、不存学号；页面只显示「关注的宿舍 + 电量」。宿舍名统一格式：{楼号}号楼{座}{房间号}，如 13号楼324 / 23号楼A座321。

5.4 前端交互（已上线，v3 数据仪表盘）

  • 入口：「全部」页新增「宿舍电费」卡片（不改顶部 4 格布局，用户已确认）。
  • 每个账号只关注一个宿舍：页面顶部一个「关注宿舍」下拉框（按楼栋分组），随时可改。
  • 数据仪表盘：电量环（刻度 = 估算可用天数 / 30 天，环内大字剩余电量 +「≈N 天」+ 状态）+ 趋势折线 + 4 个指标（估算可用 / 区间用电 / 低电阈值 / 上次充值）+ 低电红色提醒条。
  • 趋势可切换 24h / 7天 / 30天（分段控件），图带固定竖坐标轴（y 轴刻度）与横向滑动（历史可左右拖看）；区间用电随档位变化。
  • 上次充值：从历史采样检测电量上升跳变，显示「上次充值时间 + 重置度数」（无记录显示「—」）。
  • 充分利用空间：桌面 ≥960px 左右两栏铺满（左 5 : 右 7，高度撑满视口，1280×1000 底部余量 27px）；平板横排；手机纵向三段，不再有 65% 空白。
  • 估算可用：24h + 7 天双窗口分段统计（充值跳变整段跳过），按 0.65 : 0.35 混合；速率下限 0.05 度/天；≥30 天显示「≥30 天」并满环，tile 副标「≈X 度/天」。
  • 低电阈值可调：点「低电阈值」tile 弹出 8 档（10–100 度，40px 可点）；默认 30；判定 q<low → 低电、low≤q<low×2 → 偏低；随账号同步（power={sel,at,low}）。
  • 选择会同步：写入 CloudBase userdata blob v6 新增 section power = {sel, at, low}，换浏览器/换设备用同一账号登录后自动恢复；两个账号互不影响。
  • 视觉：沿用站点现行 Monet 调色板（暖白 / 雾青 / 暖沙 / 红），状态三档（充足 / 偏低 / 低电）全部通过 WCAG AA 对比度；页面不出现姓名、学号。

7风险与合规

风险说明应对
非官方接口协议随时可能被厂商调整，届时查询会失效工具做了错误分类与日志；失效时重抓一次缴费页请求即可更新参数
频率 / WAF请求过密会触发「频繁请求」或 405 拦截页串行 + ≥1s 间隔 + 每小时 1 轮；失败退避，不做高频轮询
越权读取面该接口只凭学校码 + 房间 ID 即可查询（设计如此）只查本班宿舍、只用于本班自己人；不批量探测其他房间、不对外提供查询服务
支付安全充值需要登录态 + 支付密码本方案完全不做充值，缴费仍在完美校园 App 内手动完成
隐私（宿舍号）站点规范里「页面不暴露宿舍号」是一条红线，本功能按用户明确要求展示楼栋房间号（不含姓名/学号）仅登录后可见；如后续要收紧，可改成「只显示自己宿舍」模式
数据延迟依赖本机定时同步，电脑关机时数据会停更页面显示「更新于」，超过 N 小时标灰提示
合规底线：只查询本班已授权的宿舍、只用于同学生活便利、不对外提供查询服务、不做批量扫描、不碰支付。 这类逆向接口属于「自己查自己的数据」，但也不应扩展到他人与其他用途。
