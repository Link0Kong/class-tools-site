## 1. 问题与根因

| | |
|---|---|
| 现象 | 网页端选择「关注宿舍」后，下次打开网页（尤其停在抽签/作业/通知页）又变回未选择；换设备也看不到 |
| 根因 | `UD.sections().power` 直接读内存 `POWER.sel`；`POWER` 只在用户打开电费页 `POWER.enter()` 时才从 UD 缓存恢复。用户停在别的 tab 时，启动同步（`UD.bootPull`）读到空 `power.sel`，与 UD 缓存里的非空选择不同 → 被判为「本机把选择改成了空」→ 把 `power={sel:"",at:now}` 推回云端覆盖真实选择；此后每次打开循环清空 |
| 证据 | 真实页面代码 + CDP Fetch 合成 userdata（拦截云端写）：修复前场景「缓存=云端=423、停在抽签页」捕获 `power.sel=""` 的 POST，云端被覆盖为空；修复后同场景云端保持 423。修复前冻结副本对新增门禁实跑 FAIL，修复后 47/47 |

## 2. 改动

### 2.1 记忆修复（`tools/index.html`）
1. `POWER.bootRestore()`：启动即从 UD 缓存 → 本机兜底 `zq_power_sel_<sid>` 恢复 `sel/selAt/low`（幂等）；`UD.sections()` 读取 power 前兜底调用，`POWER.enter` 开头也调用，`WATER.restoreSel` 改为复用。
2. `UD.localView` power 防丢：隐式空（未初始化 / 非法旧值 / 无基线）不得覆盖非空基线或云端；只有 `POWER._clearedAt`（用户在 UI 里显式清空）允许推送空值；非法基线（旧脏数据）视作无基线。
3. `UD.pull` 自愈：云端 `power.sel` 为空、本机仍有非空选择且非显式清空 → 保留本机选择并以新时间戳补推一次（修复历史上被冒烟清空的云端）。
4. `POWER.applyRemote` 重置显式清空标记；水量页选空同样设置标记。

### 2.2 选择器优化
- 原生 `<select>`（17 项长列表）→ 自定义选择器：触发按钮（当前宿舍 / 占位）+ 浮层面板。
- 面板：楼栋分段 **13 / 16 / 23A / 23B** + 房间网格（23B 4 列、13/16 2 列、23A 3 列；选中 ✓）；空间不足自动向上翻转。
- 交互：点击开合、Esc / 点面板外关闭、打开后焦点落选中房间、`aria-expanded` / `aria-label`、点按 ≥40px（触发器 44 / 楼栋 40 / 房间 42）。
- 隐藏原生 `#pwSelect`（1px、opacity 0）保留为值源与既有自动化兼容；水量页 `#wtSel` 仍为原生 select。
- `.pw-pickwrap` 加入页面手势与工具切换两处豁免（选择器内滑动不切工具）；使用说明补一句同步恢复提示。
