# 微信小程序性能专项优化 · 验收记录（2026-11-17）

## 1. 用户反馈指标（微信后台性能报告）

| 指标 | 实测 | 同类均值 |
| --- | --- | --- |
| 整体打开率 | 93.85%（iOS 50.00%） | 97.76% |
| 总启动耗时 | 1638ms（Android 1726ms / iOS 1027ms） | 1594ms |
| 请求处理耗时 | 251ms | — |
| **请求错误率** | **45.45%**（Android 5/11） | **2.54%** |

> iOS 50% 样本可能很小（如 1/2），但 14MB 响应导致的 iOS 内存压力是明确风险；修复后需等新版本发布后重新观察。

## 2. 根因（实测）

- `public.notices` 全表（`select=*&archived=eq.false`）响应 **14,070,212 B（14.07MB）**，耗时 **1.6s**（本机直连）；其中 `body.items[].url` 8.6MB、`items[].src` 4.4MB、`archive.files[].url` 0.45MB，均为 data URI。
- 小程序冷启动/签名变化即拉整表，`cloud-config.timeout=8000`；弱网超时后 GET 再自动重试一次 → 同一次刷新产生 2 个失败请求。
- 14MB > `utils/cache.js` 的 5MB 总预算 → `cache.set('ntAuto')` 永远失败，每次冷启动重复拉；旧实现先 `splitChunks` 再判预算，额外复制 24 个 600KB 块，抬高主线程/内存峰值。
- 其他可消除的失败源：`visits` 同账号同小时重复写主键 409；`class_members` 冷启动并发 2 次；`ttLegacy` 在 DNS 暂停期仍回退 `tool.furina.fun`；正式/体验版云空间默认请求已暂停域名；云函数无提醒时仍每前台调用 2 次；身份页 80ms 切换在冷启动早期偶发失败。

## 3. 方案（不缩减功能）

### 云端（已应用，幂等）

`deploy/cloudbase/2026-11-17_notice_meta.sql`：

- `notice_lite_body(text)`：只把 `[[CLASS_NOTICE_V1]]` JSON 中 `items[].url/src`、`items[].archive.files[].url/src` 的 `data:` URI 置空并写 `lazy=true`；标题/时间/摘要/文件名/大小/压缩包清单全部保留。
- `class_notices_meta()`：`auth_ok()` 校验；返回与 `notices?select=*` 同构的行数组。
- 实测：**122 行 / 296,482 B / 0 data URI / 65 个 lazy item**（14.07MB → 0.30MB，-97.9%）。
- 匿名调用 401；旧客户端/网页继续走原表，不受影响。

### 小程序

- `utils/cloud.js`：`noticesMeta` 优先；404/405 才回退旧整表；401 不回退并统一 `onAuthExpired()`；`ntGroupFull` 20s；完整 body 只进内存热缓存不回写；`visits` 改 `Prefer: resolution=ignore-duplicates`；`classMembersPull` 单飞；网络失败指数退避（后台轮询）。
- `pages/nt`：lite 附件/图片按 id 懒加载；只自动加载前 2 张**有图片**的卡，其余点「图片加载中… 点击加载」；`_bodyTried` 负缓存修掉「确实未获取」卡片 84 次/页重复拉取。
- `app.js`：顶部不再 require cloud/store/diag/notify；`wx.cloud.init`/`store.get()` 移出 onLaunch；30s 同步延后 300ms。
- `pages/identity`：onReady 立即切 + 600ms 兜底 + `switchTab` 挂起时 `reLaunch` 兜底。
- `utils/cloud-config.js`：`ttLegacy:false`；`utils/cloudspace.js` 未配置 `dropBase` 时正式/体验版直接返回「等待域名备案」，不再打必失败请求。
- `utils/cache.js`：先判预算再切块。
- `utils/identity.js`：401 清身份回身份页。
- `utils/notify.js`：云开发 init 延迟；无提醒时启动不调云函数。

## 5. 部署/回滚

- DB：已 `python deploy/cloudbase/apply_sql.py 2026-11-17_notice_meta.sql`（5 statements，0 fail）；回滚 `DROP FUNCTION public.class_notices_meta(); DROP FUNCTION public.notice_lite_body(text);`，小程序自动 404 回退旧整表。
- 网页：本轮无 `tools/index.html` 改动，无需 OSS/ECS 部署。
- 小程序：源码已改，**需用户用微信开发者工具上传发布后生效**；`VERSION` 仍 2.0.0、UD v6 不变。
- 云空间/大屏互联：正式/体验版在 `dropBase` 为空时暂不可用（域名备案中）；恢复解析后配置 `dropBase` 即恢复；开发版仍可直连 ECS IP。

## 6. 已知取舍

- lite 列表首次打开附件/图片会多一次按 id 请求（20s 超时；完整 body 不持久化），换取启动/错误率/内存全面下降。
- `notices` 表本身仍 14MB（旧客户端/网页不受影响）；后续可让网页也接入 meta RPC。
- iOS 打开率样本可能很小，需发布后看新周期数据；本轮先消除 14MB 内存压力/超时源。
- CloudBase 环境 2026-12-10 到期，迁移时需带走两个新函数。
