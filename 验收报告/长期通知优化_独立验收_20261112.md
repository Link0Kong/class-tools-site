## 4. 独立计算与实现输出的不一致（具体数据）

除下列跨端口径差异外，网页与小程序的主列表/长期区/统计/筛选与验收者独立模型**逐项一致**（集合、顺序、计数均一致，见 §2/§3 的 PASS 项）。

1. **跨端长期 info 排序锚点语义不同（P2）**：真实数据 86 条中 12 张 info 卡里，`g_qqfile_8b01d25799`（items 仅 1 个 file@11-05 09:28）与 `g_ait_d31f303909`（仅 1 个 file@11-07 19:41）：
   - 网页 `cardAnchorTs` 取**任意** item.time → 锚点分别为 11-05 09:28 / 11-07 19:41；
   - 小程序 `cardAnchorTs` 只取 **text/follow** item.time → 两张卡锚点为 0，排到 info 末尾。
   - 结果：同一数据在两端长期区 info 顺序不同。例（其余 10 张一致）：
     mp：`… g_invoice, g_qqfile_8b01d25799, g_ait_d31f303909`；
     web：`… g_ait_d31f303909, g_qqfile_8b01d25799, g_elective, g_qqimg_7e7cee0917, g_invoice`。
   - 归属：两端各自的 `cardAnchorTs` 既有契约不同（mp 契约限定 text/follow），本次排序沿用各自锚点；功能（分组/计数/收起）不受影响，仅排序位置差异 → **P2**，建议后续统一锚点定义。
2. **小程序 `statusOf` 不读 `expired:true`（P2）**：网页模板 `statusOf` 对 `expired===true` 直接判过期；小程序 `statusOf` 无该分支。若云端出现「无时间锚点且 `expired:true`」的通知，网页归「已过期」、小程序会归「长期 info」。**当前 demo/线上数据中该字段为 0 条**，现状无可见影响 → P2。
3. **网页折叠头缺「·」分隔（P2）**：规格文字「长期通知 · N 条」；小程序渲染「长期通知 · 14 条」，网页渲染为「长期通知 14 条」（元素间 flex 间距，无中点）。计数与功能正确 → P2 文案细节。
