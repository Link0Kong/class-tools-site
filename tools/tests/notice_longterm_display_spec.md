# 长期通知优化显示 · 网页 / 小程序共享规格（2026-11-12）

> 用户需求（原话）：「对长期通知进行优化显示，防止长期霸占通知前排」。
> 用户确认口径：**改动网页 + 小程序**；「长期通知」= **长期安排（recurrence）+ 无时间/长期有效通知**；
> 展示方式 = **移到主列表下方、独立折叠区（默认收起）**，主列表只保留时间明确、可处理的通知。

## 1. 定义

`isLongterm(g)` 为真：

1. `g.recurrence` 为对象且 `freq` 非空 → 长期安排（subtype = `recur`，永不按 deadline 判过期）；
2. 否则「无时间/长期有效」：同时满足
   - 无真实截止（`deadlineOf(g)` 为空，含 extensions 最后一条截止）；
   - 无活动时间 `eventAt`；
   - 无报名窗口（`signupStart` / `signupEnd` / 非空 `signupWindows`）；
   - 不是已过期（`statusOf(g).key` 不是 `expired` / `extended_past` / `alert`）。
   → subtype = `info`。

讨论：站内已有 `statusOf` 的 `none`（无时间）语义与「长期有效」高度重合，但 `done` 会抢在 `none`
之前返回，所以实现不能用 `statusOf().key==='none'` 做唯一判据，必须用上面的「无时间锚点」内在判断。

## 2. 分组展示（web = 内嵌通知模板，mp = pages/nt）

主列表（`#list` / `cards`）：

- 全部：非过期 且 非长期通知（已处理仍在主列表，按现有规则排最后）；
- 待处理：非过期 且 非长期通知 且 未处理；
- 已截止：只显示过期通知（不变）；
- 长期通知不再出现在主列表任何筛选里。

长期通知区（主列表下方、已过期区上方；折叠头「长期通知 · N 条」）：

- 默认**收起**；点折叠头展开/收起（`state.expandLongterm` / `data.showLongterm`，会话内状态，不落盘）；
- 只在「全部」筛选出现（待处理/已截止筛选隐藏）；
- 分类筛选对区内卡片同样生效；
- 卡片沿用现有完整卡片；长期安排卡保留「长期安排 · label + 下次 MM-DD 周X HH:MM」，不显示「标记已处理」；
- `info` 卡允许「标记已处理」（与现有主列表非 recur 卡一致）。

排序：

- 长期安排在前，按本地计算的**下次发生时间**升序；
- `info` 在后，按卡片锚点消息时间（`cardAnchorTs`）倒序（新的在上）；
- 仍相同则按数据源顺序（web `GROUPS` 顺序 / mp 云端 `ts.asc` 顺序）。

## 3. 简报统计与筛选

- 「待处理」数、`#briefChip`、小程序工作台待办数：**排除长期通知**（两类都排除）；长期安排原本已排除；
- 「已过期」统计不变；
- 「24h 截止 / 7 天内」仍只统计待处理（长期通知不再计入）；
- 简报「最近截止」列表不出现长期通知（原本长期安排已排除；`info` 无时间本就排最后，保持）。

## 4. 排序口径（主列表，两端一致）

小程序通知页原按云端 `ts.asc` 顺序展示（最旧的在前），本次改为与网页同口径：

1. `alert`（已截止 · 有新名单）最前；
2. `urgent` / `today`（≤24h）；
3. `extended`（已延期）；
4. `soon` / `active`；
5. 同一档内按主显示时间升序（`expireOf` / mp `whenOf`，报名优先）；无时间者最后；
6. `done`（已处理）在主列表最后；
7. 仍相同按数据源顺序。

## 5. 红线

- 网页：单文件零依赖、零外部请求、`APP_VER` 仍 `2.0.0`；模板源在
  `briefdesk-plan/build_notice_board.py`，改后必须重跑生成 demo → `tools/build_notice_embed.py` 重新嵌入
  `tools/index.html`；通知 iframe 的「固定视口 + 内部原生滚动」方案不得改动。
- 小程序：`VERSION` 仍 `2.0.0`；不新增网络请求/依赖；UD v6 契约不变；页面默认展开/收起等交互不变。
- 不得用前端隐藏代替权限；不改云端数据。
- 不允许把「长期通知」整块删除或只保留计数；必须可展开看到全部卡片。

## 6. 验收要点

- 构造数据同时含：长期安排 2 条、无时间 info 若干、24h/7 天内/已处理/已过期各若干；
- 主列表不含任何长期通知；长期区计数正确、默认收起、可展开/收起；
- 「待处理」数不含长期通知；分类筛选/已截止筛选互不串扰；
- 430px 无横向溢出、0 JS 报错、0 外部请求（web）；小程序单测全绿、staticcheck exit 0；
- 既有通知页交互（标记已处理、原始消息、附件、滚动恢复、展开收起）不回退。
