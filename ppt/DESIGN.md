# 班级 PPT 演示 · 设计参考（DESIGN.md）

> 配套 `CONTRACT.md` v1：接口/字段/状态以契约为唯一真源，本文只给设计取舍与交互规格。
> 研究日期 2026-11-09。竞品结论来自公开文档，凡"未查证"处均已标注，不作官方结论使用。
> 术语：**页** = 一张幻灯片；**步** = 页内一次点击后的画面（`steps[j]`）。推进单位是步，老师心智单位是页。

## 0. 五条结论（先看这段）

1. 我们做的是行业里成熟的一档：**静态分步图 + 外挂媒体**（声网"静态文档转换"、SlideShare、Speaker Deck 同族），不在"动画保真"赛道（iSpring/声网动态转换）。别在 UI 上暗示动画被保留。
2. 课堂缺的不是"炫"，是**不卡、能黑屏、能跳页、视频点了才播、错了能退一步**。控制条越少越好，键位跟 PowerPoint 一致。
3. 界面收敛成三层：列表（暖白卡片）→ 播放器（纯黑舞台 + 一条自动隐藏控制条）→ 抽屉（缩略图/备注）。播放器里没有任何站点导航。
4. 老设备预算从**图片体积与解码张数**下手，不从"降分辨率"下手：1600 宽 WebP、常驻 ≤5 张解码、页切换动效默认降级 fade。
5. 小程序两个硬卡点必须先过：**OSS 域名白名单**与 **`<image>` 默认不解码 WebP**（第三节）。

## 一、竞品拆解

### 1.1 云文档 / 在线幻灯片

**Google Slides**
- 入口：右上「幻灯片放映」+ 下拉「演示者视图」；`Ctrl+Enter` 从当前页起播。
- 播放器：全屏、极简（翻页/页码/更多）；`s` 调备注、`B` 全黑、`W` 全白（2019 官方更新）。
- 演示者视图为第二窗口：备注 + 计时器 + 观众问答。**不适用**：问答/远程观众（一间教室一块屏）。

**PowerPoint 网页版（Office Online）**
- 网页版**没有演示者视图**，只有"从头/从当前页放映"（社区答复，非官方功能文档）。
- 媒体依赖浏览器解码 —— 正是教室电脑"媒体不可用"的同类问题。吸收：入口只留两个动词。

**WPS 演示 / 金山文档**
- 演讲者视图 = 电脑渲染备注与计时、手机只发翻页信令；云文档侧上传即转自有格式，播放不依赖本机 PowerPoint。
- **不适用**：手机遥控（本期不做，R7）、双屏演讲者视图（教室单屏）。

**腾讯文档（幻灯片）**
- 远程演示：右上播放图标 → 二维码/链接 → 观众只读同步；演示者可控制观众翻页权限、激光笔同步。
- 入口藏在"播放图标"里，本地未保存时置灰 —— 反面教材：入口状态要可解释。
- 吸收：**"正在演示"是全局状态**，退出要明确。拒绝：远程观众端。

**石墨文档（幻灯片）**
- 官网口径：兼容 .pptx 导入导出；远程/本地演示切换、演讲者/普通视图、激光笔 + 计时器。
- 启示：它把"演示"当文档的一种模式；我们反过来——演示是独立全屏层，因为课堂只需要播放。

**飞书（幻灯片 / 文档演示）**
- 幻灯片：`Ctrl+Enter` 当前页起播、`Ctrl+Shift+Enter` 从头；演示者视图 = 新窗口观众视图 + 右侧备注 + 底部导航栏。
- 文档演示模式：全屏 / 幻灯片两模式，`Ctrl+Shift+P` 进入。
- 吸收：**底部缩略图导航**（我们改左侧抽屉，避免挤压舞台）。拒绝：双窗口。

**Canva 演示**
- 数字键 `1–9` 直接起计时器（按分钟），演示者视图内也能开，可配背景音乐。
- 启示：**单键直达**强于菜单；但课堂不需要计时器，只保留"黑屏"这一枚单键。

**Gamma**
- Present Mode：极简布局 + presenter view + speaker notes + spotlight（聚光高亮某块内容）。
- 启示：spotlight 讲密集表格很好用，但需区域坐标，成本高，列 P2；本期不做。

### 1.2 教育 / 课堂

**希沃白板 5**
- 手机与电脑同账号即"双屏同步"：手机控翻页、批注同步上大屏、拍照上传、调用摄像头直播。
- 课件云同步是元素级，跨电脑/一体机/网页/手机。
- 吸收：**"翻页"是手机端第一功能**。拒绝：批注/投屏/直播（超出范围）。

**101 教育 PPT**
- 手机连 PC 后：放映/结束、左右翻页、点页码弹缩略图跳转、画笔、**黑屏**、激光笔、鼓励动画。
- 最贴近我们场景的一套遥控键位：翻页 + 缩略图 + 黑屏三件套。
- **不适用**：画笔/激光笔/鼓励——需叠在真实放映画面上，我们叠在图片层，做了也不准。

**ClassIn**
- 官方明确：播 PPT 内嵌视频必须先切「点击工具」再点视频框里的播放按钮，否则会**跳过该页**。
- 吸收：**视频必须"点击才播"**，点击区域与视频框一致（我们的 `media` 热点同理）。
- 拒绝：工具模式切换（多一步，课堂受不了）。

**钉钉 / 企业微信 直播课件**
- 两条路：共享屏幕（保动画但吃本机性能）或上传课件到课堂（转图片、分页浏览、可批注、可设自动翻页）。
- 启示：**"上传转图"是低配设备的官方兜底路线**，我们把它做成本地化一等公民。拒绝：自动翻页。

### 1.3 在线 PPT 转换 / 播放

**iSpring**
- 直接把 PPT 转 HTML5/视频，宣称保留触发器、动画、切换、音视频，也能"发布为 MP4"。
- 吸收：产物要能被任意设备消费；拒绝：保真承诺（成本极高，我们要流畅不要还原）。

**声网 PPT 转码（Agora）**
- 官方分两档：**静态转换**（→ PNG/JPG，**不保留动画**）与**动态转换**（→ HTML，保留动画与音视频）。
- 官方限制：源文件最好 ≤50 页，>100 页可能超时；图片分辨率越高越慢；PDF 结果最准；底层 Aspose。
- 对我们最直接的背书兼警告：**页数与图片分辨率是转换耗时的两个旋钮**，也是失败率主因；超页数要在上传前提示，而不是转完才失败。

**SlideShare**
- 上传后转成逐页图片浏览（转场/动画不支持），提供 transcript 与 embed 代码。
- 吸收：**只做"图 + 页码"也能成为产品**；拒绝：社交（点赞/评论/推荐）。

**Speaker Deck**
- 官方：只支持 PDF（≤150MB），上传后拆成逐页播放器；动画/视频/切换一律没有。
- 播放器极简到只有左右键与页码 —— 是我们"克制"的上限参考。**不适用**：PDF 工作流（老师手里是 .pptx）。

### 1.4 演示遥控 / 演讲者视图

**Keynote 遥控（Apple 官方）**
- iPhone 控 Mac：四位数配对码确认、Wi-Fi/蓝牙近场；遥控端可看当前页/下一页与备注。
- 吸收：**配对用"短码确认"**——安全又轻，若做遥控直接抄，不要账号体系。

**蓝牙 PPT 遥控器类 App**
- 手机模拟蓝牙键盘：上一页/下一页、首页/末页、开始/退出、**黑屏开关**、音量键翻页。
- 吸收：**音量键 = 翻页**（安卓必做，单手拿手机时最顺）。

**扫码遥控 Web 插件（开源小项目）**
- 电脑装插件出二维码 → 手机扫码即控；遥控端能看当前页截图、备注、点哪指哪。
- 吸收：二维码配对 + 遥控端显示当前页缩略图；本期不做，记 P3。

### 1.5 共同模式（提炼，不是照抄）

- 播放器骨架高度一致：**全屏内容 + 自动隐藏控制条 + 单键黑屏 + 缩略图跳页 + 备注不进观众视野**。
- 转换类产品都把"进度"当第一等 UI：没有进度就没有信任；教育类差异点全在"手机当遥控器"——而我们三端本身就能开播放器，所以遥控不是刚需。

## 二、吸收什么、拒绝什么

> 只吸收机制，不抄外观与文案：每条都写清"改什么"；任何竞品的界面结构、话术、图标一律不照搬。

### 吸收

- **A1 先占位再上传**：选完文件立刻在列表顶部插卡片（id 已生成），进度就地显示。比"上传完才出现"少一次疑惑（腾讯文档/Google Drive 同款）。
- **A2 单击前进**：整屏可点，右 2/3 前进、左 1/3 后退（契约已定），与 PowerPoint/Google Slides 肌肉记忆一致。
- **A3 单键黑屏 `B`**：讲事情时一键全黑，任意键恢复。PowerPoint 与 Google Slides 都是官方键位。
- **A4 缩略图抽屉**：只显示每页首帧（`thumb`），点即跳页；101 教育 PPT 手机端"点页码弹缩略图"的桌面版。
- **A5 视频点击才播**：热点 = 视频框位置，绝不自动播放（ClassIn 的教训：误触会跳页）。
- **A6 进度即信任**：上传进度用"已传片/总片"，转换进度用"页 x/y"，两者不混成一根进度条。
- **A7 备注可见但不打扰 + 断点可续**：备注抽屉独立、`H` 长按瞬显 1.5s；本地记 `deckId → (slide, step)`，7 天内再进播放器时控制条出现「续播」（不自动跳）。

### 拒绝

- **R1 不做双窗口演讲者视图**：教室电脑几乎都是"复制"显示，第二块屏不存在。
- **R2 不承诺动画保真**：分步图只给"每步最终态"；UI 不出现"动画已保留"，只在降级时给短标签。
- **R3 不做远程观众/问答/直播**：人就在同一间教室。
- **R4 不做自动播放/自动翻页**：讲课节奏必须由人控制（钉钉那套会毁掉一节课）。
- **R5 不做在线编辑**：只做上传 → 转换 → 播放。编辑是 WPS/腾讯文档的战场。
- **R6 不做画笔/激光笔/批注，也不做社交**（点赞/评论/推荐/公开广场）：前者坐标对不上，后者对班级材料是噪音。
- **R7 本期不做手机遥控**（P3）：三端都能自己开播放器，遥控只解决"老师离开讲台"，收益低于成本。

## 三、技术前置查证：小程序能不能直接加载 OSS 上的图片/视频

### 3.1 结论

| 问题 | 结论 | 依据强度 |
|---|---|---|
| `wx.downloadFile` / `wx.uploadFile` 是否要配置「downloadFile / uploadFile 合法域名」 | **要**。官方把 request/uploadFile/downloadFile/connectSocket 一并列入"服务器域名"管控 | 官方明文 |
| `<image src>` 加载非白名单域名的远程 HTTPS 图 | **受同一套域名策略约束，未加白名单大概率被拦**（开发者工具/体验版可关校验，具有欺骗性） | 官方未单写"image 需白名单"，但把"https 图片无法加载、音视频无法播放"并入同一套"服务器域名 + 证书"排查流程 → **灰区，必须真机实测** |
| `<video src>` 网络视频 | **同样受控**；只支持 https，不支持 IP/localhost | 同上 + 社区/第三方一致 |
| `<image>` 能否直接显示 WebP | **默认不能**，需显式 `webp` 属性（2.9.0+，仅网络资源，WebView 渲染） | 官方组件文档 |

出处：《网络 · 使用说明》§1 与 §4「常见问题 / HTTPS 证书」（https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html ），原文："除了网络请求 API 外，小程序中其他 HTTPS 请求如果出现异常，也请按上述流程进行检查。如 https 的图片无法加载、音视频无法播放等。" 这是"图片/视频也走域名+证书"的最强官方依据；但官方**没有**一句话写"image 组件必须配置 downloadFile 域名"，所以只能说"受同一套策略约束"，不能编造成明文规定。

### 3.2 我们这边必须做的 6 件事

1. 小程序后台把 `https://tool-furina-fun.oss-cn-hongkong.aliyuncs.com` 加入 **request 合法域名** 与 **downloadFile 合法域名**（uploadFile 不用：源文件走 PostgREST 分片，不上 OSS）。
2. 域名须 HTTPS + 已 ICP 备案。**"香港地域 + OSS 默认域名"是高风险组合**（备案主体是阿里云，通常能过，但微信是否接受 `*.oss-cn-hongkong.aliyuncs.com` **未查证**）→ 发布前用**真机正式版**（不是开发者工具、不是体验版）验一张图 + 一段视频。
3. 若 OSS 开了防盗链，必须放行**空 Referer** 与小程序固定 Referer `https://servicewechat.com/{appid}/{version}/page-frame.html`（官方明确：小程序 referer 不可设置、格式固定）；否则 403，表现为"图全裂"。
4. 小程序 `<image>` 必须写 `webp="{{true}}"`，否则契约里所有 `.webp` 在真机是白图（开发者工具可能正常，最容易漏）。
5. `wx.downloadFile` 并发上限 10（官方）→ 预加载队列 ≤6，留 4 给业务请求。
6. `<video>` 是原生组件（2.4.0 起同层渲染）→ **媒体层必须独立全屏**，进入时隐藏控制条/抽屉，避免层级打架。

### 3.3 兜底（按优先级）与未查证

- **B1 给 OSS 绑已备案的自定义域名**（CNAME + HTTPS），用作 `manifest.base`。最稳，改动只在转换机一处常量 + 小程序域名配置。
- **B2 换 CloudBase 云存储**：`image`/`video` 自 2.3.0 支持 `cloud://` 文件 ID；**是否免配域名未查证**，需实测。
- **B3 不要"先 downloadFile 到本地再喂 video"来绕域名**：downloadFile 本身也受域名约束，绕不过，只多一层失败；小图 base64 内联仅应急（≤40KB 缩略图，体积 +33%），主图禁用。
- **未查证**：香港地域 OSS 默认域名能否通过微信后台校验；CloudBase 云存储是否免域名；小程序 `pageOrientation:"auto"` 在低端安卓的实际旋转行为。

## 四、三端组件与交互规格

> 通用原则：暖白/雾青只出现在**列表页**；播放器内部一律中性黑白（投影不吃品牌色，也不跟内容抢眼）。尺寸按 1x CSS px，安卓用 dp。

### 4.1 列表页（三端同构）

| 项 | 规格 |
|---|---|
| 容器 | 手机：满宽 −32 内边距；桌面：最大 1120 居中 |
| 顶部 | 标题「演示」20/600 + 右侧「上传」按钮（雾青实心，高 36，圆角 12，14px） |
| 卡片（手机） | 高 96 横向：封面 128×72（圆角 8，`cover_url`，无则暖白占位）＋标题 15/600 单行省略＋元信息 12px `#8A8F8C`「38 页 · 管理员」 |
| 卡片（桌面） | 3 列网格，封面上 16:9 全宽，下两行信息；圆角 16、白底、阴影 `0 1px 2px rgba(0,0,0,.04)` |
| 状态胶囊 | 高 22 / 圆角 11 / 11px；**`ready` 不显示胶囊**（只显示页数），减少噪音 |
| 排序 | 本人进行中置顶，其余 `created_at desc`（契约 §4.4） |
| 更多 | 卡片右上 `⋯` → 重命名 / 下载原件 / 删除（仅本人） |
| 空态 | 居中「还没有演示文件」16/`#6E7370` ＋ 按钮「上传 PPT」；**不放插画** |
| 交互 | 点卡片 = 直接播放（≤2 步到全屏）；长按 = 更多菜单；骨架 3 张 `#F0F1F1` shimmer 1.2s，仅首次进入 |

### 4.2 上传流程

1. 选文件（网页 `input[type=file] accept=".ppt,.pptx"`；小程序 `wx.chooseMessageFile({count:1,type:'file',extension:['pptx','ppt']})`；安卓 SAF `ACTION_OPEN_DOCUMENT` + pptx MIME）。
2. **立刻插入占位卡片**到列表顶部（A1），封面位置显示进度条（底部 3px，雾青）；上传中不阻塞其它操作。
3. 分片上传，进度 = 已成功片数/总片数，文案 `上传 34%`。
4. 完成 → 自动变 `排队转换`，无需用户再点。
5. 失败 → 胶囊变红 `上传中断` ＋ 卡片内一行 `重试`（不弹窗）；取消 → 进度右侧 `×`，软删 + 移除占位。
6. 小程序唯一入口是**聊天记录里的文件**：空态按钮写「从聊天选择」，下面一行 12px `#8A8F8C`「先把 .pptx 发到聊天」——全站唯一允许的说明性小字，否则用户会卡死。
7. 标题默认 = 文件名去扩展名（≤80 字），`⋯` 可改；单文件 >60 页时在上传前给 12px `页数较多，转换较慢`（不要等转完才失败）。

### 4.3 播放器骨架与层级

舞台 `fixed inset:0; background:#000`；图片 `object-fit:contain` 居中，按 `w:h` letterbox；**无任何站点导航/底栏/滚动**。

| z | 层 | 说明 |
|---|---|---|
| 10 | 图片层 | 双 `<img>` A/B 交叉；切完把旧图 `src=''` 释放解码 |
| 20 | 媒体热点 | 归一化坐标 × **图片实际渲染矩形**（不是屏幕矩形） |
| 30 | 媒体层 | 视频/音频独立全屏，进入时隐藏 40/41/51 |
| 40 | 顶部进度 | 2px，轨道 `rgba(255,255,255,.18)`、填充 `.9`，按 step 总进度（契约） |
| 41 | 控制条 | 见 4.4 |
| 50/51 | 抽屉遮罩/抽屉 | 见 4.5/4.6 |
| 60 | 轻提示 | 黑屏角标、错误 toast |

- 左上文件名 14px `rgba(255,255,255,.7)`，进入后 3s 淡出，之后不再出现。
- 首次进入：先用 `cover_url` 铺满（立即有画面），`steps[0].img` 到位后 120ms 淡入替换；**不出现"加载中"文字**。
- 退出：`Esc` / 控制条 `×` / 安卓返回键；有进度且不在末页时弹 2 按钮确认（`继续`/`退出`），其余直接退。

### 4.4 控制条

- 底部居中，宽 `min(720px, 100%−32px)`，高 52，圆角 14，底 `rgba(18,20,20,.72)` + `blur(14px)`（不支持则 `.82` 纯色）。
- 从左到右：`‹` 40×40 ｜ `3 / 12` 15px ＋ 页内步点（6px 圆点，当前白、其余 `.35`，间距 4）｜ `›` 40×40 ｜ 1px 分隔 `.12` ｜ 图标 36×36：缩略图、备注、黑屏、全屏、更多。
- **步点只在当前页 step ≥2 时出现**（1 步不显示，让"这页没有动画"一目了然）。
- 显示/隐藏：任意 `pointermove` 或触摸 → 淡入 160ms；3s 无操作 → 淡出 200ms；隐藏时桌面 `cursor:none`；键盘翻页**不唤出**（讲课时不闪）。
- 手机：高 48、图标 32、底部 `+env(safe-area-inset-bottom)`；`更多` 只放 `下载原件`（`src` 非空才显示）与 `退出演示`。

### 4.5 缩略图抽屉

- 桌面：左侧滑入，宽 288 全高，底 `rgba(14,16,16,.94)`，内部滚动；2 列网格，128×72（16:9），圆角 6，间距 10，页码 11px 白字 + `.35` 黑底角标。
- 当前页 2px `#4E9082` 描边；该页有多步时下方加一条 2px 短线标当前步。
- 手机：底部抽屉高 62vh，3 列（约 104×58），顶部圆角 16 + 36×4 拖拽条。
- **覆盖而非挤压**舞台（避免重排掉帧）；打开 240ms `cubic-bezier(.2,0,0,1)`，遮罩 180ms（仅手机）；先加载可视区 12 张。

### 4.6 备注抽屉

- 桌面：右侧滑入，宽 320，底 `rgba(14,16,16,.94)`，内边距 20，17px/行高 1.7；空则 `本页无备注` 13px `.45` 白。手机：底部 50vh、16px、可拖拽。
- **单屏课堂保护**：备注会投到墙上 —— 抽屉底必须不透明（半透明浮在图上会被误认成演示内容）；`H` 长按 1.5s 瞬显、松手即隐，老师低头一眼就够。
- 只读，不参与导出/截图。

### 4.7 视频热点与媒体层

- 热点：`media` 矩形中心 56px 圆（手机 48），白 92% 三角 + `rgba(0,0,0,.45)` 底；按下 `scale(.96)` 90ms；右下 11px 角标 `视频 0:12`（`dur` → `m:ss`）。
- 点击 → 媒体层：全屏黑、视频 `contain`、底部原生控制（网页 `<video controls>` / 小程序 `controls` / 安卓自绘 3 键），`×` 在左上安全区。
- 结束（`ended` / `×` / 下滑）→ 回**当前 step**，图片不变。
- **视频层不随 step 卸载**：只在换页或退出播放器时卸载，否则老师点下一步视频就没了。
- 音频（`k:'a'`）不占画面：热点降级成 32px 小喇叭，控制条右侧出现 12px 三条波动；再点暂停。
- 失败：热点灰化 + 11px `视频不可用`，**不阻塞翻页**。

### 4.8 状态 / 空态 / 错误文案（≤12 字，不加句号）

| 场景 | 文案 |
|---|---|
| 列表空 | `还没有演示文件` ／ 按钮 `上传 PPT` |

| 失败 | `转换失败` ＋ 下一行 `error` 原文（≤2 行，超出省略）＋ `重试` |

| 退出确认 | `退出演示？` ＋ `继续` / `退出` |

### 4.9 手势与快捷键

| 输入 | 网页 | 小程序 | 安卓 |
|---|---|---|---|
| 前进 | 单击右 2/3、`→` `Space` `PageDown` `↓` | 单击右 2/3、左滑 | 单击右 2/3、左滑、**音量+** |
| 后退 | 单击左 1/3、`←` `PageUp` `↑` | 单击左 1/3、右滑 | 单击左 1/3、右滑、**音量−** |
| 黑屏 | `B` / `.`（任意键恢复） | 控制条按钮 | `B`（外接键盘）/ 控制条 |
| 缩略图 / 备注 | `T` / `S`（长按 `H` 瞬显） | 控制条按钮 | 控制条按钮 |
| 全屏 / 退出 | `F`（进播放即请求一次）/ `Esc`（先关抽屉再退播放） | 横屏 + 自定义导航（无 Fullscreen API）/ 左上 `×` | immersive / 返回键（两次确认） |
| 禁用 | 双指缩放、双击缩放、长按菜单（三端一致） | 同 | 同 |

- 后退粒度 = **step**；`step=0` 时退到上一页最后一步（否则永远退不回上一个动画）。
- 滑动阈值 40px 或屏宽 12%（取大），跟手 ≤120ms，未过半回弹 180ms；抽屉与横向可滚区不触发。
- 触摸区不吃站点其它滑动逻辑（`stopPropagation`），否则会把工具 tab 切开。

### 4.10 三端差异

| 能力 | 网页（单文件/零依赖） | 小程序 | 安卓（Compose） |
|---|---|---|---|
| 全屏 | Fullscreen API；iOS Safari 无元素全屏 → 伪全屏 `fixed 100vw/100vh` | `navigationStyle:custom` + `pageOrientation:"auto"`；不生效则竖屏 letterbox | `WindowInsetsController` 隐藏系统栏 |
| 图片 / 视频 | 双 `<img>` A/B；`<video playsinline controls>` | `<image webp>` + `<video controls>`（原生组件） | Coil（若已有）+ 现有 VideoView/MediaPlayer，不新增重依赖 |
| 预加载 | `new Image()` 预热，并发 4 | `wx.downloadFile` → 临时路径，并发 ≤6（上限 10） | Coil 预热，并发 4 |
| 常亮 / 进度 | `WakeLock`（可选）/ `localStorage` | `wx.setKeepScreenOn` / `wx.setStorageSync` | `FLAG_KEEP_SCREEN_ON` / DataStore |
| 上传入口 | 文件选择器 | **只能从聊天记录选** | SAF |

### 4.11 动效时长

| 元素 | 时长 | 曲线 |
|---|---|---|
| 控制条淡入 / 淡出 | 160 / 200ms | ease-out |
| 抽屉滑入 / 遮罩 | 240 / 180ms | `cubic-bezier(.2,0,0,1)` |
| 步内切换 | 120ms 淡入（低端 0） | linear |
| 页切换 | `fade` 320、`push` 360、`wipe` 380、`zoom` 300、`cover` 340、`none` 0（契约 §7） | ease-out |
| 热点按下 / 胶囊状态 | 90 / 200ms | ease |

**降级开关**：`navigator.hardwareConcurrency ≤ 2` 或 `deviceMemory ≤ 2` 或小程序低端机判定 → 所有 `tr` 强制 `fade 200ms`、步内 0ms。课堂只认流畅，不认花活。

### 4.12 对 CONTRACT v1 的 3 条建议（需 Lead 决策）

1. `push/wipe/zoom/cover` 在 4GB 老机 + 集显上掉帧明显：建议**全端默认只做 `fade`**，其余值保留解析但降级执行（改动只在客户端渲染分支）。
2. 明确"视频层不随 step 卸载"（契约只写"回到当前步"，未写生命周期），并明确"左 1/3 后退粒度 = step"（契约写"上一步"，易被理解成退一页）。
3. `manifest` 增加可选 `ph`（视频占位封面文件名，缺省用该 step 图裁切），否则视频未加载时热点压在黑块上。

## 五、课堂场景专项

### 5.1 性能预算（4GB / 双核 / Intel HD4000 / Chrome 90 基线）

| 项 | 预算 | 说明 |
|---|---|---|
| 主图 | 1600 长边 WebP q72，**≤200KB** | 契约已定 1600/q72；多数页 90–180KB。>200KB 的页建议转换机降 q62 重试一次 |
| 缩略图 | 400 宽 WebP q65，**≤25KB** | 抽屉一次最多 12 张 ≈ 300KB |
| 单份总量 | 38 页 × 1.4 步 ≈ 53 张 ≈ **8MB** | OSS `immutable` 长缓存，第二次进秒开 |
| 首屏 | 1 张主图 + 6 张缩略图 ≈ **350KB** | 进播放器到有画面：缓存命中 ≤1.2s / 首次 ≤2.5s |
| 预加载 | 当前步之后 2 张（契约）+ 相邻页首帧 | 网页并发 4、小程序 ≤6 |
| 解码内存 | 1600×900 RGBA ≈ 5.76MB/张，**常驻 ≤5 张 ≈ 29MB** | 切换后立刻释放旧图（`src=''`），别让 12 张躺着 |
| 视频 | 720p H.264 ≤2.5Mbps，`faststart`，单段 ≤3min | 契约 ffmpeg：`scale=min(1280,iw)`、crf26 |
| 主线程 | 切步呈现 **<50ms**；长任务 >50ms 视为 bug | 不做逐帧动画、不做滤镜 |

### 5.2 投影比例

- 内容永远 `contain` + 纯黑边，**绝不裁切**（裁掉的是老师的板书）。16:9 在 16:10 屏上下各 5% 黑边、4:3 在 16:9 屏左右黑边，都可接受。
- **不提供"填满屏幕"开关**（拉伸变形，得不偿失）；播放器不额外加内容边距；控制条浮在画面下沿 24px 避开字幕区。
- 背景一律 `#000`（不是暖白）：投影黑色不刺眼，也不暴露屏幕边框。

### 5.3 课堂常用操作路径（全部 ≤2 步）

| 目标 | 路径 | 步数 |
|---|---|---|
| 开始放映 | 首页 → 演示 → 点卡片 | 2 |
| 下一页 / 下一个动画 | 单击 / `→` / 音量+ | 1 |
| 退回上一个动画 | 单击左 1/3 / `←` | 1 |
| 跳到第 N 页 | 缩略图 → 点页 | 2 |
| 黑屏讲两句 | `B` | 1 |
| 播嵌入视频 | 点视频区域 | 1 |
| 看备注 | `S` 或长按 `H` | 1 |
| 结束 | `Esc` ×2 / 左上 `×` | 1–2 |

### 5.4 老设备降级清单（按顺序做）

1. 页切换动效统一 fade 200ms（4.11 降级开关）。
2. 图片解码常驻 ≤5 张，超出按 LRU 释放。
3. `backdrop-filter` 不支持 → 控制条/抽屉改纯色 `.82`（不要半透明叠图）。
4. 视频 `preload="none"` + `poster`（用 `ph`/该 step 图裁切），点击才 `load()`。
5. 图片失败保留上一张（画面不跳）并给 `重试`；连续 3 张失败 → 静默降级为 `thumb` 尺寸加载。

### 5.5 弱网与离线

- 判据：`navigator.onLine === false`，或同一张图连续 2 次超时（>6s）；小程序用 `wx.getNetworkType` 监听，切 2G/断网时**暂停预加载队列**（把带宽全留给当前页）。
- 弱网播放：只预取"当前步 + 后 1 步"；失败重试 1 次（退避 1.2s），仍失败降级用 `thumb` 撑满（糊但不断），再失败才 `图片加载失败 · 重试`。
- 离线：已看过的页走 HTTP 缓存（OSS `immutable`）仍可翻；未缓存的页显示灰底 + 页码占位，**不白屏、不崩、不弹窗**。
- 上传弱网：分片失败重试 2 次（契约 §4.2），进度条**只增不减**（用已成功片数，不用字节估算）。
- 明确不做「整份预下载」按钮：8MB 在教室 Wi-Fi 上会拖垮整节课；缓存靠"看过就留下"。

## 七、给三端实现者的 10 条检查点

1. **`webp` 属性**：小程序 `<image>` 必须 `webp="{{true}}"`，否则真机全白（3.2 / 4.10）。
2. **域名三件套**：OSS 域名进 request + downloadFile；发布前用**真机正式版**验一张图 + 一段视频（3.2）。
3. **Referer 放行**：OSS 防盗链放行空 Referer 与 `servicewechat.com`，否则 403（3.2）。
4. **占位先行**：选完文件立刻插卡片再上传；进度 = 片数比，不与转换进度混一根条（4.2）。
5. **步/页双轨**：页码按页、页内步点、顶部进度按 step；`step=0` 后退到上一页末步（4.4 / 4.9）。
6. **视频不自动播、不随步卸载**：热点点击才播，换页才销毁（4.7 / 4.12）。
7. **黑屏 `B` 必做**，三端同键；恢复不显示任何 UI（4.9）。
8. **降级开关**：低端机强制 `fade 200ms` + 步内 0ms；`backdrop-filter` 不支持改纯色（4.11 / 5.4）。
9. **内存纪律**：常驻解码 ≤5 张，切完释放旧 `src`；小程序预加载并发 ≤6（上限 10）（5.1）。
10. **文案纪律**：只允许 4.8 表里的短句；除小程序上传空态那一行，**不新增任何解释性句子**（全站红线）。
