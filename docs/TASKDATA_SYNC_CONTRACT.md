# 个人任务同步与旧客户端混用（W03，v1）

每个已验证账号在 `public.taskdata` 占一行。已有 REST 接口足以让遵守条件写入的设备在冲突后重读合并。隔离 PostgreSQL 也验证了，同一账号的旧端仍可无条件覆盖整行，甚至重复使用已经出现过的版本号。本轮沿用现有表、RLS 和权限，零生产迁移。

## 客户端写入顺序

1. 按账号分开保存最后确认的完整快照 `base` 和待发的本机快照 `local`。请求捕获账号与会话代次，每次异步返回都校验。账号切换、退出以及同账号换票会使旧回包失效。只剩时间戳的旧缓存可供离线展示；没有已确认基线和可识别的操作时，先读云，保留有歧义的本地差异供用户确认。不能把旧缓存的缺项推断为删除。
2. 用原会话 GET `taskdata?id=eq.<sid>&select=blob,ts` 读取 `remote`。已验证身份下可见行的格式必须通过下表校验。RLS 可能把读拒绝呈现为空结果；仅凭 GET 空数组不能宣称已清空、已写入或有权覆盖。无本地编辑时只读。
3. 按稳定 task/list ID，把从 base 到 local 可证明的编辑重放到 remote 上。首次创建使用 POST，传 `Prefer: resolution=ignore-duplicates,return=representation`。有行时使用 PATCH，过滤 `id=eq.<sid>&ts=eq.<读到的版本>`，传 `Prefer: return=representation`。写入一行的 `id,blob,ts`；`ts` 与快照 `updatedAt` 同步推进，取本机毫秒、待发版本、旧行版本加一的最大值，并验证为安全的非负整数。拒绝无法再加一的版本。墙钟和 `updated_at` 都不能单独证明写入顺序。
4. 身份仍有效、响应只含一行并与送出的 id、ts、blob 相符时才能推进 base。回执缺列、错版本或多行时保留待发并重读核实。发出请求以后又编辑的差异继续待发。重读到同一账号、足够新的版本且完整云端投影与待确认写入一致，也可确认；如读到的是其他内容，重新合并。条件更新或首写返回 `[]` 时重新 GET 并合并，每轮同步最多四次尝试（含首次）；用完保留待发，下一次用户操作或恢复网络可重试。

## 合并决策

| 同一账号两台设备的操作 | 重读之后的处理 |
|---|---|
| 不同任务或分组；同一任务的不同字段 | 独立 ID 均保留；同 ID 只改本端显式编辑的字段，其余保留最新远端值。数组字段如步骤由编辑该字段的一方整字段提交。无冲突的未来字段、包装元数据和未编辑的 prefs 原样传递。 |
| 同一 ID 同一字段 | 后一个通过条件检查的显式编辑生效。排序/侧栏设置依原业务稳定 ID 和专用顺序时间戳裁决；传输耗时不构成用户意图。 |
| 删除与已有项目的离线修改相遇 | 删除优先。base 有而 local 删除时移除该 ID；base 有而 remote 已删时，旧修改不得重建它。分组删除后任务保留，失效分组引用清空。显式新增使用新的稳定 ID，继续保留现有来源关联及重复任务去重语义。 |
| 显式清空、另一端同时新增 | 删除本次操作在 base 中见过的 ID。并发新增保留。若合并结果为空，写入带版本的合法空快照和更高 ts；后续仍可条件更新。 |
| 附件与来源 | 云端投影移除本地文件记录，attachments 省略或置空；收到其他设备的快照后按稳定任务 ID 接回本设备附件。来源作业/通知 ID 与来源描述随任务保留。 |
| 两端同时导入同一来源或生成同一期重复任务 | 新任务按 sourceHwId / sourceNoticeId，重复子项按 fromId 与 due 识别同一次生成，保留已确认的远端 ID。下一期保留独立 ID。 |
| 未知旧基线、缺失或重复实体 ID | 不能无歧义推断的变更保留本机待核对。保留服务端原文，避免静默修复成空快照。 |

## 载体与旧端读取

SQL 的 blob 是 text。新建行继续写 JSON 文本的扁平 `{"v":1,"items":[],"lists":[]}` 结构。每个存在的实体都有稳定字符串 ID。显式删除和旧协议里的初始空占位分别处理。

| 已读形态 | 读取与回写约定 | 已有实现差异 |
|---|---|---|
| 扁平文本，items 为数组；含合法空数组 | 保留 lists、prefs、未来字段，文本写回；缺省 lists 可读。清空不使用 SQL DELETE。 | 现有多端常用形态，旧 Web 浏览器 mock 仍可读常规任务、分组及侧栏顺序。 |
| 旧包装 JSON 文本，有 task、data 或对象 v，最多三层 | 在已识别的同一路径替换叶子，保留原包装与同级字段。 | 鸿蒙 TaskWire 已支持。Android 当前只解析顶层 items；M09 接入并覆盖损坏形态。 |
| 历史适配器/本机缓存直接给对象 | 在适配边界接受相同形态，保留原载体；访问正式 text 列时编码成 JSON 文本。 | 鸿蒙读取器支持对象。没有将对象出现频率或来源推断为线上数据库实况。 |
| GET 无可见行；真实旧占位 blob 为空串且 ts=0 | 在当前身份下可以尝试受保护的首次创建；已有占位仍按旧 ts PATCH。合法空数组与 SQL 默认占位分开记录。 | 已有原生实现接受更宽松的空值；下游不得把非零版本空串、缺列、null、坏 JSON 或无法识别的结构当作清空。 |

## 响应及验证对照

| 模拟路径 | 检查方式与实际结果 | 状态与后续动作 |
|---|---|---|
| 两设备同时读无行，分别插入；旧条件 PATCH 后到 | 实际 SQL 的第二次 DO NOTHING、过期 WHERE 均返回零行；按最新行重放后两条任务都在 | 零行为重读；返回对应行才确认。 |
| 清空确认丢失、另一端发旧写 | 舍弃实际 UPDATE 返回后读回更高 ts 和合法空数组；旧谓词得到零行 | 网络超时先显示“待同步 · 已保存本机”，重读确认；旧操作不得复活删除。 |
| 每次重新读取后又遭遇竞争 | 四次 SQL 旧条件写均返回零行，原快照保留 | 停止本轮，保持可重试。 |
| 跨账号、票据过期、写入期间更换票据 | 隔离库使用 anon，带原策略；跨账号/失效读及更新返回零行，插入拒绝 42501。假回执另测 401/403 和迟到成功 | 当前会话明确拒绝时显示“登录失效/无权限 · 更改留在本机”。旧会话的成功或错误都丢弃，保留原账号草稿。网络层的空响应不可直接解释为个人行不存在。 |
| 无条件旧 POST 混用同一行 | 实际执行旧 upsert 可从较高 ts 回写 10、重用先前 ts 后使陈旧条件写再次命中，也可带更高时钟整体覆盖 | RLS 继续保护账号归属，同账号旧整行仍可能丢改动。混用时不承诺跨设备无损。 |

单纯拒绝降低 ts 的触发器无法拦住高时钟旧整行，也会改变旧客户端的回执。本批沿用既有条件接口。W06（Web）、C05（微信小程序）须移除无条件写并保留旧缓存读取；M09（Android）保留已有条件写，补历史载体、远端删除后离线编辑与回执验证。鸿蒙已有条件写和任务删除保护，本批的 M02 处理独立的 userdata 仓储。回退到旧端继续写会重新打开整行覆盖窗口；若需在所有写者升级前提供全量保证，应另外决定写入口的版本准入及旧端兼容方案。

**现有鸿蒙实现的验收边界。** 使用 DevEco 自带 TypeScript 在内存执行 TaskWire 与 mergeTaskEdits，已验证嵌套载体、远端删除优先及作业/通知/重复实例去重。TaskWire 也接受非零版本空串、null、重复任务 ID 及无 ID 分组。把本机文件字段注入合成任务后，合并器保留了这些字段，需在发送投影验证剥离。分组和 prefs 编辑目前由提供这些编辑操作的端负责。TaskRepository 的现行写确认只检查非空数组，会话判断只要求同一账号对象且有 token。G03 的鸿蒙个人任务签收应单独覆盖同账号换票、异常回执、损坏快照与附件投影，不能用 userdata 已通过的 M02 替代。

**其他端的实测差异。** 通过 JVM 调用本机 Android 构建的 mergeTasks 与 taskCloudView，兼容空附件及缺省 lists 的等价编码后，9 个合并向量中 7 个通过。远端已删除的任务被离线编辑复活，同一个 fromId/due 的重复子任务会多出一条，交由 M09 同步修正。旧 Web 和小程序的归一化只读取顶层 items；W06/C05 必须先识别包装或暂存无法解释的原文，避免把坏输入显示或写成已清空。

## 复跑

在 Web 仓运行以下 PowerShell。夹具只含合成 ID。Node 22+ 负责运行模型；PGlite 在内存执行仓内原始 taskdata SQL。会话变量仅替代身份函数，无外部请求或项目依赖变更。SQL WHERE/RETURNING 对照 PostgREST 的请求语义；浏览器回归另用 Web 现有 mock。

```powershell
$qaDir = Join-Path ([IO.Path]::GetTempPath()) ('taskdata-qa-' + [guid]::NewGuid().ToString('N'))
npm install --prefix $qaDir --no-save --no-package-lock --ignore-scripts @electric-sql/pglite@0.6.0
$env:NODE_PATH = Join-Path $qaDir 'node_modules'
node --test deploy/tests/taskdata_contract.cjs
python -B tools/tests/task_cloud_check.py
```
