## 3 控制技术路径（云控 vs 蓝牙/BLE）

### 3.1 结论
**最可能：混合架构——云端负责账号/绑定/订单/扣费/优惠券/报修，手机通过蓝牙（BLE）在本机近距离向洗衣机下发洗衣指令；没有公开证据表明可「人不在机器旁」远程启动。**
- 置信度：**中高**（多条独立线索同向；但缺少 6.5.9 真机抓包，故不能写「已证实」）。
- 备选解释：部分新机型可能内置联网模块（招标要求「物联网系统」），由云端下发指令；但公开面**没有**任何远程洗衣/远程启动的说明或宣传，且 6.5.x 仍保留强蓝牙特征。→ **需真机抓包/PoC 验证**。

### 3.3 控制流程（多源一致，高）
下载注册 →「洗衣」页「绑定洗衣机」输入机身编号（或扫码）→ 选模式（强力/标准/快速/单脱水/洁桶）→ 选水位（低/中/高）→ 确认余额/支付 → **点「通电洗衣」** → 进度/剩余时间 → 完成提醒；故障走「报修」。来源：官网、商店描述、多校通知、公开商店截图（§1.3、§4）。置信度：高。

### 3.4 如果控制是 BLE，对第三方网页意味着什么（技术判断，高）
- 浏览器（含微信内置 WebView、iOS Safari）**不支持对任意 BLE 设备的 Web Bluetooth**（iOS Safari/微信 WebView 无 Web Bluetooth；Chrome Android 有但需 HTTPS、用户手势、且要机器 GATT 服务/特征值协议）；微信小程序有 `wx.createBLEConnection` 等，但**需要小程序 appid 且在小程序内**，外部网页无法调用。
- 即使拿到账号 token，还缺「BLE 指令格式/加密」——公开资料只有旧版论坛口述，未证实、且很可能已变。
- → **网页端「控制洗衣机」在 BLE 路径下技术上不可行**（除非厂商开放云 API，见 §2.1，公开面为零）。

## 8 对本项目可行性判断的启示（供可行性报告使用）

> 前提：班级工具站是**单文件、零依赖、纯前端静态站**（无后端、无支付资质、无厂商合作），用户是班级同学，功能诉求是「控制洗衣机 + 充值」。

1. **控制洗衣机：不可行（高置信度）**
   - 公开面无官方 API/开放平台/合作文档；唯一入口是 App。
   - 若控制为 BLE（现有证据最支持），网页/微信 WebView 无法发 BLE；即便用微信小程序 BLE，也需**小依自己的 appid**，且用户必须在机器旁、需逆向 GATT 协议——属未授权接入。
   - 若控制为云 API，也需账号 token + 协议逆向，同样无授权、违反实名/支付类账号安全要求，且 52pojie 先例已显示「改包绕过扣费」的刑事风险。
   - 结论：**任何「网页一键开洗」方案都应否决**；不要做 PoC 抓包，也不要用同学账号试。

2. **充值：不可行（高置信度）**
   - 充值在 App 内完成，支付渠道为 App 自有收银台（支付宝/银联等 SDK）；第三方网页无法合法调起。
   - 班级工具站若代收代充（先收钱再帮充）涉及**二清/支付资质**；若存同学账号密码/token 代登录，涉及个人信息与账号安全。
   - 结论：**不做代充、不做余额代管、不存账号密码/token**。

3. **「接入」唯一现实形态：信息层 + 引导层（可行）**
   - 可做：洗衣价格/模式时长/报修电话（0591-38251600）/使用教程/常见故障（水龙头、进水超时、面板灯）/「去下载小依 App」二维码或应用商店链接/各校入口提示。
   - 不可做：任何自动化控制、余额查询、订单同步、代登录、代充。
   - 注意：**不要把 App 图标、小依商标做成官方合作暗示**；标注「非官方，仅信息整理」。

4. **若确实要做深：走「校方/后勤—厂商」正式合作（唯一合规路径）**
   - 福建师大 2026 招标已把「物联网系统」写进运营方义务、且学生扫码缴费收入归运营方；班级工具站可作为**学生侧信息/提醒工具**，由校方或运营方提供只读接口（如空闲状态、价格）后再接；需书面授权与数据最小化。
   - 可把「请运营方提供只读查询页/小程序入口」作为与后勤沟通的具体诉求，而不是自行逆向。

5. **风险与红线（写进报告结论）**
   - 法律：未授权访问/绕过支付（刑法 285/286/287、网络安全法 27）；账号借用违约；个人信息（手机号/宿舍/支付）处理需单独同意。
   - 平台：微信小程序抓包/改包可能触发微信风控；厂商有发法律函/下架第三方接入的先例（海尔欧洲 2024）。
   - 运维：即使做出 PoC，也会随 App 版本（6.5.x 频繁更新）随时失效，维护成本高、责任不可控。

6. **建议的可行性结论措辞**
   - 「控制洗衣机 + 充值」：**不可行（不建议立项）**；无官方开放能力，控制链路为本机蓝牙（高概率），充值无第三方合法入口，且触及未授权访问与支付合规红线。
   - 「洗衣信息/报修/教程/价格」：**可行（低风险）**；纯静态内容 + 外链 App 商店页，不涉及账号与支付。
   - 「宿舍洗衣空闲/排队」等增强：**当前不可行**（无公开 API）；除非取得校方/运营方书面授权与只读接口。
