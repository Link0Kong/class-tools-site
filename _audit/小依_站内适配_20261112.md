## 0. 结论摘要（TL;DR）

1. **站内架构可以承载「只读查询 + 入口引导」**：绑定关系、余额/机器状态快照、审计日志，都有成熟的站内先例可照抄
   （PGP 信封 + 队列 + worker 的课表登录链路 `deploy/cloudbase/2026-11-08_diag_login.sql:164-214`）。
2. **「代充/站内支付」必须排除**：本站是个人主体 + 非经营性备案，没有支付资质；备案自查明确提出要去掉「充值」字样
   （`_compliance/备案内容自查_20261106.md:34-35,49-50`），微信个人主体小程序也不能做支付
   （`_compliance/research_delivery_paths.md:83`）。充值只能「引导到官方 App/学校官方渠道」，站内**不碰钱、不留支付凭证、不出现充值字样**。
3. **「站内远程控制洗衣机」技术上可做、架构上不建议做**（详见 F2）。若用户坚持，唯一不破前端红线的形态是
   **B③′「PostgREST RPC 队列 + ECS worker 轮询」**（前端仍只调 PostgREST，AGENTS.md:22），延迟 2–5s（常驻轮询）或 ≤60s（定时器）；
   想要 1s 级直连（B③）必须**用户书面同意**新增同源路径 `/xy/*`（先例：`/drop/*`，AGENTS.md §4b-33/37、`deploy/ecs_site.py:126-130`）。
4. **不要把新功能建在 CloudBase 云函数上**：环境 **2026-12-10 到期（剩 28 天）**（`AGENTS.md:112`、`CLOUDBASE.md:690`、
   `_audit/cloudbase_data_audit_20261111.md:60-62`），且云函数访问不了校园内网（教务实测先例 `HANDOFF.md:2381`）。
   长期依赖应落 ECS（杭州 2C2G，`deploy/ECS_DEPLOY.md:17`）。
5. **凭据只允许「密文 + 用后即清 + 不进前端/仓库/日志」**：小依密码照课表登录链路——密码 → PGP 信封 → worker 解密 → 用后清空；
   token 用服务侧密钥加密后落库或只落 ECS 文件（root 0640）。**手机号一律不落库、不展示、不导出**（AGENTS.md:23、`HANDOFF.md:259`）。
6. **工作量**：①入口卡 0.5–1 人日；B③′ 5–8 人日；B③ 6–9 人日（另加小依协议 PoC 3–5 人日）；
   B② 云函数 3–5 人日（不建议）；B④ 本机 agent 3–5 人日（可靠性不达标）。均不含独立验收（+1 人日）与合规评审（+0.5–1 人日）。
7. **最推荐的落地顺序**：先做 **B①（静态信息 + 官方入口卡，零风险）**，同时用附录 G 的 6 个决策门把「要不要控制」交回用户/小依方拍板；
   在 G1（可达性）与 G4（小依方许可）没结论前，不要写任何真实接口代码。

## A. 硬约束清单（逐条引用 AGENTS.md 原文）

判定标记：✅ 可碰（在约束内实现） / ⚠️ 需用户书面同意或额外评审 / ❌ 不能碰（直接否决该做法）。

### A1 单文件零依赖（无构建链）

- 原文（`AGENTS.md:13-14`）：「**不得引入构建链**：禁止 npm / yarn / pnpm / vite / webpack / TypeScript 编译 / 任何前端框架。
  产物必须是**双击即可打开**的 HTML；JS 只用原生浏览器 API。」
- 原文（`HANDOFF.md:256`）：「❌ 不要引入 npm/框架/构建步骤；不要拆分文件导致无法直接用浏览器打开。」
- 对本功能：新工具必须内联进 `tools/index.html`（一个 `__XY_V1__` 块：CSS 在 `</style>` 前、HTML `#s-xy` 在 `#s-all` 前、JS 在文件尾），
  坐标系示例见 `file` 工具块（`tools/index.html:18257` `TOOLS.push({k:"file"…})`、`:18259` `ALL_TONE.file`、`:18267` `__WEB_B2_JS_END__`）。
- 判定：✅（照 `file`/`ppt`/`vote` 的挂载法）；任何「装 SDK / 引小依 JS / 起 dev server」都是 ❌。

### A2 前端只允许一个接口（本方案最硬的门）

- 原文（`AGENTS.md:22`）：「前端只允许原生 `fetch` 调 PostgREST 一个接口；`localStorage` 降级为缓存，请求失败仍可用。」
- 原文（`AGENTS.md:17`）：「**所有班级数据**（作业、通知、名单、体测、marks、访问统计等）都走 CloudBase PostgreSQL + PostgREST，
  RLS 统一校验 token；**不能用前端隐藏代替权限**。」
- 站内现状：确实存在**用户明确要求后的例外**——`file`（临时云空间）页直接 `fetch` 同源 `/drop/*`
  （`tools/index.html:16523` `STG_DROP_BASE`、`deploy/drop_app.py`、`drop/CONTRACT.md:30-45`、`AGENTS.md §4b-33/37`）。
  该例外是**用户 13 项反馈驱动**的（`CHANGELOG.md` 增量 45），不是可以默示扩权的先例。
- 对本功能：❌ 前端直连小依 API；❌ 未经用户同意新增 `/xy/*` 同源调用；✅ 走 PostgREST（表 / RPC）；
  ⚠️ 用户书面同意后可加同源 `/xy/*`（照 drop 的 Caddy handle + 同源策略）。
- 判定：**所有方案都必须先回答「前端这一跳走 RPC 还是走新同源路径」**（见 B 章对比）。

### A3 零外部请求

- 原文（`AGENTS.md:46`）：「**零外部请求**：不引 Google Fonts、CDN、统计脚本、埋点。」
- 对本功能：小依 App 二维码 / 说明图必须放同源 `tools/assets/` 或 data URI；不得引小依 web 组件、统计、字体、支付 SDK。
- 判定：✅；外链**导航**（点击后跳走）是允许的，历史已有学习通/慕课/教务外链（`_compliance/备案内容自查_20261106.md:23`），
  但页面上不能自动加载其资源。

### A4 身份门禁 + RLS 统一鉴权

- 原文（`AGENTS.md:16-19`）：启动必须先「学号+姓名」匹配名单拿 token；「网页用 `X-Device-Id: <token>`…小程序用 `X-Class-Token`；
  服务端 `auth_hdr()` 两者都接受」；管理员＝陈子麒。
- 原文（`CLOUDBASE.md:20-22`）：token 30 天；所有班级数据请求都必须带 token。
- 对本功能：任何「余额 / 机器状态 / 控制记录」都是班级数据 → 必须 RLS + RPC 校验 `auth_sid()`；不能靠前端隐藏。
  **控制类接口尤其不能用「页面没显示按钮」当权限。**
- 判定：✅（照 `stage_prefs` 的「仅本人」RLS `deploy/cloudbase/2026-11-11_stage_prefs.sql:36-56` 与 `polls` 的
  「两表对 anon 完全无直连、只经 SECURITY DEFINER RPC」`CLOUDBASE.md:770-771`）。

### A5 隐私红线（手机号 / 学号 / 宿舍号）

- 原文（`AGENTS.md:23-24`）：「**禁止在导出图片或页面上暴露手机号、学号、宿舍号等个人隐私。**
  唯一例外（用户 2026-11-05 明确要求）：电费页展示「本人关注宿舍」的规范楼栋+房间号+剩余电量（无姓名/学号），此数据**不导出、不对外分享**。」
- 原文（`HANDOFF.md:259`）：「❌ 不要上传用户名单/手机号等个人数据。」
- 对本功能：小依账号大概率绑手机号 → **手机号不能落库、不能展示、不能进日志**（需以脱敏 hint 代替，如 `138****1234`，
  且建议连 hint 都不存）；绑定的洗衣机若显示「13号楼324」这类宿舍号，**属于新的隐私例外，必须用户单独批准**（不能援引电费例外，
  那是 2026-11-05 针对电费页的明确授权）。只读余额/状态本身不含身份信息，风险低。
- 判定：⚠️（展示机器/宿舍信息需用户批准；其余按最小化实现）。

### A6 密钥零泄漏

- 原文（`AGENTS.md:10-12`）：「**密钥零泄漏**：`deploy/creds.env`、`tools/cert/`、`deploy/acme_account_key.pem` 是机密。
  **不得读取其内容、不得复制、不得粘贴进对话或任何外部请求（包括模型上下文）。** 部署脚本只通过"读取文件"的方式使用它们。」
- 原文（`HANDOFF.md:258`）：「❌ 不要把任何密钥写进前端代码或仓库（`index.html` 里**一个 secret 都不能有**）。」
- 站内既有做法：ECS 侧凭据只以文件形式落地并以 0640 权限运行（`drop/CONTRACT.md:42-43`）：
  「**publish_key 只以文件形式落在 ECS**…由 `deploy/ecs_drop.py` 从 `deploy/cloudbase/publish_key.txt` 读取后上传，**不打印、不进代码/日志**。」；
  ECS 服务「不接触 AK/SK/token」（`deploy/pptfiles_app.py:18-22`）。
- 对本功能：小依密码/刷新令牌/服务侧加密密钥 = 新增机密类；只能在 ECS 文件（root/服务用户 0640）或 PGP 密文里，
  不得进前端、仓库、`client_diag`、任何日志、任何对话。
- 判定：⚠️（可做，但必须像 publish_key 一样「文件化 + 不打印」；见 C 章凭据列设计）。

### A10 DNS 暂停期部署态（当前真实环境）

- 原文（`AGENTS.md:113`）：「**用户暂停 furina.fun DNS 前先 `--on`，恢复解析后 `--off`**」；
  `AGENTS.md:166`：「DNS 暂停期 `site_config.web.paused=true`（恢复解析后 `web_pause.py --off`）」。
- 现状（`deploy/ECS_DEPLOY.md:24-27,41-49`）：ECS 只有 `:80`（HTTP）；HTTPS 配置 `Caddyfile.https.ready` 已校验但**未启用**
  （DNS 停用中无法签发）；线上静态站以 **OSS 字节校验**为准（`deploy/oss_object.py:4-6`：`python deploy/oss_object.py check index.html` = MATCH）。
- 对本功能的影响（重要）：
  1. 线上页面走 OSS 默认域名 → `location.protocol === "https:"`，此时前端调 `http://121.196.47.2/xy` 会被浏览器 **mixed content** 拦；
     `/drop` 现有代码就是按协议二选一（`tools/index.html:16523-16527`），HTTPS 页面下只能走同源 `/drop`——而 OSS 上没有这个路径。
  2. 本机调试通道 `deploy/local_channel.py` **只代理 CloudBase `/__cb/`**（`deploy/local_channel.py:87-92,123-158`），
     **不代理 `/drop` 也不代理 `/xy`** → 开发期要么 mock fetch、要么扩展 local_channel（属开发工具改动，需同样走双远端提交）。
  3. 验收：新前端一律 `oss_object.py check` 字节比对；新后端用 `ecs_*_verify` / 公网 HTTP 探活（DNS 恢复前 HTTPS 无法验）。
- 判定：⚠️（可做；但「DNS 恢复后同源」才是正式形态，测试计划必须覆盖两种协议）。

## C. 数据模型草案（建表 / RLS / RPC 风格 / 与 UD v6 的关系）

### C0 设计原则（全部来自站内既有做法）

1. **账号键只用班级 sid**（`auth_sid()`），不新增第二套身份；不存姓名/手机号（`AGENTS.md:23`、`HANDOFF.md:259`）。
2. **表默认不开 anon 直连**：能不开策略就不开，全部走 `SECURITY DEFINER` RPC，响应里不出现敏感字段
   （照投票：「两表对 anon 完全无直连权限…所有校验都在 SECURITY DEFINER RPC 内」`CLOUDBASE.md:770-771`；
   函数写法照 `class_whoami`：`SECURITY DEFINER + set search_path=public,private,pg_temp` + `revoke all … from public` 后仅 `grant execute … to anon`，
   `deploy/cloudbase/2026-11-11_stage_rpc.sql:42-71`）。
3. **偏好类只用本机 localStorage**；不进 userdata v6（A8）。

### C1 表草案

```sql

--   cd web/deploy/cloudbase && python apply_sql_api.py <file>  —— 含函数体分号，别用 tcb db execute）
-- 回滚头部写 DROP FUNCTION / DROP TABLE（照 2026-11-11_polls.sql 头部风格）

-- 1) 绑定关系（凭据密文；前端永远读不到这一列）
CREATE TABLE IF NOT EXISTS public.xy_accounts (
  sid        text PRIMARY KEY,                     -- 班级账号（auth_sid()），不存手机号/姓名
  state      text NOT NULL DEFAULT 'pending',      -- pending | bound | invalid | revoked
  acct_hint  text NOT NULL DEFAULT '',             -- 脱敏显示用（如 "138****1234"），可为空 —— 建议留空
  cred_enc   text NOT NULL DEFAULT '',             -- 小依 token/刷新令牌的密文（AES-GCM，密钥只在 ECS 文件；空=未绑定）

ALTER TABLE public.xy_accounts ENABLE ROW LEVEL SECURITY;
REVOKE ALL ON public.xy_accounts FROM PUBLIC, anon;   -- 前端零直连；只经 RPC（照 polls 的收紧口径）

-- 2) 洗衣机（opaque deviceId；alias 用户自填，禁自动拼宿舍号）
CREATE TABLE IF NOT EXISTS public.xy_devices (
  id         text PRIMARY KEY,                     -- 小依设备 id 的哈希/opaque（不存原始长 id 也行）
  owner_sid  text NOT NULL,
  alias      text NOT NULL DEFAULT '',             -- ≤20 字，用户自填（如 "宿舍机"），默认空
  last_seen  bigint NOT NULL DEFAULT 0,
  status     text NOT NULL DEFAULT '',             -- 小依返回的状态码/枚举（脱敏后）
  updated_at timestamptz NOT NULL DEFAULT now()
);
ALTER TABLE public.xy_devices ENABLE ROW LEVEL SECURITY;
GRANT SELECT ON public.xy_devices TO anon;
DROP POLICY IF EXISTS xyd_sel ON public.xy_devices;
CREATE POLICY xyd_sel ON public.xy_devices FOR SELECT TO anon
  USING (public.auth_ok() AND owner_sid = coalesce(public.auth_sid(),''));
-- 写只经 RPC（不授 INSERT/UPDATE）

-- 3) 指令/任务队列（同时是审计真源；worker 消费）
CREATE TABLE IF NOT EXISTS public.xy_jobs (
  id         text PRIMARY KEY,                     -- md5(random) 风格，照 login_jobs
  sid        text NOT NULL,
  kind       text NOT NULL,                        -- bind | check | balance | control（白名单 CHECK）
  params     jsonb NOT NULL DEFAULT '{}'::jsonb,   -- 白名单字段（mode/water/…），服务端再校验
  nonce      text NOT NULL DEFAULT '',             -- 幂等键；UNIQUE 防双击/重放
  status     text NOT NULL DEFAULT 'pending',      -- pending|claimed|running|done|failed|expired
  worker     text NOT NULL DEFAULT '',             -- 'ecs' | 'local'
  attempts   int  NOT NULL DEFAULT 0,
  created_at bigint NOT NULL,
  expires_at bigint NOT NULL,                      -- 控制类 ≤90s；只读类 ≤10min
  claimed_at bigint NOT NULL DEFAULT 0,
  finished_at bigint NOT NULL DEFAULT 0,
  result     jsonb,                                -- 脱敏结果（余额/状态；不含 token/手机号）
  error      text NOT NULL DEFAULT ''              -- 中文，≤300 字（照 ppt_decks.error 口径）
);
CREATE UNIQUE INDEX IF NOT EXISTS xy_jobs_nonce_uq ON public.xy_jobs (sid, nonce) WHERE nonce <> '';
CREATE INDEX IF NOT EXISTS xy_jobs_pending_idx ON public.xy_jobs (status, created_at);
ALTER TABLE public.xy_jobs ENABLE ROW LEVEL SECURITY;
REVOKE ALL ON public.xy_jobs FROM PUBLIC, anon;   -- 前端零直连；只经 RPC

-- 4) 审计日志（append-only；不存响应原文；按天清理）
CREATE TABLE IF NOT EXISTS public.xy_audit (
  id         text PRIMARY KEY,
  sid        text NOT NULL,
  kind       text NOT NULL,                        -- bind/unbind/check/balance/control
  code       text NOT NULL DEFAULT '',             -- ok | auth_fail | api_error | timeout | blocked
  note       text NOT NULL DEFAULT '',             -- ≤120 字，禁止 token/手机号/原文
  ts         bigint NOT NULL,

);

ALTER TABLE public.xy_audit ENABLE ROW LEVEL SECURITY;
GRANT SELECT ON public.xy_audit TO anon;
DROP POLICY IF EXISTS xya_sel ON public.xy_audit;
CREATE POLICY xya_sel ON public.xy_audit FOR SELECT TO anon
  USING (public.auth_ok() AND (sid = coalesce(public.auth_sid(),'') OR public.auth_admin()));
-- 写只经 RPC（或 worker 管理员 token）
```

### C2 RPC 草案（SECURITY DEFINER 风格；错误返回 `{ok:false,reason:"中文"}`，HTTP 200）

| RPC | 入参 | 行为 | 限流/守卫 |
|---|---|---|---|
| `xy_bind_start(p_user text, p_secret text, p_platform text)` | 小依账号标识 + 密码/验证码 | PGP 公钥加密 `p_secret` 后写 `xy_jobs(kind='bind', expires_at=+15min)`，`p_secret` 用后清空；**账号标识也加密或只留脱敏 hint** | 每 sid 每小时 3 次；worker 离线（`agent_keys.id='xy_bind'.seen_at` >180s）返回 `agent_offline`（照 `tt_login_enqueue` `diag_login.sql:186-201`） |
| `xy_bind_status(p_id text)` | job id | 返回 status/error（**不返回密文**）；仅本人/管理员（照 `tt_login_status` `:218-248`） | — |
| `xy_job_submit(p_kind text, p_params jsonb, p_nonce text)` | check/balance/control | 校验 kind 白名单 + params 白名单 + `expires_at`；`nonce` 幂等（重复返回同一 job）；写 `xy_jobs` | 控制类：每 sid 60s ≤1 次；同时只允许 1 个未完成控制 job |
| `xy_job_status(p_id text)` | job id | 本人/管理员；返回脱敏 result | — |
| `xy_state()` | — | 聚合：绑定状态 + 设备列表 + 余额快照 + 最近 5 条 audit | 需 `auth_ok()`；无绑定返回 `{bound:false}` |
| `xy_unbind()` | — | 清 `cred_enc`、写 `xy_audit(kind='unbind')`、删/标记设备（软删优先） | 幂等 |
| `xy_revoke_admin(p_sid)`（可选） | sid | 仅 `auth_admin()`：清绑定（应急） | 写审计 |

- worker 侧**不新增 RPC**：直接以管理员 token 走 PostgREST 表（先例：PPT 转换机用管理员 token 更新任意 deck，

- **任何 RPC 响应都不返回 sid/手机号/密文**（照投票口径 `CLOUDBASE.md:771`）；错误不区分「不存在/他人」（照 `poll_detail` 的「投票不存在」语义 `CLOUDBASE.md:834`）。

## D. 安全 / 隐私 / 合规门禁

### D1 谁能控制哪台机器（授权模型）

| 场景 | 允许 | 不允许 |
|---|---|---|
| 本人绑定的洗衣机（宿舍自用） | 本人查看状态/余额；控制需二次确认 | 他人查看/控制；管理员代控 |
| 管理员 | 查看**审计**、应急解绑（`xy_revoke_admin`） | 直接控制他人机器（避免"管理员误启动"担责） |
| 共享机（多人使用，若小依支持共享） | **只显示余额/状态**，并引导到官方 App 操作 | 站内提供启停按钮——"谁有权启动"无解，必然纠纷 |
| 未绑定 | 只读公开信息（价格/报修） | 任何数据接口 |

- 控制权默认 = 「绑定者本人」。**管理员没有控制权**（这与站内"管理员可看统计/管理"不同，理由是物理世界后果不可撤销）。
- 每条控制指令必须带 `nonce`（防双击/重放）+ `expires_at≤90s`（防延迟执行）+ 服务端白名单 `params`（防注入任意指令）。

### D2 防越权

- 用户侧：RLS + RPC 内 `auth_sid()`；`xy_jobs`/`xy_accounts` 零直连（REVOKE），只能经 RPC（照 polls `CLOUDBASE.md:770-771`）。
- worker 侧：管理员 token **只存在 ECS 文件 0640**，不进前端/日志/对话；失效即 fail closed（不降级为"任意执行"）。
- 错误语义：不泄露他人数据存在性（统一「记录不存在」）。
- 限流：绑定 3/h、控制 1/min、查询 10/min（防刷；参照 `tt_login_enqueue` 的 3/h 与投票的频控）。

### D3 防误操作（控制类专用）

1. 二次确认弹层，明确写出：「将启动 `<alias/楼栋房间（若用户批准展示）>` · 标准洗 · 预计约 xx 分钟」；默认按钮是「取消」。
2. `nonce` 幂等：同一按钮双击只产生一个 job。
3. 90s 过期：用户点了但 worker 没及时消费 → 过期失败，不"补执行"。
4. 控制类失败**不自动重试**（只读类可重试 2 次）；重试必须重新走用户确认。
5. 审计留痕：谁、何时、什么指令、结果码（不含原文）。
6. 服务端"熔断"：同一 sid 连续失败 3 次 → 5 分钟内禁止再控制（防脚本刷）。

### D4 日志/展示脱敏

- worker 日志只打 `kind/status/耗时/错误码`；**不打** token、手机号、完整 deviceId、小依响应原文。
- 前端展示：不显示手机号；`acct_hint` 若不慎存了手机号中间段也要二次脱敏；`result` 里的设备名若含宿舍号 → 由 RPC 裁剪（需用户批准 G3）。
- 复用站内 `sensMask()` 思路（诊断页对 IP/`C:\`/URL/token 的脱敏，`AGENTS.md:118`）。
- 错误提示走 `{ok:false,reason:"中文"}`，reason 不得回显上游 URL/参数（照 `drop/CONTRACT.md:57`「访问日志绝不打印 token / query / 请求头」）。

### D5 充值资金流（**绝对不碰**）

| 不做 | 理由 | 站内依据 |
|---|---|---|
| 站内充值/代充/支付按钮 | 个人主体 + 非经营性备案 + 无支付资质；一旦有资金流即改变网站性质 | `_compliance/备案内容自查_20261106.md:34-35`（要求把「充值」改成「购电/余额提醒」）、`:49-50`（答问话术：不提供任何支付/充值功能） |

| 页面出现「充值 / 支付 / 代付 / 代充」字样 | 备案与平台审核误判 | 同上；`AGENTS.md:46` 精神 |

> 余额数字本身可以展示（本人账户自己的余额，不涉及支付动作），但**充值入口不做**。若小依余额接口无法只读获得，则连余额也不做。
