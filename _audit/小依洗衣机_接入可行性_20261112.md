## 0. 结论速览

**总评：按「站内控制洗衣机 + 充值」的原始设想，整体可行性 = 低，不建议落地。**

拆开看，三件事的结论完全不同：

| 能力 | 技术可行性（对站内网页/微信） | 合规可行性 | 站内架构可行性 | 综合结论 | 建议 |
|---|---|---|---|---|---|
| **充值 / 购洗衣卡 / 代充** | **不可行**（充值只在官方 App 收银台内完成，无对外支付接口） | **不可行**（个人主体、非经营性备案、无支付资质） | **不可行**（不碰资金） | **不可行** | ❌ 只允许纯文字引导到官方 App/学校渠道 |
| **控制洗衣机**（选模式/水位/启动/取消） | **站内不可行**（分品牌：小依侧证据指向**本机蓝牙 BLE**、云端只做账号/订单/扣费；悠洗侧 2026 新建 13 号楼公告明写「学生可通过微信公众号或洗衣 App 控制启动及付费」→ 存在云控/公众号分支。**但两条路都无第三方接口**，外部网页不能调用厂商公众号/小程序） | **低**（未授权接口、校园合同、物理责任） | 架构上可做（需新增后端），但**没有可合法接入的接口** | **不可行**（建议保持官方 App/公众号） | ❌ 不在站内做；最多作为个人 PoC 由你本人真机验证 |
| **只读查询**（余额/洗衣券/订单记录） | 待 PoC（中低：云端确有账号/订单数据，但无授权接口） | **低–中**（未授权 + 个人信息） | 可（推荐 B③′ 队列方案） | **低** | ⚠️ 仅在厂商书面许可 + 你接受隐私取舍后，做只读 |
| **官方入口 / 信息卡 / 报修指引** | 高 | 高 | 高 | **高** | ✅ 可立即做（0.5–1.5 人日，零风险） |
| **洗衣计时提醒 / 班级洗衣记账**（不接小依接口） | 高 | 高 | 高 | **高** | ✅ 推荐作为替代小工具 |

**三个决定性的「硬门」**（任何一门没过，都不该写真实接口代码）：

1. **厂商许可门**：小依/悠洗没有任何开放平台、API 文档或第三方接入入口；未取得厂商书面/客服明确许可，调用其私有接口属于「未授权访问」。→ 没过就只能做入口卡。
2. **控制方式门（本报告最关键的发现）**：控制入口和技术路径**按品牌/机型不同且都封闭**——小依（2024 项目/老机型）多条证据指向**手机蓝牙（BLE）本机下发指令**（云端只做账号/绑定/订单/扣费，为推定）；悠洗（2026 新建 13 号楼）公告则明写**微信公众号或洗衣 App 控制启动及付费**（存在云控/公众号分支，具体实现未证实）。但**两家都没有开放 API，外部网页/第三方小程序无法调用其公众号/小程序**；且网页/微信 WebView 无法对任意 BLE 设备发指令。→ 站内控制这条路封死。
3. **账号与测试门**：小依账号是手机号+验证码/微信登录，且**公开面未发现测试账号/沙箱（未证实）**；做站内绑定就要存每人手机号/会话 token（触碰隐私红线），而站内测试纪律（只用班级测试身份）无法覆盖小依真机验证 → 工程化验收无法闭环。

> 一句话：**「充值」不用讨论，技术、合规、资金责任三方面都做不了；「控制」在「网页 + 无厂商授权 + 入口封闭（小依侧 BLE 本机、悠洗侧公众号/App）」前提下不可行；真正能落地的只有「官方入口信息卡 + 本地计时提醒/记账」，或者走厂商/学校官方合作拿正式接口。**

## 1. 我理解的需求与边界

你希望：在班级工具站里增加一个「洗衣机」工具，让本班同学在站内完成小依 App 的两类操作：

1. **控制洗衣机**：查看机器状态 → 选模式/水位 → 启动/取消 → 看剩余时间/完成提醒；
2. **充值**：查询余额/洗衣卡，并能在站内充值。

分析边界：

- ✅ 回答：外部产品与协议现状、法律与校园合规、站内架构与红线、工作量与风险、推荐路线、PoC 验证清单。
- ❌ 不做：不提供任何绕过付费/破解的代码或步骤；不抓包、不下载/运行第三方 APK、不登录小依账号；不读取/不引用站点密钥；不修改线上功能。
- 默认前提：你是福建中医药大学在校学生，使用小依品牌洗衣机；班级工具站是**个人开发、非经营性、仅本班约 70 人使用**的 H5（`AGENTS.md` 定位）。

## 2. 小依是什么：产品、入口、你校的现状

### 2.1 产品与公司（已证实）

- 「小依」是**校园共享洗衣机**平台：运营公司为**福州恰同学信息科技有限公司**（官网 `qtx2015.com`，App 备案号 **闽ICP备15017629号-2A**），2015 年成立、2015-11 获 300 万元天使轮。模式为「**硬件免费、按次收费**、一宿舍一台」，学生通过 App 控制洗衣机并在线付费。
  - 来源：[36氪项目页](https://pitchhub.36kr.com/project/1678399466320902)、[猎云网报道](https://m.lieyunpro.com/archives/290859)、[创业家 2018 报道](https://news.chuangyejia.com/article/2018/0829/6814420.shtml)、[铅笔道 2016 报道](https://www.pencilnews.cn/p/12297.html)、官网 [qtx2015.com](http://www.qtx2015.com/)
- 硬件：采购家用洗衣机后**改造主板 + 内嵌通讯模块**，官方口径为「云控制」（2016–2018 年采访）；但 2020 年后的 App 功能/权限/指南又指向**蓝牙本机控制**（详见 §3；不同代机型可能不同）。
- 单次价格随学校/合同不同：常见 **1.7 / 1.8 / 2.0 元**，也有 2.5 元、2–3 元口径；洁桶免费；2016 年官方数据（2018 年报道回顾）：每台机器月收入约 36 元。

### 2.2 学生实际使用流程（已证实）

1. 扫洗衣机上的二维码 → 按提示下载「小依」App（应用商店/官网）；
2. 注册：手机号+验证码，或微信登录；
3. 绑定设备：在「洗衣」页输入洗衣机上的**设备编号**（或扫码）；
4. 充值：App「账户」页购买余额（旧版商店截图显示 10/20/30/50/100 元 + 任意金额，中置信），或购买洗衣卡/领券；
5. 选模式（强力洗约 69 分钟 / 标准洗约 41 分钟 / 快速洗约 23 分钟 / 单脱水约 7 分钟 / 洁桶）与水位（低/中/高）；
6. 点「**通电洗衣**」→ 实时看进度/剩余时间/故障提醒 → 完成提醒晾晒；
7. 报修：App 内报修，或客服电话 **0591-38251600**（校内另有维修人员电话）。

来源：[福中医 2025 新生洗衣指南（微信公众号）](http://mp.weixin.qq.com/s?__biz=MzA3NDAxNTUwMA==&mid=2650058338&idx=1&sn=ccdd1feb2746d48c01da3610d03ed159)、[豌豆荚小依页](https://www.wandoujia.com/apps/7223476)、[应用宝小依页](https://sj.qq.com/appdetail/com.sys.washmashine)、[口可网小依说明](https://m.okemu.com/azsoft/937128.html)、[闽江学院 2025 洗衣余额退费指南](https://xgb.mju.edu.cn/2025/0718/c1540a206323/page.htm)（App 报修 + 支付宝人工退款）

## 3. 技术可行性：能不能接（本报告最关键的一节）

### 3.1 官方没有可用的开放接口（已证实）

- 无开放平台、无 API 文档、无 OAuth/合作接入入口；
- App/小程序是**唯一官方入口**，支付在官方生态内闭环；
- 公开面没有「远程洗衣/远程启动」的宣传或说明；
- GitHub/Gitee 无任何小依相关项目（`小依 洗衣`、`qtx2015` 均 0 结果）。

→ **不存在「正规 API 接入」这条路**；要接入只能逆向私有协议（未授权），或者走厂商商务合作（目前无先例）。

### 3.2 控制路径：**分品牌、且都是封闭入口**（小依倾向本机 BLE；悠洗有公众号/App 云控分支）

**先给结论**：小依（2024 项目/老机型）的多条证据指向**手机蓝牙（BLE）本机下发指令**，云端只负责账号/绑定/订单/扣费（**推定**，中高）；但**2026 新建 13 号楼的悠洗公告明写「学生可通过微信公众号或洗衣 APP 控制启动及付费」**——说明同集团新项目存在**云控/公众号分支（公告高置信，技术实现未证实）**。无论哪种，**两家都没有对第三方开放的接口/入口**，外部网页无法调用其公众号/小程序；站内控制仍不可行。

小依侧证据（按强度）：

1. **App 内官方内容**：豌豆荚公开商店截图显示 App「发现」页有官方文章 **《洗衣机蓝牙控制使用指南》**（2020-11-24，阅读 22,468）。来源：[豌豆荚小依页截图](https://www.wandoujia.com/apps/7223476)（截图 CDN 日期 2026-09-09；文章日期 2020，不能证明 6.5.9 界面仍完全如此，中置信）。
2. **功能文案**：6.5.0（2025-06）功能列表首条「**一键蓝牙洗衣**」；同类表述见 6.4.2。来源：[bgmfans 小依 V6.5.0](http://www.bgmfans.com/soft/16882.html)、[51pgzs 6.4.2](https://www.51pgzs.com/app/69391.html)（第三方转述商店文案，中置信）。
3. **App 权限**：6.5.5/6.5.9 商店权限含「与蓝牙设备配对 / 蓝牙管理 / 创建蓝牙连接 / 控制近距离通信（NFC）」。来源：[bear20 6.5.5 页](https://m.bear20.com/sjsoft/438/160438.html)、[chedu 6.5.9 页](https://www.chedu.net/soft/xiao-yi-xi-yi-ji-v6-5-9.html)（商店权限=APK 清单转写；权限存在≠必用，中高置信）。
4. **旧版论坛**：52pojie 2020–2021 跟帖称「小依通过蓝牙控制洗衣机转动」「对洗衣机发送成功扣费的蓝牙 api 信号」，并给出 iPhone 抓包改包经验（旧版 7.8.141）。来源：[52pojie tid=1187963](https://www.52pojie.cn/forum.php?mod=viewthread&tid=1187963)（个人经验、旧版，仅作线索，**不采用其绕过方法**，低–中置信）。
5. **校内报修文**：「机身面板指示灯一直闪烁，导致**手机连接不上**」→ 手机与机器之间存在连接环节（而非纯远程）。来源：[校内公众号报修文](http://mp.weixin.qq.com/s?__biz=MzU2NDA5NTUzMA==&mid=2247512698&idx=1&sn=ba1536d49097d61a68f40f4d872eb820)（2023-04，中置信）。
6. **反向证据（云控/公众号分支）**：① 2016–2018 官方采访称「改造主板+通讯模块，实现手机 App 云端控制」；② **2026-08 福中医新建 13 号楼悠洗中标公告：「学生可通过微信公众号或洗衣 App 控制启动及付费」**（[coopaa 公告](https://www.coopaa.com/notice-38451912.html)，高置信，但未说明云控实现）。→ 说明「控制=纯蓝牙」不能外推到所有品牌/机型，应限定为**小依侧推定**。

**技术判断（高置信）**：

- **微信内置 WebView、iOS Safari 均不支持 Web Bluetooth**，无法对任意 BLE 设备下发指令；
- Chrome/Edge Android 虽有 Web Bluetooth，但需要 HTTPS + 用户手势 + 已知的 GATT 服务/特征值协议，且很可能有服务端下发的授权参数；
- 微信小程序有 `wx.createBLEConnection`，但**必须是官方小依/悠洗小程序（有 appid、在小程序内）**，第三方网页/第三方小程序都无法调用；
- 悠洗的「公众号/App 控启动」即使走云控，也是**厂商自有公众号/小程序内**的能力，外部网页无法深链或转发其接口（需小程序方生成 URL Link/Scheme）。

→ **在「无厂商授权 + 入口封闭」前提下，站内（网页/微信）控制洗衣机不可行。** 仍需真机验证的分支：小依现役机型是否完全 BLE、悠洗公众号控制是否云控（见 §8）。

### 3.3 账号体系与凭据（已证实 + 推断）

| 项 | 现状 | 对站内接入的影响 |
|---|---|---|
| 注册/登录 | 手机号+验证码，或微信登录；「我的」页含姓名+学校 | 站内绑定要收集手机号/验证码或微信授权 → 隐私红线 + 额外授权流程 |
| 会话 | App 内登录态（token/会话，形态未公开）；多端登录策略未知 | 服务端需加密保存每人 token、处理过期/互踢 |
| 设备绑定 | 输入机器编号绑定到账号 | 绑定/共享策略未知；越权控制风险 |
| 支付 | App 内调起支付宝/京东/建行/交行/银联等支付 SDK（隐私政策列明）；未点名微信支付 | 第三方网页无法发起；**充值不可做** |
| 测试账号 | **公开面未发现测试账号/沙箱（未证实）** | 站内测试纪律无法覆盖小依真机验证；控制类测试不可回滚 |

来源：小依隐私政策（2023-05-26）[腾讯应用宝隐私页](https://cftweb.3g.qq.com/privacy/privacyPolicy?content_id=b8ed1cce6269e976a935eb39de43d757)；豌豆荚公开商店截图。

### 3.4 充值/支付为什么第三方做不了（已证实 + 合规）

1. **技术**：充值在官方 App 收银台完成（账户余额/购买金额 + 洗衣券）；小依隐私政策（2023-05-26）列明集成支付宝/京东/建行/交行/银联支付 SDK（**这是 SDK 清单，不等于逐项验证过的实际充值渠道**，中置信）；**没有对外充值 API / H5 支付页**；退款也不是自助——闽江学院 2025 公告显示退费要在 App 报修里填「支付宝真实姓名+账号+宿舍」，人工退至支付宝 10–15 工作日（**个例，中置信**）。第三方页面无法完成支付/回调/对账。
2. **合规**：站点是**个人主体、非经营性 ICP 备案（审核中；站点当前暂停期）**；备案内容自查明确要求去掉「充值」字样、对外口径为「不提供任何支付/充值功能」（`_compliance/备案内容自查_20261106.md:34-35,49-50`）；**微信个人主体小程序也不能使用微信支付**（`_compliance/research_delivery_paths.md:83`）。
3. **责任**：涉资金即变成支付/代收代付业务，需要牌照/商户资质；退款、对账、纠纷责任无法由班级工具站承担。

→ **站内「充值」没有任何合规实现路径，最多做纯文字引导（"请到小依官方 App 内充值"）。**

### 3.5 技术可行性结论表

| 能力 | 结论 | 依据 |
|---|---|---|
| 控制机器（启动/选模式/水位/取消） | **站内不可行**；小依侧仅官方 App 本机蓝牙；悠洗侧仅官方公众号/App（均无第三方接口） | §3.2；入口封闭 + 网页/微信无法调厂商接口 |
| 查机器状态/空闲 | 不可行（网页）/ 未证实的云侧只读可能 | 状态大概率来自云端，但无授权接口；需 PoC |
| 查余额/洗衣券/订单 | 待 PoC（中低） | App 内存在账户/订单数据；但无对外授权，需本人 token |
| 充 值 | **不可行** | §3.4 |
| 完成提醒 | 官方已有（App+短信）；站内可做本地计时提醒 | — |

## 4. 站内架构可行性：就算能接，放哪

> 本节结论压缩自 `_audit/小依_站内适配_20261112.md`（含逐条红线引用与完整数据模型草案），只保留决策相关部分。**注意：架构可行 ≠ 有接口可接**——§3 已说明没有可合法接入的接口，本节回答「如果将来厂商开放接口，站内怎么接」。

### 4.1 硬约束（来自 AGENTS.md，逐条引用见适配报告 §A）

| 约束 | 对本功能的影响 |
|---|---|
| **前端只允许原生 fetch 调 PostgREST 一个接口** | 前端不能直连小依 API，也不能随便新增第二个同源接口；要接必须走「PostgREST RPC 队列」或经你明确同意新增 `/xy/*` |
| 单文件零依赖、无构建链 | 新工具只能内联进 `tools/index.html`，不能装 SDK/框架 |
| 零外部请求 | 二维码/图片必须同源或 data URI；不能加载小依网页/统计/支付 SDK |
| 身份门禁 + RLS | 余额/状态/控制记录都算班级数据，必须 `auth_sid()` + RLS，不能只靠前端隐藏 |
| 隐私红线（手机号/学号/宿舍号） | 小依账号绑手机号 → 不能落库、不能展示、不能进日志；展示宿舍/机器信息是**新的隐私例外**，需你单独批准 |
| 密钥零泄漏 | 小依密码/token/加密密钥只能放 ECS 文件（0640）或 PGP 密文，不得进前端/仓库/日志/对话 |
| 测试账号唯一化 | `AGENTS.md` 的纪律覆盖的是**班级账号**；本功能另需一条**新增建议红线**：禁止用真实小依账号做自动化测试（控制类不可回滚、会产生真实扣费）——是否采纳需你拍板 |
| 新增同步类别先问用户 | 不建议为洗衣功能新增 userdata v6 section；关注哪台机器用本机 localStorage |
| CloudBase 2026-12-10 到期（剩 28 天） | **不要把长期链路建在云函数/定时器上**；长期后台放 ECS |
| DNS 暂停期部署态 | 线上页面为 HTTPS（OSS），调不到 ECS 的 HTTP 服务（mixed content）；本地调试通道只代理 `/__cb/` |

### 4.2 现有可复用后端模式（全部有站内先例）

| 能力 | 先例 | 可复用点 |
|---|---|---|
| PostgREST 表 + SECURITY DEFINER RPC | 投票、大屏布局、名单 | 前端唯一接口、RLS 校验 `auth_sid()` |
| ECS Python 微服务 + Caddy 反代 | `/drop`（文件传输）、`/pptfiles`（PPT 缓存）、附件服务 | class token → `class_whoami` 鉴权、fail-closed、日志脱敏、systemd |
| 云函数外网抓取 | `power_sync`、`xgj_sync` | 仅参考；**因 2026-12-10 到期，不建议**；云函数能否到达小依 API 需 PoC（已知的「校园内网不可达」是教务 210.34.74.77 的证据，不能外推到小依公网云侧） |
| PGP 信封 + 队列 + worker | 课表登录 `tt_login_enqueue` + 本机 diag_agent | 密码加密存队列、worker 解密、用后即清、限流 |
| 本机 agent | `diag_agent`（1 分钟轮询） | 仅适合 PoC/自用，不适合公共服务 |

### 4.3 五种架构方案对比（决策版）

| 方案 | 说明 | 满足「前端只调 PostgREST」 | 控制延迟 | 长期可靠性 | 工作量 | 结论 |
|---|---|---|---|---|---|---|
| **B① 入口卡/信息卡** | 只放说明、价格、报修、官方 App 入口 | ✅（零请求） | — | — | **0.5–1.5 人日** | ✅ **唯一可立即上线** |
| B② CloudBase 云函数代理 | 云函数抓小依接口 + 写 PG | 只读✅/控制❌ | 30–60min | ❌ 2026-12-10 到期；能否到达小依 API 待 PoC | 3–6 人日 | ⚠️ 不建议 |
| **B③′ RPC 队列 + ECS worker（推荐）** | 前端只写 `rpc/xy_job_submit` 轮询结果；ECS worker 轮询任务表并调小依 | ✅ | 2–5s | ⚠️ 出网半边在 ECS；队列/RPC 仍在 CloudBase，需随续费/迁移 | **5–8 人日**（+PoC 3–5） | ⚠️ 仅当厂商开放只读接口时 |
| B③ ECS 微服务直连 `/xy/*` | 前端直接调同源 `/xy/*` | ❌ 破红线，需你书面同意 | 1–3s | ✅（ECS） | 6–9 人日 | ⚠️ 仅在你批准破例时 |
| B④ 本机 agent | 复用课表登录链路，本机轮询执行 | ✅ | 60s+ | ❌ 依赖本机开机 | 3–5 人日 | ⚠️ 仅 PoC/自用 |
| B⑤ 小程序嵌入/跳转 | 嵌官方页面/跳转官方小程序 | — | — | — | — | ❌ 个人主体小程序不支持 web-view；跳转第三方小程序需 appid/关联，无授权 |

> 推荐组合（若未来拿到授权）：**先上 B①**；只读接口验证通过后再做 **B③′**；不要为「更快 1s」去破前端单接口红线（B③）。

### 4.4 若做 B③′：最小数据模型与安全设计（详见适配报告 §C/§D）

- 表：`xy_accounts`（sid → 加密 token/状态，**不存手机号**）、`xy_devices`（设备别名/状态）、`xy_jobs`（指令队列：`nonce` 幂等、`expires_at≤90s`、状态机）、`xy_audit`（审计，脱敏、保留 30 天）；
- RPC（SECURITY DEFINER，前端只调这些）：`xy_bind_start/status`、`xy_job_submit/status`、`xy_state`、`xy_unbind`、`xy_revoke_admin`；
- 凭据：密码/验证码走 PGP 信封 → ECS worker 解密 → 用后清空（照课表登录链路）；token AES-GCM 加密落库，密钥只在 ECS 文件 0640；
- 控制权：**只有绑定者本人**可控制；管理员只能看审计/应急解绑，**不能控制他人机器**；
- 防误操作：二次确认 + nonce 幂等 + 90s 过期不补执行 + 失败不自动重试 + 连续失败熔断；
- 充值：**不建任何订单/支付表、不出现「充值/支付/代付」字样**。

### 4.5 前端不是难点

按现有工具（`file`/`vote`/`ppt`）的挂载方式，新增一个工具卡/页面本身约 1–2 人日；真正的成本和风险全在**后端代理、协议授权/逆向、凭据与合规**。

## 5. 合规与安全：为什么「能做」不等于「该做」

### 5.1 法律风险（未授权访问/破解/支付）

| 风险 | 说明 |
|---|---|
| **未授权访问计算机信息系统** | 调用厂商未公开接口、逆向协议，可能违反《网络安全法》第 27 条；情节严重可触及《刑法》第 285/286 条（非法获取数据/提供侵入工具/破坏系统）。对本人账号的自动化访问风险相对低，但**不存在厂商授权**时始终是灰色地带；批量/代他人操作风险显著更高。 |
| **绕过付费** | 公开论坛曾出现改包绕过扣费的做法——明确的违法/违约行为，**本方案绝不采用**，也不提供任何相关步骤。 |
| **支付/资金** | 站内充值/代充/代收代付需要支付业务许可与商户资质；个人站不能做。 |
| **个人信息（PIPL）** | 绑定小依账号会收集手机号/会话 token/机器与宿舍信息；需最小必要、单独同意、可删除，且不得对外提供。 |

**厂商维权先例（非小依，但同行业）**：海尔欧洲 2024-01 向 Home Assistant 第三方插件作者发法律警告并下架（理由「economic harm」）。来源：[The Register 2024-01-22](https://www.theregister.com/software/2024/01/22/haier_europe_sends_takedowns_over_open_source_plugins/)（高置信，媒体）。→ 第三方接入厂商设备存在被法律函/下架的先例。
另有安全事件先例：荷兰阿姆斯特丹校园智能洗衣机被入侵、超千名学生免费洗衣（cn-sec 转引，2026-10），以及国内 CSDN「低成本破解学校洗衣机实验」——说明这类系统是攻击目标，学校/厂商有动力收紧（中置信，二手）。

### 5.2 校园合同与厂商关系

- 你校与厂商签有 3 年服务合同（2024 既有宿舍、2026 新建 13 号楼，分属小依/悠洗）；**未授权接入可能构成违约/干扰运营**，厂商可封号，学校也可要求下线。
- 一旦站内发生「误启动/占用他人机器/扣费争议」，**责任主体是工具站（个人）**，很难界定与承担。
- 正确路径：联系小依客服（0591-38251600）或学校后勤，**取得书面许可/官方接口/官方小程序跳转授权**。

### 5.3 备案与主体性质（决定性）

- 站点是**个人主体、非经营性**备案，当前仍在**审核中（站点暂停期）**（`_compliance/备案内容自查_20261106.md:24`）；自查报告已明确要求把页面里的「充值」字样（**实测现网 10 处**）改为「购电/余额提醒/学校官方渠道」，并删除第三方支付品牌名（「完美校园」目前仍残留 1 处待清理）；
- 如果新增「洗衣机充值」，等于**直接新增支付/充值字样和功能**，与备案口径冲突，审核/抽查风险高；
- 小程序端也是**个人主体**：不能用 web-view、不能微信支付（`_compliance/research_delivery_paths.md:81,83`）。

### 5.4 隐私红线（具体到本功能）

- 小依账号通常=手机号；班站身份=学号+姓名。绑定后若存手机号/明文 token，违反「密钥零泄漏 + 不暴露个人隐私」红线；
- 展示洗衣机位置（楼栋+房间）属于**新的隐私例外**，需你明确批准（不能自动沿用「电费关注宿舍」例外）；
- 建议：手机号**零落库**（只存加密 token）；设备用用户自填别名（不自动拼宿舍号）；提供一键解绑/删除。

### 5.5 测试账号红线（工程化「死结」）

`AGENTS.md` 的测试账号纪律约束的是**班级账号**（真实同学/管理员），本身没有覆盖小依账号；因此本方案需**新增一条建议红线**（是否采纳需你拍板）：**禁止用真实小依账号做自动化测试**。而小依没有测试账号/沙箱：
- 真机控制测试不可回滚（会启动真实洗衣机、产生真实扣费）；
- 用真实小依账号做自动化 = 触碰上述建议红线，也无法在 CI 复现；
- 因此只能「fake 小依 API + mock worker」测试协议适配层，**真实链路只能由你本人在生产边缘手工验证**——这会让「独立验收」很难达标。

### 5.6 物理安全与责任

- 远程启动涉及真实水电与衣物：误启动、占用、水淹、损坏都可能发生；网页端无法做 fail-safe（无法确认机器内是否有衣物、是否有人）；
- 建议除非有厂商官方保障，否则**不做远程启动**。

## 7. 推荐方案（按可行性排序）

### ✅ 方案 A（推荐，可立即做）：洗衣机信息卡 + 官方入口
- 形态：全部页一张「洗衣机」卡 → 点开后**只放入口按钮 + 关键标签 + 报修电话**；使用步骤/模式时长/注意事项一律用**标签、短句、表格**表达（或并入既有「使用说明」页），**不写解释性段落**（遵守 AGENTS §1「不要多余的说明文字」）。
- 数据：纯静态，不调任何外部接口；官方入口只做普通导航链接或同源二维码，不加载第三方资源。
- 工作量 0.5–1.5 人日；零后端、零凭据、零合规新增；文案不出现「充值/支付/代付」，标注「个人开发·非学校官方」；若有官方小程序入口（需你现场二维码确认），也只做「复制/引导」。

### ⚠️ 方案 B（若你坚持要数据）：只读查询，先 PoC 再决定
- 前提：拿到厂商许可 + 你确认接受「绑定手机号/存加密 token」的隐私取舍 + PoC 验证只读接口可用。
- 形态：B③′（前端只调 PostgREST 队列，ECS worker 调小依）；只做余额/状态/记录，**不做控制**。
- 工作量：PoC 3–5 人日 + 生产化 5–8 人日；维护成本持续。

### ❌ 方案 C（不可行）：站内远程控制洗衣机
- 小依侧本机蓝牙为主（推定）、悠洗侧公众号/App 云控分支（公告高置信），**但两家都没有第三方接口/可深链入口**；网页/微信 WebView 无法调用厂商公众号/小程序，物理后果不可撤销，测试无法闭环。
- 如只做「个人自用 PoC」：仅你本人账号、自费、不绕过支付、不进生产、不上线、数据不落库——且需先真机确认控制路径。

### ❌ 方案 D（不可行）：充值/代充
- 无官方接口、无支付资质、备案与主体限制；只允许纯文字引导官方渠道。

### ✅ 方案 E（正解，如果需要「官方能力」）：走厂商/学校合作
- 联系小依客服（0591-38251600）或学校后勤，询问：① 是否允许第三方班级工具调用查询/控制接口；② 是否有官方小程序/H5 可授权跳转；③ 是否有开发者/合作接入文档。
- 只有这条路能同时解决「授权 + 稳定性 + 支付（由官方承担）」。
- 注意：同校新建 13 号楼已由悠洗运营，合作需明确覆盖楼栋/品牌范围。

### ✅ 可作为替代的小工具（不接小依接口，零风险）
- **洗衣计时提醒**：手动点「开始洗衣」→ 按模式（23/41/69 分钟）本地计时，到点站内提醒（不依赖厂商数据）；
- **班级洗衣记账**（可选）：宿舍成员分摊洗衣费用，本地记录/统计；
- 这两项零合规风险、1–2 人日可做，适合作为「洗衣机工具」的轻量替代。

## 8. 若你坚持推进：PoC 验证清单（只读/本人账号/不绕过付费/不逆向 BLE）

> 原则：**不进生产代码、不抓同学账号、不做真机控制测试、不绕过任何付费、不逆向蓝牙协议**。PoC 结果决定是否进入开发。

1. **确认入口与品牌**：扫你宿舍洗衣机上的二维码，记录：是小依 App 下载页、小依小程序，还是悠洗公众号/小程序；记录 App 版本、注册方式；核对小依 vs 悠洗（13 号楼是悠洗）。
2. **确认控制方式**：查阅 App 内「帮助/发现」是否有蓝牙控制指南；关掉手机蓝牙后能否「通电洗衣」→ 判断是否必须蓝牙。此步只观察，不抓包、不改包。
3. **只读接口 PoC（仅本人账号，若你愿意）**：在自己手机上抓**自己的**登录/设备列表/余额/订单请求，目标：确认接口域名、鉴权头/token 形态、签名/时间戳、token 有效期、多端登录限制；**不抓他人、不改包、不重放支付**。
4. **确认充值链路**：验证充值是否只能由官方 App 内支付完成（预期：是，无外部 H5 支付页）。
5. **确认厂商许可**：读小依隐私政策/（App 内）购买协议；联系客服/学校后勤询问第三方接入政策，留存书面/截图证据。
6. **合规与隐私评审**：手机号是否必须落库（尽量不）、宿舍信息是否展示、备案字样是否合规。
7. **收益评估**：把 PoC 结果套回 §6.2——如果只是省几秒，直接停在方案 A。

**PoC 通过判据（全部满足才考虑开发）**：厂商书面许可 + 只读接口稳定可达 + 无需存手机号明文 + 有可接受的测试方案 + 你本人书面确认承担风险与维护成本。

## 10. 一句话结论

**「把控制洗衣机和充值加进班级工具站」按原设想整体不可行，不建议落地：充值在技术、合规、资金责任上都没有实现路径；控制在公开证据下也走不通——小依（老机型/2024 项目）指向「手机蓝牙本机下发指令」，悠洗（2026 新建 13 号楼）公告称可「微信公众号或洗衣 App 控制启动及付费」，但两家都没有第三方接口/可深链入口，加上厂商无授权、网页/微信无法调用厂商入口，站内无法实现。真正可行且值得做的只有「官方入口信息卡 + 本地计时提醒/记账」，或者走厂商/学校官方合作拿正式接口。**

## 附录 B：术语

- **云控**：App→厂商服务器→洗衣机通讯模块，理论上可远程启动；

- **B③′ 队列方案**：前端只调 PostgREST RPC，ECS worker 轮询任务表后调用厂商接口，守住「前端单接口」红线；
- **PoC**：Proof of Concept，小范围可行性验证，不进生产。
