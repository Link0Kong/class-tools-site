# 参考站拆解：旗山校园 · 三维空间研究

> 参考地址：https://qishan-campus-3d-1022.mossy-hippo-0554.chatgpt.site/
> 内容：「福建中医药大学旗山校区」三维重建 / 空间研究站；创建于 2026-10-25（重建计划 JSON 的 `created_at_utc`）
> 抓取日期：2026-11-13；本文件是只读分析，不包含其源码、模型或渲染图（避免版权与仓库体积问题）

## 1. 它是什么

一个**按总平面图逐栋重建校园**的 3D 研究项目网站，不只是一个"校园地图"：

- **3D 场景**：Three.js（自托管 `vendor/three.module.js`）+ OrbitControls；拖拽旋转 / 滚轮缩放 / 右键平移 / 点选元素；带小地图（相机位置）、视角预设、加载阶段进度、软件渲染回退（无 WebGL 时降级）。
- **研究内容**：48 个建筑设计单元 / 73 个源图建筑部件；分 5 个阶段（待补资料 → 三视图设计 → 精细建模 → 场景替换 → 目标验收）；逐栋重建清单、环境工程清单、来源对照（总平面图）、建筑手册。
- **视觉**：写实建筑体量（示例：图书馆 B50 的橙砖 + 玻璃幕墙效果图）、日景光照/大气/水体预设、植被模型；配色偏暖白 + 自然绿。
- **交付物**：下载三维离线版、校园源码、建筑设计资源（Google Drive 归档）；有"重建进度"与"下载"页。
- **实现规模**：`main.js` ≈74KB + `scene.js` ≈57KB + 植被/水/光照/大气/资产/对比/软件渲染等十余个模块 + Three.js 本体 + 几何/参数/植被/材质等 JSON（几何约 119KB、重建计划约 1.1MB）。

## 2. 它的数据长什么样（对我们最有价值的部分）

| 文件 | 内容 | 规模 |
|---|---|---|
| `assets/geometry.json` | 按总平面图描出的 129 个要素：73 栋建筑多边形 + 8 块水面 + 17 条道路中心线 + 运动场/广场/地形轮廓/红线等；坐标是**原图像素**（848×493），明确标注"无可靠尺寸、不得当米" | 119KB |
| `assets/model_parameters.json` | 79 栋建筑的高度/楼层假设（层高 3.05 模型单位；住宅默认 5 层、学研 4 层、公共 3 层、体育 2 层；B50 特殊 18） | 19KB |
| `assets/campus-reconstruction-plan.json` | 48 个建筑设计单元与真实楼名映射，例如：B20 厚德楼、B28 精诚楼、B32 五行楼、B36 至善楼、B40 自强楼、B44 教学综合楼、B50 图书馆、B58 国际中医药培训中心、B59 明德楼、B60 求真楼、B66 中医实训楼、B70 体育馆、B04 延平学生活动中心、B53 食堂综合楼… | 1.1MB |

**注意**：它的数据是"按同一张总平面图描的"，与我们一起看到的规划图同源；但**楼名/高度都有"推定"成分**（文件里明确写了 `observed_or_inferred`、`assumed_floors`），且**同样没有 16 号楼 / 23A / 23B**（电费关注的那几栋不在这张一期图里）。

## 3. 能借鉴 vs 不能照搬

### 可以借鉴（不增加依赖）
1. **交互范式**：拖拽旋转 / 滚轮缩放 / 右键平移 / 点选建筑 → 信息卡 / 双击复位；小地图显示相机位置；"视角预设"。
2. **状态与反馈**：加载阶段文案（"正在准备地形、水岸与建筑体量…"）、场景脚注（"依据总平面图重建 · 高度为建模假设"）、侧栏"本轮研究说明"。
3. **内容组织**：楼栋索引 + 重建进度 + "关于这张图"（来源对照/免责说明）可做成我们地图页的"关于"弹层。
4. **视觉基调**：暖白/自然色、低饱和建筑体块、克制的 UI 工具栏（与班级工具站现有风格兼容）。

### 不能照搬（会破站点红线或不可维护）
1. **整站/整场景嵌入**：Three.js + 模型 + 植被/材质/JSON 是数 MB 级；违反"单文件、零构建、零依赖、零外部请求"；旧教室电脑/微信 X5 WebGL 兼容与性能风险大；且参考站托管在 `chatgpt.site`，可用性不受我们控制。
2. **直接复制其 geometry/模型**：除非确认版权归属与授权（见下"待确认"）。研究数据本身也标注了大量"推定"，精度不等于测绘。
3. **一套 48 栋的研究级重建流程**：成本远超班级工具站的需求（我们要的是"找楼/找教室/下一节在哪"，不是建筑档案）。

## 4. 我们的落地方案（已在 mock_3d 里验证）

**原生 Canvas 2D 的「2.5D 体块校园」**（无 WebGL / 无第三方库，≈15–25KB 代码）：

- 正交斜视投影 + 建筑体块挤出 + 画家算法排序；水面/道路/广场平铺；树木点缀；建筑按类别着色。
- 交互（正式实现）：拖拽旋转、滚轮/双指缩放、右键/双指平移、点选楼栋 → 信息卡、"下一节"高亮 + 步行路线虚线与估算、视角复位、"平面 / 2.5D"切换。
- 数据：复用我们 `map_draft.js` 的楼栋多边形 + 湖岸线（来自总平面图提取），高度按楼层假设（如 5 层教学 15.3、4 层 12.2），图上明确标"高度为建模假设 · 非比例尺"。
- 性能：40–70 个体块 + 平面层，Canvas 2D 在手机上 30–60fps 无压力；低端机/`prefers-reduced-motion` 时自动降级为静态平面。
- 概念图：`mock_3d.png`（桌面）、`mock_3d_phone.png`（手机）。
