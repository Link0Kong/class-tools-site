## 1. 我理解的需求（先对齐）

在工具站新增「校内地图」工具，解决三件事：

1. **找楼**：校内主要楼栋 + 生活服务点（食堂/快递/医务室/超市/打印店/运动场/宿舍楼）一张图看清。
2. **找教室**：课表里的 `厚德楼(教室02101)`、`自强楼(教室01104)` 能直接定位到楼栋，最好能到楼层/房间。
3. **下一节课在哪**：课表页「下一节」与地图联动，一键高亮。

明确**不做**（除非你另外要求）：校园 GPS 定位/「我在哪」、真实路径导航、校外地图、地图图片导出。

### ③ 你给的规划图怎么用：**描摹参考**，不直接当底图（推荐）

**不建议**直接把这张 1603×931 的规划图放进页面当底图，原因：

1. **版权**：学校规划图/设计院成果属图形作品，公开网页（即使有身份门禁）不适用"课堂合理使用"，需要学校书面授权；
2. **审图**：图上有用地红线、周边道路、方位、拟建项目，比"手绘示意图"更接近《地图管理条例》要审的"地图"；
3. **清晰度**：手机全图时楼名只有 3–4px，必须放大到 4 倍才能读，且放大后糊；
4. **时效/一致性**：图上有"拟建"项目，且没有 16#/23A/23B，和课表、电费对不上；直接当底图会显示过期/缺失信息。

**推荐做法（也就是我已做的）**：以这张图为**描摹参考**重绘矢量示意图——湖岸线按原图轮廓提取（`extract_water3.py` 离线跑一次，不发布原图像素），楼栋按相对位置摆放，颜色/字阶按站内规范；最终产物是原创 SVG，无版权/审图问题；原规划图不随仓库/站点发布（本地参考用）。草图见 `map_draft.png`。

## 2. 硬约束（这些直接筛掉了大部分方案）

| 约束 | 影响 |
|---|---|
| 单文件、零构建、原生 JS | 不能引入 Leaflet/MapLibre 等第三方地图库；地图要用原生 SVG/Canvas 自己画 |
| **零第三方请求**（不加载 CDN/第三方脚本/字体/统计） | 高德/腾讯/百度 JS API、OSM 瓦片 **网页端直接违反红线** |
| 课表/身份已有，且教室号只在 `tt.json` | 教室数据必须从课表同源解析，不能另造一份容易对不上的清单 |
| 手机优先、顶部工具条、无底栏 | 地图是「工具内容」：内容区横拖不能切工具（必须注册手势豁免） |
| 三端（网页/小程序/安卓） | 网页先上；小程序源码改完要你手动上传发布；安卓另出 APK |
| 合规（调研结论见 §6） | 自绘示意图风险最低；官方图/航拍/在线地图有版权与审图问题 |

## 3. 三个方案对比

### 方案 A：自绘矢量示意图（推荐）

**形态**：内联 SVG 手绘校园平面示意（楼栋块 + 道路 + 点位），可拖动/缩放；每个楼栋可点开信息条；搜索框输入楼名或教室号直接高亮；「下一节」从课表联动。第二阶段给重点教学楼做楼层平面（房间网格）。

**数据**：一份内联 `CAMPUS_MAP` JSON（约 20–50KB）：楼栋矩形/多边形、名称、类别、楼层房间、POI 点位、主路折线；无经纬度、无比例尺（只给一个"约 xx 米宽"的估算提示，用于步行时间）。

**优点**
- 零外部请求、零新增图片资源、离线可用、任意分辨率清晰；
- 完全贴合站内视觉（暖白/雾青/灰蓝/暖沙、卡片圆角），不是"嵌了一个地图"；
- 楼栋/教室/下一节都与课表同一份数据源，不会出现"地图说 A、课表说 B"；
- 无版权风险（原创绘制）；无真实坐标/边界 → 不落入审图范围（见 §6）；
- 体积极小（+30–60KB），对 1.23MB 单文件影响可忽略。

**缺点 / 成本**
- 需要人工画（校园相对位置正确即可，不追求比例尺）：首次绘制 4–8 小时（v0 草稿已完成，正式版校核/补楼约 2–4 小时，含生活服务点现场核对）；
- 后续新增/改建楼栋要改数据（1 处 JSON + 重新部署）；
- 精度是"示意图"级别：只保证相对位置与顺序。

**工作量（网页 v1）**：前端 4–6h + 数据绘制 4–8h + 测试 3–4h + 部署验收 1h ≈ **1.5–2 人天**。

### 方案 B：官方/实拍平面图 + 热点

**形态**：把学校官网/学工处/宣传册的校园平面图（或航拍/卫星截图）当底图，按百分比坐标叠热点。**你现在提供的规划图就属于这一类——建议只作描摹参考（见 §1b③），不建议直接当底图。**

**优点**：视觉最"真"、制图成本最低（有图就能用）、航拍图信息量大。

**缺点 / 风险**
- **版权**：地图/示意图属《著作权法》图形作品，公开网页不适用"课堂教学少量提供"的合理使用 → 必须有学校书面授权（调研结论 §6）；
- **审图**：若底图被认定为"地图"（有方位/边界的成品图），公开需要审图号，且不得擅自修改；
- 高德/百度/卫星影像截图还违反服务商条款，航拍还涉及测绘资质与空域；
- 图片体积 200KB–2MB（内联 base64 再 +33%），且缩放会糊、与站内风格不搭、图会过期（你给的图上还有"拟建"项目，且缺 16#/23A/23B）。

**工作量**：若授权已拿到约 0.5–1 人天；但**授权周期不可控**，不建议作为首发。

### 方案 C：在线地图 SDK（高德 / 腾讯 / 百度 / OSM）

**形态**：真实地图 + GPS 定位 + 路线规划 + 公交换乘。

**优点**：真坐标、路线与距离最准、可扩展性最好。

**缺点 / 结论**
- **网页端直接违反「零外部请求」红线**（加载第三方 JS + 瓦片）→ 不可选；
- 高德/腾讯免费额度仅限"个人学习研究/非商业"，面向全班同学提供服务属授权灰区，且需 Key + 域名白名单；
- 定位属敏感个人信息（PIPL 单独同意）；微信内置浏览器 H5 定位常不弹授权、精度约 100 米，定位不到楼；
- 断网不可用、与"单文件双击可打开"冲突。
- 仅当以后**小程序端**要做"真地图/导航"时，原生 `<map>` 组件才是可选项（另需腾讯位置服务 Key、类目、隐私指引、你上传发布）。

### 方案 D（降级形态）：纯卡片「楼栋索引」

不画图：分组卡片（教学楼/生活/运动/宿舍）+ 搜索 + 「下一节课在自强楼 01104」直达。**0.5 天可上**，能先解决 90% 的"找楼/找教室"，也是方案 A 的数据未就绪时的降级界面。因你要的是地图，D 建议只作为 A 的过渡/兜底，不单独成工具。

### 对比表

| | A 自绘 SVG | B 官方图+热点 | C 在线地图 SDK | D 卡片索引 |
|---|---|---|---|---|
| 零外部请求 | ✅ | ✅（同源图，需放 assets） | ❌ 网页端 | ✅ |
| 版权/审图风险 | 低（原创示意） | 中高（需学校授权/审图） | 中（审图号/授权灰区） | 无 |
| 视觉与站内一致性 | 高 | 低 | 低 | 高 |
| 真实坐标/导航 | 无（示意） | 无 | 有 | 无 |
| 体积 | +30–60KB | +0.3–2.6MB | 0（但联网） | +10KB |
| 制作/维护 | 人工画，一次性 | 有图就行，易过期 | 接 SDK，受外部约束 | 最简单 |
| 推荐度 | ★★★★★ | ★★（授权后才考虑） | ★（网页端不可选） | ★★★（兜底） |

## 5. 方案 A 的具体设计（可直接照此实现）

### 5.1 入口与页面
- `TOOLS`（当前 12 项，L5543–5555）**追加在数组末尾**：`{k:"map", n:"地图", d:"校内楼栋与教室位置；下一节课在哪"}`；默认 `homeTools` 是固定的 `["draw","hw","nt","tt"]`（L3517）→ **老用户默认工具栏不变**，地图出现在「全部」页，由用户自己拖入（homeTools ≤4）；
- `ALL_TONE` 增加 `map:"teal"`（全部页卡片色调，1 行）；`allCardDefs`/`renderTabs` 会自动收录，无需另改；
- 使用说明 `UG.CARDS` 新增 1 张「校内地图」卡（学习分类，紧随「课表」卡），配图可复用现有 scene（零新图片）；如想更贴切再加一个内联 `ugIcoMap` SVG symbol；
- 页面骨架 `#s-map` 插在 `#s-file` 与 `#s-all` 之间；手机 = 地图卡 + 下一节课卡 + 常用地点；桌面 ≥960px = 左侧地图 + 右侧栏（下一节 / 楼栋索引 / 教室索引），符合"桌面靠排布"的要求；
- 记录：`gotoTab` 增加 `if(k==="map"){…MAP.enter();}`（切走清理仿 DIAG/PPT/VOTE 的 `leave()`）；history 返回键、滚动位置恢复（POS/HIST）自动生效，无需改。

### 5.2 地图交互
- 容器内拖动平移（pointer events + transform，`touch-action:none`），双指/按钮缩放（0.8–2.5x），双击放大，复位按钮；
- 楼栋点击 → 高亮 + 底部信息条（名称/类别/教室数/教室号 chips）；点位点击 → 小信息条；
- 搜索：输入楼名或教室号（`01104`、`自强楼`、`厚德楼`）→ 命中即高亮并居中；无结果提示"课表里没有这个教室"；
- 「下一节课」：直接复用现有课表逻辑 `ttNowInfo(ttData().c, ttNowWeek())` 取 `info.c.room`（形如 `自强楼(教室01104)`）与 `info.kind/left`，解析出楼栋+教室号 → 高亮楼栋 + 若有楼层数据则切到对应楼层 + 房间高亮；课表页与地图页共用同一份 `ttData()`（发布链接/个人课表/公共课表优先级天然一致）；
  - **课表联动示例**：`info.c.room = "自强楼(教室01217)"` → 自强楼（01 号楼）→ 2 层 → 17 教室 → 高亮楼栋 + 切到 2F 房间图；`"厚德楼(教室02101)"` → 02 号楼 1 层 01 教室；
  - **解析注意**：`room` 里还有非楼栋值（`体育场篮球区(篮球场1-3)`、`网络平台(网络平台)`）和嵌套全角括号（`自强楼(01506-语音室（6）)`）→ 规则取"首个左括号前=楼栋，最后一个右括号前=教室"，解析不到楼栋的值不强行上图（或归到"运动场"类 POI）；
  - **时机**：课表快照是 idle 时才拉（`ttSyncPull`），地图页 enter 时可能为空 → enter 时先渲染静态地图，拿到 `ttData()` 后再补高亮（与课表页一致的兜底）；
- 手势豁免：在滑动引擎唯一豁免入口 `excluded()` 中加 `if(closest(t,"#mapStage"))return true;`，并给舞台 `touch-action:none`、自己挂 pointer/touch 处理（照抄电费趋势图 L7271–7294 的 `passive:false` + `preventDefault` 写法）→ 地图内横拖**不切工具**；不要复用 `.tscroll` 的 `scrollWidth` 判定（地图不是横向滚动容器）；
- 不显示比例尺/经纬度；图角落标注「示意 · 非比例尺 · 不作导航用途」。

## 6. 合规结论（调研摘要，含依据）

1. **自绘示意图**：只画楼栋相对位置、不含经纬度/比例尺/行政边界的手绘示意图，通常不进入地图审核；但一旦画出方位、周边道路或边界关系，仍可能被认定为地图（《地图管理条例》第 15 条"内容简单的地图除外"；自然资源部公开答复同口径）。建议图上注明「示意图 · 非测绘成果 · 不作导航用途」。
2. **官方图/航拍/卫星截图**：默认不能用。地图/示意图属《著作权法》图形作品，公开网页不适用课堂合理使用；服务商影像截图违反其条款；航拍可能涉及测绘资质与空域许可。需学校书面授权才考虑。
3. **在线地图 SDK**：个人非商业配额可用但"面向他人提供服务"属授权灰区，须展示审图号；网页端违反本项目零外部请求红线。仅小程序原生 map 端未来可选。
4. **定位（我在哪）**：不建议。微信内 H5 定位不可靠（官方 FAQ 建议改用 JSSDK），前端定位约 100 米误差，位置属敏感个人信息（PIPL 第 28/29 条）。用"选楼栋/高亮"替代。
5. **同类案例**：武大"智慧珞珈"、参观北大等 30+ 校园导览、学生自建"首义地图"均为「定制（手绘）底图 + 点位数据」，没有直接截官网图。
6. 具体条文与链接：见会话调研记录（地图管理条例/地图审核管理规定/著作权法/测绘法/PIPL/微信开放文档/高德腾讯条款）。

## 9. 风险与取舍（如实）

- **示意图精度**：只保证相对位置/顺序，不保证距离比例；图上明确标注，避免同学误以为导航；
- **数据维护**：楼栋/教室变化需改 1 份数据 + 重新部署；用"课表教室全映射"测试防漏（`tt.json` 现有 17 种 room 值，其中 `体育场篮球区`、`网络平台` 不是教学楼，需单独归类）；
- **楼层号规则（已确认）**：`01203` = 01 号楼 2 层 03 教室；据此 `01104` 是 1 层 04 教室、`01506` 是 5 层 06 教室。课表 17 种 room 值全部可解析；非教学楼的 2 个值单独归类；
- **数据补充缺口**：16 号楼 / 23A / 23B 不在一期规划图上，需你补位置或暂以"生活区"占位；生活服务点（快递/超市/医务室/打印店）需现场指认；
- **规划图版权**：你提供的规划图只作描摹参考，不直接发布；湖岸线由离线脚本从图中提取轮廓后重绘，不携带原图像素；
- **课表时机**：课表是空闲时拉取、个人课表优先，地图页进入瞬间可能还没数据 → 先出静态图、数据到了再补高亮，不阻塞页面；
- **测试硬编码**：三端"使用说明卡数"（网页 17 / 小程序 19 / 安卓 20）与 `v2_ug_check` 的字面量断言，漏改会红——实施时按 §7 清单逐项同步；
- **代码约束**：网页主脚本必须 ES5、零外部 `src/href`（`perf_check.py` 口径），内联 SVG/JSON 不能带 `const/let/=>`；
- **体量**：内联 +30–80KB（1.23MB → 1.26–1.31MB，gzip 约 +10–26KB），可接受；若以后数据涨到 >150KB，再改同源 `tools/campus.json`（需同步改 3 处部署脚本 + Caddy 缓存规则）；
- **隐私/合规**：自绘示意风险低；一旦改用官方图/在线地图/定位，需重新评估授权、审图、隐私；页面不出现学号/姓名/宿舍房间号，不导出图片、不做定位；
- **跨端一致性**：小程序/安卓各有一份几何数据时，用同一份 JSON 源（构建期复制/脚本生成）避免三端漂移；地图偏好不进 UD v6；
- **不做的**：GPS 定位、真实路径导航、公交换乘、地图导出。
