## 0. 结论速览

### 0.1 一句话

班级工具站是「**一个 1.2MB 单文件静态 H5 + 腾讯 CloudBase 单环境 PostgreSQL/PostgREST + 阿里云 1 台 ECS（Caddy 反代 + 4 个常驻微服务）+ 本机 Windows 采集/转换管线 + 原生小程序 + 原生安卓**」的四层拼装系统；它已经有一套**成熟、可复制、已上线验证过的「把外部系统数据接进来」范式**（教务课表登录、完美校园电费、briefdesk 通知、PPT 转换机、drop 互联、诊断 agent）。今日校园若要接，工程上**不缺模式，缺的是「数据从哪来、允不允许来」**。

| 档位 | 形态 | 新增表/RPC/服务 | 主要改动文件 | 工作量（工程侧，不含合规/独立验收） | 置信度 | 最大前置 |

> **工程侧建议（不替代 03 的判断）**：**先做 A（1–1.5 人日，零风险、可立即上线）**；B 只在 01 报告确认数据源可程序化且 03 认为合规后做；**C 不建议在「代登录」形态下贸然启动**——它与现有 `#tLogin` 同构，技术上可行，但合规/风控风险显著高于教务课表（教务是学校自有系统、学生本人密码、只取本人课表；今日校园涉及学校官方门户与更广的个人数据）。若最终一定要实时数据，**C1（队列 + 本机 agent）是唯一不破前端红线的形态**。

### 0.3 最值得复用的 5 个「现成零件」

1. **「云端收单（PGP 密文）+ 本机代理执行 + 结果回写」**：`login_jobs` 表 + `tt_login_enqueue/status` RPC + `C:\briefdesk\scripts\diag_agent.py` 认领循环 + `jwxt.py::sso_login_http`（`deploy/cloudbase/2026-11-08_diag_login.sql:133-248`、`diag_agent.py:688-770`、`jwxt/jwxt.py:428-495`）。**今日校园若走「用户自己密码」的实时代理，照抄这套即可。**
2. **「静态快照行」**：`public.site_assets(id,body,meta,updated_at)`，读 `auth_ok()` / 写 `auth_admin()`，课表已用它去域名化（`deploy/cloudbase/2026-11-07_site_assets.sql:33-56`、`jwxt/tt_cloud.py:191-249`、网页读路径 `tools/index.html:9652-9677`）。**今日校园的公共/共享只读数据可以直接加一行 `id='tc'`，零 DDL。**
3. **「三端页面标准动作」**：`TOOLS.push` + `#s-xx` 段 + CSS 块 + `gotoTab` 包装 + `ALL_TONE`（`tools/index.html:19068-19104` 的 `file` 工具是当前最小样例）。**加今日校园页照这个 diff 做，不重排主结构。**
4. **「ECS 常驻微服务 + Caddy 反代 + 云助手部署」**：`drop_app.py`（8093）/`pptfiles_app.py`（8092）/附件（8091）/board api（8090）；鉴权统一走 `rpc/class_whoami`（120s 缓存、fail-closed 503）；部署走 `deploy/ecs_*.py`（云助手 RunCommand，无需 SSH）。**C2 形态的脚手架现成。**
5. **「定时只读采集」**：云函数 `power_sync`（每小时:01）+ 本机 `sync_power_cloud.py`（每小时:46 兜底）→ `power`/`power_history` 表；以及本机 QQ/微信采集→通知→云端（`briefdesk`）。**B 档的采集侧照这两条链路选一条。**

## 2. 身份 / 权限 / 同步（接新数据前必须过的门）

### 2.1 身份门禁与 token

- 唯一入口：**学号 + 姓名** → `POST rpc/class_verify`（`p_sid`,`p_name`）→ 云端签发 **30 天 token** + sid/name/role/badge/is_admin；匹配 `private.class_ids`（70 人 + 1 个 `is_test` 测试身份）。
- 网页头：`X-Device-Id: <token>`（`:5117` 调 `class_verify`；`authHdr` `:4970`）；小程序/安卓头：`X-Class-Token`；服务端 `auth_hdr()` 两者都接受（`AGENTS.md:18`；`CLOUDBASE.md:14-22`）。
- 名单：`rpc/class_members`（`:5131`）返回全班（测试身份被过滤，`AGENTS.md:16`）。
- 管理员：`canManage() = AUTH.is_admin`（`:5071`）；当前唯一管理员见 `AGENTS.md:19`（本文不重复真实学号/姓名）。
- token 失效：前端回身份页；各端 401 → 清会话（安卓 `docs/ARCHITECTURE.md:76-78`）。
- **新工具页必须在身份通过后才可请求数据**（门禁前 0 请求是既有测试口径，如诊断页 `AGENTS.md` §18-①）。今日校园页同样适用。

### 2.2 RLS 与角色

| 角色 | 判定 | 能做什么 |
|---|---|---|
| anon | 只有 publishable key | 除登录 RPC 外基本读 `[]`；部分表（`polls`/`draw_*`）**完全无直连权限** |
| 班级成员 | 有效班级 token（`auth_ok()`/`auth_sid()`） | 读共享表；写本人数据（`marks`/`userdata`/`visits` 本人行等）；投票/存证走 RPC |
| 班委/团员 | `auth_is_committee()` / `auth_is_league()` | 决定 audience=committee/league 的可见性（`CLOUDBASE.md:367-410,426-435`） |
| 管理员 | `auth_admin()` | 写 `site_assets`/`service_health`/公告 override/角色；跨人读 |

- 设计铁律：**不能用前端隐藏代替权限**（`AGENTS.md:17`）。今日校园数据若落库，**必须新表 + RLS + 服务端裁剪**，不能把「今日校园 token」放前端。
- 新表若要「本人可读/管理员可写」，照 `ppt_decks`（`deploy/cloudbase/2026-11-09_ppt_decks.sql` 的 `pd_*`/`pc_*` 策略段）或 `userdata`（`security_hardening.sql:83-93`）写策略即可；但注意**权威 `auth_*` 函数不在仓库**（§1.3），新迁移只能「调用」它们、不能重建环境——这是 P0 迁移风险（详见 §4）。

### 3.1 a · 教务 SSO 课表登录（与今日校园最同构的范式）

**链路（2026-11-08 后默认纯 requests）**：

```
网页 #tLogin（输入学号+密码，密码提交后立即清空，不落 localStorage/日志）
  → POST rpc/tt_login_enqueue {p_pwd,p_platform:'web'}（X-Device-Id）

          → pgp_pub_encrypt(密码, agent 公钥) → login_jobs.pending（expires 15 分钟）
  → 每 1.5s 轮询 rpc/tt_login_status（≤120s）→ done/ failed/ expired

  login_jobs?status=pending → PATCH claimed（乐观并发）→ pgpy 解密私钥

  → 门户 → 教务系统 cookie → 抓周课表 HTML → parse_timetable

前端 done → D.d.ttLocal={c,t} → UD v6 tt section 同步 → 立即 renderTT()
```

**关键约束（原样适用于今日校园）**：
1. 云函数**不可达校园内网**（实测 `210.34.74.77` 超时，`HANDOFF.md:2381`）→ 若今日校园接口也限校园网，**只能本机 agent**。

3. 同一学生并发登录会互踢（教务侧，`HANDOFF.md:201`）→ 需要「同一账号只允许 1 个未完成任务」的复用逻辑（RPC 已实现 `reused:true`）。

## 6. 各端能力边界（今日校园页面/数据能不能承载）

### 6.1 网页 H5（浏览器 / 微信内浏览器）

| 能力 | 结论 | 证据/原因 |
|---|---|---|
| 直接请求今日校园接口 | ❌ 基本不可行 | ① 跨域：对方不给你 CORS 头就 403；② 第三方 cookie：浏览器 SameSite/ITP/第三方 Cookie 淘汰，跨站带不上登录态；③ 页面是 HTTPS，若对方是 HTTP 则混合内容被拦；④ 我们自己的 CloudBase 网关也只放行白名单 Origin（`deploy/ECS_DEPLOY.md:52-58`） |
| iframe 嵌入今日校园页面 | ❌ 不可依赖 | 对方若设 `X-Frame-Options`/CSP `frame-ancestors` 则被拒；即使能嵌，也无法读其 DOM（跨域），且微信内置浏览器另有策略——**具体需确认【需确认】** |
| 跳转官方入口（外链） | ✅ | 站内已有大量外链先例（学习通/慕课/QQ 文档/教务系统，`_compliance/备案内容自查_20261106.md:23`）；用 `<a target="_blank" rel="noopener">` |
| 展示「我们后端」的快照/代理数据 | ✅ | 只调 PostgREST（现有红线内） |
| 同源反代绕过 CORS | ✅（仅限自有服务） | ECS `/v1/rdb/rest/*` 同源反代已验证（`deploy/ecs_site.py:135-140`）；但**反代第三方站点会引入登录态/合规问题，不建议** |
| 零外部请求红线 | 必须遵守 | 页面加载不得引外部资源（`AGENTS.md:47`）；外链导航不算加载 |

**结论**：H5 只能做「入口跳转 + 展示我们自己的数据」；**不可能在浏览器里直接读今日校园**。

### 6.2 微信小程序（个人主体）

| 小程序内打开外部浏览器/下载安装 App | ❌ | 微信沙箱不允许（仅 `wx.openDocument` 打开文件） |

**结论**：小程序**不能承载今日校园页面**，只能做入口卡/数据展示；`web-view` 被个人主体硬限制（高置信，官方文档）。
