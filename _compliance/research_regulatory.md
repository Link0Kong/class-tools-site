# 监管研究：班级工具站 → 合规可备案 App

- **研究对象**：`https://tool.furina.fun`（阿里云 OSS 香港静态 H5）+ 腾讯云 CloudBase 个人版（ap-shanghai，PostgreSQL + PostgREST/RPC）+ 微信小程序（个人主体，AppID `wx3df9869d229b96c4`，未上传发布）
- **运营者画像**：福建漳州籍、福建中医药大学 2026 级本科生个人，非商业、班级内部使用
- **研究/查阅日期**：**2026-11-05**（下文所有 URL 均于该日查阅；网页会更新，落地前请复核）
- **研究方法**：仅公开来源（工信部、福建省通信管理局、中国政府网、国家网信办、教育部、微信开放文档、腾讯云/阿里云官方文档、Apple 官方指南）。**未登录任何账号、未提交任何表单、未读取 `deploy/creds.env` / `tools/cert/` / `jwxt/creds.dpapi` 等机密文件、未外发项目数据。**
- **标注约定**：
  - 【硬性】= 法律/行政法规/部门规章/管局规则，违反有法律后果
  - 【官方口径】= 平台或云厂商官方文档/官方答复的执行口径，不等于法律条文
  - 【经验】= 行业实践/从业者总结，供参考，非官方
  - 置信度：**高 / 中 / 低**

## 2. ICP 备案（网站）

### 2.1 `.fun` 能否备案：能

- 【硬性】《互联网域名管理办法》（工信部令第 43 号）要求用于境内互联网信息服务的域名须为已批复后缀、注册服务机构已批复、实名信息与主体一致。
- 【官方口径·高】阿里云《域名准备与检查》（更新于 2026-09-23）明确三条核验要求：①后缀获工信部批复；②注册商为已批复机构；③域名持有人信息与备案主体一致；并在附录"其他顶级域名"中列出 `.FUN`。
- 【硬性·高】工信部 2017-10-11《关于同意北京然迪克思科技有限公司成为".FUN""...顶级域域名注册管理机构的批复》（工信部信管函〔2017〕432号）。
- **结论**：`furina.fun` 后缀与注册商均满足备案条件，**可以备案**。剩余变量只有"域名实名信息是否=本人"和"是否有内地接入资源"。

> 需向平台确认：注册商批复状态可在工信部"域名注册服务机构审批情况"页面复查；阿里云官方称"阿里云计算有限公司"已批复，但**阿里云国际站（alibabacloud.com）注册的域名不适用**，须转入中国站并实名。

### 2.2 当前香港 OSS 架构为什么"备不了案"

- 【官方口径·高】阿里云/腾讯云均明确：ICP 备案的前提是**有中国内地服务器/接入资源**（阿里云：需购买符合备案要求的内地 ECS/轻量等获取备案服务码；腾讯云：云开发环境可作备案资源）。备案由"网络接入服务提供者"代为提交。
- 【官方口径·高】备案期间限制：首次备案/新增网站期间，**域名不得开放访问**，且**不能先把域名解析到中国香港/海外服务器等备案成功后再迁内地**——否则有驳回风险。
- 因此存在两个互斥事实：
  1. 现在 H5 在香港 → **本来就不需要 ICP 备案**（官方口径），也可继续不备案运行；
  2. 但一旦想备案（为了小程序服务器域名 / APP 备案 / 苹果中国区上架），就**必须先把站点迁到内地接入商并停止旧访问**。
- 【经验·中】这意味着 `tool.furina.fun` 若要备案，需要一次**停机迁移**（或换新域名给 API 用，见 §8 路径 B）。

### 2.4 网站名称与"教育类前置审批"口径

这里有一个**容易踩坑的法规冲突**，必须说清楚：

1. 【硬性】《互联网信息服务管理办法》（国务院令第 292 号）第五条规定：从事新闻、出版、教育、医疗保健、药品和医疗器械等互联网信息服务，依法须经有关主管部门审核同意的，**在履行备案手续前应经主管部门审核同意**。
2. 【硬性】《非经营性互联网信息服务备案管理办法》（信产部令第 33 号）第十一条同样列出"教育"等需前置审批的类别。
3. 【硬性】但 2016 年 2 月 3 日《国务院关于第二批取消 152 项中央指定地方实施行政审批事项的决定》（**国发〔2016〕9 号**）取消了"教育网站和网校审批"。此后**设立教育网站不再需要教育行政部门前置审批**；多地教育部门（如湖南、贵州）公开答复也明确按国发〔2016〕9 号执行。
   - [国发〔2016〕9号全文](https://www.gov.cn/zhengce/content/2016-02/19/content_5043903.htm)
4. 【官方口径·中高】然而云厂商备案系统的**关键词库与 FAQ 仍把"教育"列为敏感领域**：华为云《ICP备案常见问题》把"教育类"列入需前置审批的行业类型；阿里云开发者社区答复称"网站名称含新闻、出版、教育、医疗保健…等字样需联系主管部门办理前置或专项审批"。这属于**表单层面的审慎口径**，不是新设审批。
5. 【经验·中】实际操作中，管局对**个人**网站的审核重点是"名称是否让人误以为是教育机构/在线教育平台"。纯班级事务工具（作业登记、通知、课表、抽签、体测记录）**不构成"教育信息服务"经营**，一般不需要前置审批；但名称、简介、页面文案里出现"教育/学习/学校/课堂/学科/教辅/培训/考试/成绩查询"等词，很容易被驳回或要求补材料。

**建议网站名称与文案策略**（经验）：
- 名称避开：教育、学习、学校、课堂、学科、教辅、培训、考试、成绩、教务、校园、家长、老师。
- 可用方向："XX班务工具""班级小助手""班务汇总""（谐音/中性词）+ 工具"。
- 服务内容选"其他"；简介只写"班级内部事务工具，非公开、非商业"。
- 若被要求补前置审批材料，可书面引用国发〔2016〕9 号说明"教育网站审批已取消"——**是否被接受须由福建管局决定**。

> **需向管局确认（路径）**：福建省通信管理局官网 `https://fjca.miit.gov.cn/`（联系电话 0591-83327386，官网公示），或通过阿里云/腾讯云备案客服工单转管局口径确认；工信部备案系统全国咨询电话 010-66411166（`https://beian.miit.gov.cn/` 首页公示）。

### 2.5 流程、材料、时长、费用

【官方口径·高】以阿里云代备案流程为例（腾讯云基本一致）：

**流程（6 步）**
1. 准备：阿里云账号实名、域名（实名且与主办人一致、有效期>45 天）、内地服务器（获取"备案服务码"）。
2. 在阿里云 ICP 代备案系统填写主体信息（个人：姓名/身份证号/手机号/邮箱/应急联系人/通信地址）。
3. 填写网站信息（网站名称、服务内容、域名、服务器 IP、网站负责人）。
4. 上传资料 + **人脸核验/实人核验**：身份证正反面、域名证书；签署《互联网信息服务备案承诺书》《信息安全管理协议》。
5. 阿里云初审（**1~2 个工作日**，会电话核验真实性）。
6. 工信部短信核验（**24 小时内**在备案系统完成，超时驳回）→ 管局审核（**1~20 个工作日**，法定最长 20 工作日）→ 下发备案号。
- 阿里云整体预估：**约 3~22 个工作日**。

**材料清单（个人·福建）**
| 材料 | 说明 |
|---|---|
| 身份证原件彩色扫描/拍照 | 网站 ICP 备案：接入商通用要求**证件有效期大于 3 个月**（阿里云上传资料要求）；小程序备案要求**大于 1 个月**（微信文档）。证件须为最新一次办理，非最新有效期会被驳回 |
| 域名证书 | 从域名控制台下载 |
| 手机号、邮箱、应急联系人手机 | 本人实名、可接通，不与主体负责人重复 |
| 人脸核验 | 平台内完成 |
| 互联网信息服务承诺书 | 平台内签署 |
| 补充材料 | 16~18 岁：监护人申明+身份证或收入证明；非本省户籍：居住证 |
| （若触发）前置审批文件 | 教育类一般不需要，但名称/内容触发时会被要求 |

**时长**：接入商初审 1~2 工作日 + 管局 1~20 工作日（福建实际多在 5~15 工作日，经验值）。
**费用**：**ICP 备案本身免费**（阿里云明确"不收取服务费用"，但需先购买内地服务器/云资源，服务器费用另计）。[阿里云-ICP备案计费说明（官方问答页）](https://cn.aliyun.com/sswd/11994848-1.html)

### 2.6 备案期间与备案后的访问限制、备案号展示

- 【硬性】备案期间：**未备案/备案中网站不得开放访问**；首次备案/新增网站期间不能把域名解析到香港/海外再迁回内地，否则驳回。
- 【硬性】备案后：网站须正常可访问，**底部中央悬挂 ICP 备案号并链接** `https://beian.miit.gov.cn`；内容须与备案主体性质（个人非经营）相符。
- 【硬性】公安联网备案：网站开通之日起 **30 日内**，到"全国互联网安全管理服务平台"（`https://beian.mps.gov.cn/`）办理公安联网备案（依据公安部 33 号令；各地公安均按此执行）。[深圳公安-新办网站备案专题](https://ga.sz.gov.cn/ZT/HLWSYSQ/)
- 【经验】备案成功后若域名长期解析到境外（如继续用香港 OSS），接入商核查可能以"未实际接入"为由取消接入，导致备案失效。

### 2.7 驳回常见原因（ICP 备案）

综合阿里云/华为云官方 FAQ 与管局规则：
1. **网站名称**含前置审批领域词、含"中国/福建"等易误导前缀、与知名品牌近似、少于 3 个汉字。
2. **域名问题**：未实名、实名信息与主办人不一致、有效期不足、注册商未批复、后缀未批复。
3. **证件问题**：身份证过期/非最新/模糊、非彩色、边角不全。
4. **联系方式**：手机号非本人实名、与应急号码重复、打不通、邮箱无效。
5. **网站内容**：备案期间可访问、内容与个人性质不符（有商业/企业内容）、页面出现需前置审批的内容。
6. **年龄/居住材料**缺失（16~18 无监护人材料、外省户籍无居住证）。
7. **空壳主体**：福建要求空壳主体先注销再提交新备案。
8. 短信核验超 24 小时未完成 → 系统自动驳回。

### 3.2 个人主体：可以备案，但类目/名称受限

- 【官方口径·高】小程序备案主体分"个人/单位"；个人备案必需材料仅为**个人有效身份证件**，另有平台内的人脸核身、承诺书、真实性核验单。
  - [微信-小程序备案操作指引（2026-08-18）](https://developers.weixin.qq.com/miniprogram/product/record/record_guidelines.html)
- 【官方口径·高】**备案"服务内容"选择**：微信《小程序备案服务内容标识选择指引》（2026-03-25）中，个人备案可选"符合个人性质"的类目；**教育大类（儿童教育/培训机构/学校/其他在线视频课程）个人备案一律"不建议选择"**；"工具"大类个人"可选，符合个人性质"；"其他"大类个人"可选"。
  - [微信-备案服务内容选择指引](https://developers.weixin.qq.com/miniprogram/product/record/record_review.html)
- 【官方口径·高】**小程序服务类目**（与备案服务内容不同，是审核侧）：个人主体开放的"工具"类含：记账、日历、天气、办公、图片处理、计算器、报价/比价、**信息查询**、**预约/报名**、健康管理、**备忘录**（均无资质要求）。个人主体"教育服务"只剩**"教育信息展示"**（明确"不支持教育视频播放/直播、课程产品销售"）。
  - [微信-小程序开放的服务类目（2026-11-03）](https://developers.weixin.qq.com/miniprogram/product/material/)
- 【官方口径·高】名称筛查：微信官方社区答复——备案前平台会筛名称关键词，"名称应符合个人主体性质，不能涉及企业/单位名义、前置/专项审批相关领域（如新闻/金融/宗教/医疗器械/网约车/**校外培训**等）、国家公共事务等关键字"。
  - [微信开放社区答复（2025-08 / 2026-02）](https://developers.weixin.qq.com/community/minihome/doc/000cccff1644b81d23d3f82a06b000)

**对本案的建议（经验+官方口径）**：
- 备案服务内容选 **"工具"** 下最贴近的二级（建议"信息查询"或"办公"或"预约/报名"），**不要选教育**；
- 小程序类目选 **工具-信息查询 / 工具-办公 / 工具-预约报名**；
- 名称避开"教育、学习、课堂、学科、教辅、培训、考试、成绩、学校、校园、家长、老师、教务"；"班级"本身不在明文禁词，但会进入人工审核，建议名称+简介强调"班级内部事务工具、非公开、非商业、无教学内容"。
- 注意：**备案服务内容与小程序类目要能互相印证**，选了"信息查询"类目却满屏课表/作业，可能被要求改类目或补说明。

### 3.4 未备案的后果

- 【硬性】不能上架/发布（未上架小程序）；已发布会被**清退下线**（2024-04-01 起）。
- 【硬性】未备案小程序发布后**无法被搜索**（微信社区答复：发布后不可搜索，完成备案解除）。
- 【硬性】按 105 号文，"网络接入服务提供者、分发平台、智能终端生产企业不得为未履行备案手续的 APP 提供网络接入、分发、预置等服务"——即微信平台有义务拦截。

### 3.5 服务器域名的 ICP 口径（本项目最关键的技术合规点）

**规则原文**
- 【硬性·高】微信《网络·基础能力》：配置服务器域名时"**域名必须经过 ICP 备案**"，且"不支持配置父域名，使用子域名"；`wx.request/uploadFile/downloadFile/connectSocket` 只能向已配置域名发请求。
  - [微信-网络能力（2026-08-21）](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

**CloudBase 默认网关域名（`*.app.tcloudbase.com` / `*.tcloudbasegateway.com`）**
- 【官方口径·高】腾讯云《HTTP 访问服务》（2026-04-21）："CloudBase 为每个环境提供默认域名（`*.app.tcloudbase.com`），但**默认域名仅适用于开发测试阶段**……**生产环境必须绑定已完成备案的自定义域名**"。
  - [腾讯云-HTTP访问服务](https://cloud.tencent.cn/document/product/876/130728)
- 【官方口径·高】腾讯云《默认域名访问限制及中间页》：生产环境使用默认域名可能因流量触发风控被关停，请务必配置自定义域名；默认域名内容未经前置备案与人工审核，须履行提醒义务。
  - [CloudBase-默认域名访问限制](https://docs.cloudbase.net/service/alias)
- **结论**：默认网关域名**不是"豁免通道"**——备案主体是腾讯而非开发者，且官方明确只用于开发测试；即便个别情况下能加入白名单，也不满足"生产环境"的合规与稳定性要求。**不能作为长期方案。**

**自有域名 `tool.furina.fun` 未备案**
- 【硬性】无法在 mp 后台"服务器域名"中配置（微信校验 ICP 备案状态）；小程序 `wx.request` 直连会被拦截。
- 【硬性】若小程序内用 `<web-view>` 嵌 H5，还需配置"业务域名"，同样要求 ICP 备案 + 校验文件。H5 在 OSS 香港且域名未备案 → 无法配置。
- **结论**：**只要小程序用 `wx.request` 直连自有域名，该域名就必须先完成 ICP 备案（=必须内地接入）。**

**可免域名/免备案的官方通道（重要）**
- 【官方口径·高】微信云托管 `callContainer`/`connectContainer`：**"无需在小程序后台配置『服务器域名』"**，走微信私有协议。
  - [微信-调用云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)
- 【官方口径·高】微信云开发开发常识："小程序/公众号可使用 CallContainer，**无需域名**，因此不需要在 mp 管理后台配置服务器域名，从而一开始就无需申请域名，也**无需备案**"。
  - [微信-云托管开发常识（2026-11-03）](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/know)
- 【官方口径·高】CloudBase AnyService："通过 AnyService 接入的服务仅需 IP 地址即可，**无需配套域名**。小程序调用时也**无需配置域名白名单**"。
  - [CloudBase-AnyService 概述](https://docs.cloudbase.net/anyservice/intro)
- 【限制】以上通道对**当前项目架构**意味着改造：项目小程序端用 `fetch`/`wx.request` 调 PostgREST + 自定义头 token。要用免备案通道，需要改成 `wx.cloud`（微信云开发 SDK）/`callContainer`/AnyService 之一，取决于 CloudBase 个人版环境与这些能力的兼容性——**这属于技术方案决策，需与后端/小程序开发同学确认**（本研究报告不给实现结论）。但监管口径是明确的：**免域名通道合规；`wx.request` 直连必须备案。**

### 3.6 小程序隐私保护指引（强制）

- 【硬性·高】开发者须在「小程序管理后台-设置-功能设置-用户隐私保护指引」配置《小程序用户隐私保护指引》；**只有在指引中声明所处理的用户信息，才可以调用平台对应的接口/组件**。
  - [微信-用户隐私保护指引填写说明（2026-07-28）](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)
  - [微信-小程序隐私协议开发指南（2026-10-25）](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)
- 【硬性】每次提审会拉取"现网版本隐私协议"与"开发版本隐私接口调用情况"比对，有出入或为空会被拦截，必须先更新隐私协议。
- 【检查点】平台会在提审时按"隐私接口调用情况"比对；因此**声明必须与实际调用一致**（多声明/少声明都可能被卡）。
- **对本案的落点**：
  1. 身份门禁自己采集的"学号+姓名"不属于微信接口类信息，**不会**出现在隐私指引的勾选项里，但属于《个保法》的个人信息 → **必须在小程序内提供独立的隐私政策页面 + 首次使用前弹窗/勾选同意**，并在隐私指引的"其他/说明"部分写清楚。
  2. 若用微信登录/获取昵称头像 → 必须在隐私指引勾选"用户信息（微信昵称、头像）"。
  3. openid 由微信下发，属个人信息 → 在隐私政策中写明用途（身份绑定、订阅消息）。
  4. 订阅消息 → 必须在隐私政策与页面提示中说明用途，且**只能用户主动点击订阅**。
- 【经验】常见被拒/被拦：隐私指引与实际接口不符；收集手机号但未声明；首次启动未展示隐私弹窗；隐私政策链接打不开或内容空白。

## 4. APP 备案（工信部移动互联网应用程序备案）

### 4.1 适用对象：原生 App、小程序、快应用都覆盖

- 【硬性·高】105 号文：在境内从事互联网信息服务的 **APP 主办者**应履行备案；分发平台"（含小程序、快应用等分发）"承担核验义务。
- 【推论·高】小程序由**微信平台**统一代提交（微信备案系统），因此**完成"小程序备案"即视为完成该小程序的 APP 备案**——不需要也不可能再单独为同一个小程序做一次原生 APP 备案。
- 【硬性】**原生 App（含 WebView 套壳）是另一套备案**：需通过其**网络接入服务提供者**（云厂商）或**APP 分发平台**（应用商店）向主办者住所地省级通信管理局备案。**不能拿小程序备案号顶替 App 备案。**

### 4.2 个人主体可办

- 【官方口径·高】阿里云《App 备案快速入门》直接以"个人 App"为例：备案前需准备阿里云账号（实名）、域名、内地服务器（ECS 等）、**App 特征信息（包名、公钥、签名证书指纹 MD5）**；流程与网站备案类似。
  - [阿里云-App备案快速入门](https://help.aliyun.com/zh/icp-filing/basic-icp-service/getting-started/quick-sta-rt-for-icp-filing-for-personal-app)
- 【硬性·高】105 号文：APP 主办者向其**住所所在地**省级通信管理局备案；材料齐全准确的，**20 个工作日内**予以备案；未备案不得从事 APP 互联网信息服务。
- 【硬性】APP 主办者应在 **APP 显著位置标明备案编号**，并在编号下方链接备案系统网址；信息变更/注销需办手续。

### 4.3 材料、流程、时长、费用

| 项 | 内容 |
|---|---|
| 主体材料 | 个人：身份证（人脸核验） |
| App 特征信息 | **App 名称、包名、公钥、签名（证书指纹 MD5）**；运行平台（Android/iOS）；若上架，需应用商店开发者账号（用于生成签名） |
| 网络资源 | 域名（需符合域名核验要求）、IP/服务器（需内地接入资源作备案授权） |
| 流程 | 云厂商备案系统或分发平台 → 填写主办者/APP 信息/接入信息/运行平台 → 上传证件+人脸核验 → 云厂商初审 → 工信部短信核验（24h）→ 管局审核（≤20 工作日）→ 下发备案号 |
| 时长 | 约 3~22 个工作日（同网站备案） |
| 费用 | **备案免费**（服务器/开发者账号成本另计） |
| 后续 | 自 App 开通之日起 **30 日内**完成**公安联网备案**（阿里云文档明确要求） |

### 4.4 与 ICP 备案的关系

- 【硬性·高】105 号文："对于已履行网站备案手续的，仅需补充完善其 APP 有关信息，无需重复填报主办者真实身份信息。对于没有网站备案信息的，按照本通知规定履行备案手续。"
  - 即：**网站 ICP 备案 ≠ APP 备案，但可以复用主体身份信息**；两者是**并列的两套备案**。
- 【经验】实操上云厂商 App 备案同样要求域名/服务器符合核验规则，所以"没有网站备案"时仍需域名实名、后缀批复等条件，只是不走一遍网站备案订单。

### 4.5 未备案的后果

- 【硬性】未备案 APP 不得从事互联网信息服务；接入商不得提供接入、分发平台不得分发、智能终端不得预置（105 号文第（九）项）。
- 【硬性】2024-04-01 起，逾期未备案的境内存量 App/小程序被下架关停（工信部/各省管局公告口径）。

### 4.6 WebView 套壳 App 的风险（本项目若走"转 App"路线必须看）

**苹果侧**
- 【硬性·高】《App 审核指南》**4.2 最小功能**："App 应包含功能、内容和 UI，而**不仅仅是一个经过重新包装的网站**。如果 App 没有什么实用价值、毫无新意或者不太像是一个 App，那它就不适合出现在 App Store 中。"
  - [Apple-App 审核指南（中文，最后更新 2026-06-08）](https://developer.apple.com/cn/app-store/review/guidelines/)
- 【硬性】5.1.1(i)：所有 App 必须有可访问的隐私政策链接，说明收集的数据、用途、第三方共享、保留/删除政策。
- 【硬性】5.1.1(v)：若支持账户创建，必须提供 App 内账户删除功能。
- 【硬性】1.5：面向课堂使用的 App 尤其要提供可联系到的支持信息（对班级工具是加分项也是检查点）。
- 【经验】纯 WebView + 少量壳功能几乎必被 4.2 拒；需至少有原生化的核心交互（如本地课表、通知、离线缓存、推送等）并在审核备注里说明"非网站镜像"。

**中国区上架**
- 【官方口径·高（媒体一致转述）】Apple 自 2023-09 起更新 App Store Connect 支持文档：在**中国大陆**上架的 App 必须具备有效的 **ICP 备案号**；App Store Connect 的填写位置为「分发 → App 信息 → App Store 法规和许可 → 中国大陆 ICP 备案号」。
  - [IT之家/搜狐报道（2023-09-29）](https://www.sohu.com/a/724681407_114760)
  - **需以 App Store Connect 实际界面为准**（本次未登录验证；Apple 帮助页 URL 已变更/失效，未能取得官方原文链接——置信度高但属"转述口径"）。
- **推论**：没有 ICP 备案号 → 中国区无法上架 → WebView 壳 App 路线需要先解决 §2 的备案问题。

**国内安卓商店**
- 【官方口径·高】华为开发者问答："当前 apk、应用（除游戏外）上架，《软著》为**非必须**提供，没有《软著》暂不影响上架审核及更新版本；但建议办理以免知识产权风险。"鸿蒙应用"不强制要求软著，但**联网 App 需要备案**"。
  - [华为开发者问答（2026-07）](https://developer.huawei.com/consumer/cn/forum/topic/0203220036052953397)、[华为开发者问答（2026-09）](https://developer.huawei.com.cn/consumer/cn/forum/topic/0204224186632495393)
- 【经验·中】应用宝等部分商店历史上要求"软著或 PC 官网 ICP 备案截图"；当前主流商店对**联网 App 的备案号**是硬要求，软著多为"建议/部分类目要求"。

**结论（WebView 套壳）**：监管与平台双重不友好——①苹果 4.2 拒"网站壳"；②中国区需 ICP 备案号；③APP 备案需域名/服务器符合要求；④内容若直接加载未备案 H5，还会形成"App 已备案但内容域名未备案"的矛盾。**不建议把"WebView 套壳上架"作为主路线**，除非先完成内地备案并把壳做出实质性原生功能。

## 5. 个人信息保护合规

### 5.1 数据定性与法律适用

| 数据 | 定性 | 依据 | 置信度 |
|---|---|---|---|
| 学号 + 姓名 | **个人信息**（可识别特定自然人）；一般不属法定敏感类；但"特定身份"在敏感个人信息中有解释空间，且学号属强标识，泄露可致冒用 | 《个保法》第 4、28 条；[全国人大-个人信息保护法全文](http://www.npc.gov.cn/npc/c2/c30834/202108/t20210820_313088.html) | 中高 |
| 70 人真实班级名单 | 个人信息集合；若含身份证号/手机号/宿舍号则风险升级 | 同上 | 高 |
| 访问统计（IP/UA/页面/时间） | **个人信息**（IP 可间接识别），需告知并最小化 | 同上；《网络数据安全管理条例》第 21 条 | 高 |
| QQ/微信群消息、群成员昵称/头像、OCR 图片 | **他人个人信息**，且可能含敏感信息（健康、家庭、身份等）；无同意基础即处理属违法 | 《个保法》第 10、13、28 条 | 高 |
| 微信 openid | **个人信息**（微信生态内标识符） | 同上 | 高 |
| 订阅消息（openid + 模板） | 个人信息 + 营销/通知合规（必须主动订阅） | 同上 | 高 |
| 反馈内容 | 取决于内容；若含手机号/身份证/照片则可能敏感 | 同上 | 高 |
| 体测数据（身高体重肺活量等） | **医疗健康类信息**倾向 → 可能构成**敏感个人信息**，需单独同意 | 《个保法》第 28 条；GB/T 45574-2025 | 中高 |

**关键条文**
- 【硬性】《个保法》第 13 条（合法性基础）、14 条（同意）、17 条（告知）、19 条（最短保存期限）、23 条（向他人提供需单独同意）、25 条（公开需单独同意）、28~31 条（敏感信息/不满 14 周岁）、38~39 条（跨境）、47 条（删除）、50 条（权利受理机制）、51 条（安全措施）、54 条（定期合规审计）、55~56 条（个人信息保护影响评估 PIA）。
- 【硬性】第 72 条："自然人因个人或者家庭事务处理个人信息的，不适用本法。" **本项目服务 70 名同班同学，不属于"个人或家庭事务"，本法适用**（若只是自己记账则豁免；对外提供班级服务不豁免）。
- 【硬性】《网络数据安全管理条例》（国令第 790 号，2024-09-24 公布，**2025-01-01 施行**）：
  - 第 21 条：处理规则须集中公开、醒目、明确，含处理者名称/联系方式、目的/方式/种类、敏感信息必要性、保存期限及到期处理、权利行使途径；**处理不满 14 周岁未成年人信息还须制定专门规则**。
  - 第 22 条：最小必要；敏感个人信息（生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹等）须**单独同意**；不满 14 周岁须监护人同意；不得超范围、不得频繁骚扰式征求同意。
  - 第 23~25 条：查阅/复制/更正/删除/注销/可携带权，须提供便捷途径。
  - 第 27 条：**定期自行或委托专业机构开展个人信息保护合规审计**。
  - 第 63 条：自然人因个人或家庭事务处理个人信息不适用本条例（同个保法豁免逻辑）。
  - [中国政府网-网络数据安全管理条例全文](https://www.gov.cn/zhengce/content/202409/content_6977766.htm)

### 5.2 必须落实的义务清单（按项目落地）

| 义务 | 本项目怎么落 | 依据 |
|---|---|---|
| 告知 | 首次进入身份页前展示**隐私政策**（可点开全文），明确：处理者=个人运营者姓名/联系方式、收集学号姓名用途、访问统计、反馈、openid、保存期限、权利行使方式 | 个保法 17；网数条例 21；微信隐私指引 |
| 同意 | 身份页勾选"我已阅读并同意《隐私政策》"后才可提交；**不得默认勾选**；不同意则不能使用需说明（身份核验是核心功能，属"必需"，但仍需告知） | 个保法 14；微信规则 |
| 最小必要 | 只收学号+姓名；不要顺手收手机号/宿舍/身份证；访问统计去 IP 或截断/哈希；反馈页提示"请勿填写他人隐私或敏感信息" | 个保法 6；《常见类型App必要个人信息范围规定》 |
| 单独同意 | 体测/健康数据（若按敏感处理）、向第三方提供、公开、跨境 → 单独弹窗同意 | 个保法 23/25/29/39 |
| 保存期限 | 明确"班级在校期间 + 毕业后 X 个月"或"最后使用后 12 个月"，到期删除/匿名化；token 30 天已有期限，需在隐私政策写明 | 个保法 19；网数条例 21 |
| 删除/注销 | 提供"退出并删除我的数据"入口（删除 userdata、marks、feedback、订阅关系）；**不能只清本地缓存**；运营者侧需有后台/脚本可执行删除并留记录 | 个保法 47；微信/Apple 要求 |
| 权利受理 | 页面公布联系方式；7~15 个工作日内响应（经验值）；留存处理记录 | 个保法 50；网数条例 23 |
| PIA | 处理敏感信息、自动化决策、委托处理、向他人提供、公开、出境前做 PIA 并留存 3 年 | 个保法 55~56 |
| 安全措施 | 传输 HTTPS、token 校验、RLS、最小权限、日志审计、备份、应急预案 | 个保法 51；网数条例 9~11 |
| 事件通知 | 泄露/篡改/丢失立即补救 + 通知监管部门和个人 | 个保法 57；网数条例 11 |
| 合规审计 | 定期自审；若有未成年人信息，**每年**审计 | 个保法 54；网数条例 27；未保条例 37；[审计办法](http://jswx.gov.cn/shuju/zhengce/guizhang/202502/t20250214_119142.shtml) |

**《个人信息保护合规审计管理办法》（网信办令第 18 号，2025-05-01 施行）对本项目的适用**：
- 【硬性】处理**超过 1000 万人**个人信息 → 每两年至少一次合规审计（本项目远未达到，不触发强制专业机构审计）。
- 【硬性】监管部门在"较大风险/可能侵害众多个人权益/发生大规模泄露"时可要求委托专业机构审计（本项目风险低但**群消息抓取**这种结构性违规会显著提高被要求审计的概率）。
- 【硬性】《未成年人网络保护条例》第 37 条：处理未成年人个人信息的，**每年**自行或委托专业机构合规审计并报告网信等部门——这条**没有人数门槛**，只要用户含未成年人就适用。

### 5.3 未成年人

- 【硬性】《未成年人网络保护条例》（国令第 766 号，**2024-01-01 施行**）：
  - 第 31 条：为未成年人提供信息发布、即时通讯服务的，须要求提供真实身份信息，否则不得提供服务（本项目是班级工具，不提供即时通讯，但"通知/反馈"接近信息发布，需评估）。
  - 第 32 条：不得强制要求未成年人或其监护人同意非必要个人信息处理；不得因不同意非必要处理而拒绝基本功能。
  - 第 34 条：提供查阅、复制、更正、补充、删除的便捷途径，不得设不合理条件；拒绝须书面说明理由。
  - 第 35 条：发生泄露等事件，须通知受影响的未成年人**及其监护人**。
  - 第 36 条：工作人员最小授权、审批、记录访问。
  - 第 37 条：**每年**合规审计并报告。
  - [中国政府网-未成年人网络保护条例全文](https://www.gov.cn/zhengce/content/202310/content_6911288.htm)
- 【硬性】未满 14 周岁：个人信息属**敏感个人信息**（个保法 28），须**监护人同意** + **专门个人信息处理规则**（个保法 31；网数条例 22）。
- **对本案**：2026 级本科同学绝大多数已满 18，但同班可能有个别 17 岁；只要存在未成年人用户，上述义务即适用（无人数门槛）。若未来面向高中/中职班级，风险显著上升。**建议**：在隐私政策中写明"本工具仅面向本校同班同学，不面向未满 14 周岁未成年人；如发现未满 14 周岁用户将删除其信息"，并对未成年人信息按更高标准（最小授权、单独告知）。
- 【硬性】《人工智能生成合成内容标识办法》不影响未保，但《移动互联网未成年人模式建设指南》（网信办 2024-11）是"指南"性质，若 App/小程序被认定主要面向未成年人，平台可能要求提供未成年人模式——**当前班级工具不属"主要面向未成年人"，暂不强制，需持续关注**（置信度中）。

### 5.5 隐私政策 / 用户协议必备条款清单

**隐私政策（可直接作为撰写清单）**
1. 处理者身份：个人姓名（或笔名）+ 有效联系方式（邮箱/微信号）+ 响应时限。
2. 处理目的与方式：身份核验（学号+姓名）、班级数据同步、访问统计、反馈处理、订阅通知。
3. 收集的个人信息种类（逐项列举）：学号、姓名、微信 openid（小程序）、访问日志（IP/UA/时间/页面）、反馈内容、体测记录（若收集）、通知处理的已读状态。
4. 敏感个人信息说明（若有）：种类、必要性、对个人权益的影响、单独同意方式。
5. 保存期限与到期处理：明确期限或确定方法（如"在校期间+毕业后 6 个月"），到期删除/匿名化。
6. 第三方共享/委托处理清单：云服务商（腾讯云/阿里云）、消息推送（微信订阅消息）、AI 服务商（若有）；各自处理目的与数据种类。
7. 数据出境说明（若有）：境外接收方、目的、种类、个人权利行使方式、单独同意。
8. 个人权利：查阅、复制、更正、补充、删除、撤回同意、注销账号的具体入口与流程、响应时限。
9. 未成年人条款：是否面向未成年人、监护人同意方式、专门规则（若涉<14）。
10. 安全措施：加密、访问控制、日志、应急。
11. 政策更新机制与生效日期。
12. 投诉举报渠道（含网信/电信/公安）。

**用户协议（建议同时提供）**
- 服务性质：非商业、班级内部、非官方（不代表学校/学院）。
- 使用资格：仅限本班同学，凭学号+姓名。
- 行为规范：不得上传他人隐私、不得外传班级数据、不得用于商业用途。
- 内容与数据归属：用户数据归本人；运营者可依申请删除。
- 免责与责任限制（注意：不能排除法定个人信息义务）。
- 终止与注销。
- 争议解决与适用法律（中国法律）。

> 微信对隐私指引的要求与上述隐私政策不完全等同：**隐私指引是平台合规表单，隐私政策是法律告知文本**，两者都要有且要一致。

## 7. 其他监管事项

### 7.1 网络安全等级保护（等保）

- 【硬性】《网络安全法》第 21 条确立等级保护制度；《信息安全等级保护管理办法》（公信安〔2007〕43 号）第 15 条：**已运营（运行）的第二级以上信息系统**，应在安全保护等级确定后 **30 日内**到设区的市级以上公安机关办理备案；新建第二级以上系统投入运行后 30 日内备案。
  - [工信部转载-信息安全等级保护管理办法](https://www.miit.gov.cn/jgsj/xxjsfzs/xxgk/art/2020/art_a981907528694176a61b5b52c2d19895.html)
- 【官方/行业口径·中高】**第一级系统无需备案、无需测评**，运营者自主落实基础防护；个人非经营性小站通常定级一级。
- 【经验·中】二级以上需测评（市场价约 2~8 万元/次，含整改），对个人项目不现实。
- **对本项目的判断**：
  - 若仅作为个人非经营班级工具、用户约 70 人：**一般定一级，无需等保备案/测评**（置信度中高，建议向属地公安网安口头确认）。
  - ⚠️ **但若被认定为"教育移动应用"**：教育 APP 提供者备案的前置条件明确包含"**网络安全等级保护定级备案**"（见 §7.4），这将把项目推向"必须做等保"的路径，个人几乎无法完成。

### 7.2 算法备案 / 生成式 AI / AI 内容标识

| 情形 | 是否触发 | 依据 |
|---|---|---|
| AI 摘要仅作为**开发/内部工具**，不对小程序/网页用户输出 | **不触发** | 算法推荐/深度合成/生成式 AI 规定均针对"向公众提供服务" |
| AI 摘要**对外**输出给用户（如自动生成通知摘要并展示） | **可能触发**：生成合成类算法备案（`https://beian.cac.gov.cn`）；若使用第三方大模型，需第三方算法备案 + 合作协议；微信类目"AI 问答/AI 创作"要求《互联网信息服务算法备案》 | [微信-开放服务类目"深度合成"](https://developers.weixin.qq.com/miniprogram/product/material/)、[算法备案系统](https://beian.cac.gov.cn/) |
| 对外输出 AI 生成文本/图片 | 还须遵守《人工智能生成合成内容标识办法》（**2025-09-01 施行**）：显式标识（文字/水印）+ 隐式标识（元数据） | [光明网转发全文（2025-03-14）](https://m.gmw.cn/2025-03/14/content_1303991405.htm) |
| 使用境外模型 API（OpenAI/Claude 等）对外服务 | 叠加**数据出境**与"生成式 AI 服务"合规问题 | 见 §7.3 |

- 【官方口径·高】算法备案填报入口：**互联网信息服务算法备案系统** `https://beian.cac.gov.cn/`（国家网信办），咨询电话 010-82990520/21；填报主体为"服务提供者"或"技术支持者"，生成合成类需填算法机制机理、应用场景、标识情况等。
- 【官方口径·高】广州市工信局《算法备案、大模型备案及登记指引》明确"涉及大模型的服务，需同时完成生成合成类算法备案与大模型备案/登记"。[广州市工信局指引（docx）](https://gxj.gz.gov.cn/attachment/7/7759/7759505/10110285.docx)
- **建议**：确认"AI 摘要"是否真的对用户可见、模型来源（境内/境外）、是否第三方已备案模型。若不可控，**先关闭该功能**再上架；若要做，按"算法备案 + AI 标识 + 境内合规模型"准备。微信类目若选"AI 问答"，算法备案是硬门槛。

### 7.3 数据出境

- 【硬性】《个保法》第 38~39 条 +《促进和规范数据跨境流动规定》（网信办令 16 号）：
  - 向境外提供个人信息需满足：安全评估 / 个人信息保护认证 / 标准合同 / 法定例外等之一；并**告知 + 单独同意 + PIA**。
  - **免申报门槛**：关键信息基础设施运营者以外的处理者，自当年 1 月 1 日起累计向境外提供**不满 10 万人**个人信息（不含敏感个人信息）→ 免予申报安全评估、标准合同、认证（第 5 条第（四）项）。
  - 10 万~100 万人 → 标准合同/认证；100 万人以上 或 1 万人以上敏感信息 → 安全评估。
  - [中国政府网-促进和规范数据跨境流动规定全文](https://www.gov.cn/gongbao/2024/issue_11366/202405/content_6954192.html)
- **对本项目的判断**（置信度中）：
  - H5 静态资源在**香港 OSS**：若仅公开静态 JS/CSS/HTML，**不含个人信息** → 不构成"个人信息出境"；但香港在数据出境制度中通常按"境外"管理（**需向省级网信部门确认港澳台是否适用**）。
  - 若把访问日志、反馈、班级名单、OCR 结果等存入香港 → 构成出境。
  - 后端在上海 → 境内。
  - 若调用境外 AI API 处理班级通知 → 构成出境（通知内容可能含个人信息）。
  - 70 人规模**远低于 10 万人免申报门槛**，但"告知+单独同意+PIA"义务不因规模豁免（第 10 条）。
- **建议**：静态资源放香港不构成实质风险，但**不要**把任何个人信息/日志写到香港；AI 只用境内已备案模型；如未来用户规模扩大或迁港，重新评估。

### 7.4 教育移动互联网应用程序备案（隐藏的重大风险 ⚠️）

- 【硬性】《教育移动互联网应用程序备案管理办法》（教技厅〔2019〕3 号）：
  - **第 2 条（定义很宽）**："教育移动应用是以**教职工、学生、家长为主要用户**，以**教育、学习为主要应用场景**，服务于**学校教学与管理、学生学习与生活以及家校互动**等方面的互联网移动应用程序。"
  - **第 9 条**："提供者应在完成**互联网信息服务（ICP）备案**和**网络安全等级保护定级备案**后，进行提供者备案。"
  - **第 10 条**："教育行政部门、学校、企业和社会组织均向其住所地或注册地省级教育行政部门进行提供者备案……**小程序、企业号等平台第三方应用统一到平台方提交备案信息，并由平台方向教育部共享备案信息**。"
  - **第 14 条**：省级教育行政部门应 10 个工作日内完成备案并编号，信息向社会公布；提供者应在应用中公示备案信息。
  - [教育部-教育移动互联网应用程序备案管理办法全文](https://hudong.moe.gov.cn/srcsite/A16/s3342/201911/t20191122_409333.html)
- 【官方口径·高】配套通知：2019-12-01~2020-01-31 为缓冲期，**2020-02-01 起未完成 ICP 备案和等保备案的教育移动应用备案将被撤销并通报**；备案依托国家数字教育资源公共服务体系（`http://app.eduyun.cn`）常态化开展。
- 【官方口径·高】**该平台 2025–2026 仍在运行**：2025-10 北京发布《北京地区教育移动互联网应用程序备案名单（白名单）》445 项。[北京日报报道（2025-10-30）](https://news.bjd.com.cn/2025/10/30/11379770.shtml)
- **对本项目的判断（置信度中，必须确认）**：
  - 班级工具站包含：作业、通知、课表、体测、点名、抽签——用于"学校教学与管理、学生学习与生活"，**从定义上高度接近教育移动应用**。
  - 若被认定为教育移动应用，则需：①ICP 备案；②网络安全等级保护**定级备案**；③提供者备案。其中：
    - ②与《信息安全等级保护管理办法》"第二级以上才需公安备案"存在**口径冲突**：若系统定级为一级，可能拿不出"等保备案证明"，而教育 APP 备案平台又要求该材料 → **一级系统如何提交须向教育部门确认**；
    - ③第 10 条明确"**小程序、企业号等平台第三方应用统一到平台方提交备案信息，并由平台方向教育部共享备案信息**"——即小程序的教育 APP 备案由微信平台代提交，**不等于个人可自行向教育厅备案**；个人主体是否被受理，办法只列了教育行政部门/学校/企业/社会组织，**未列个人，存在被拒可能**；
  - **规避策略（经验）**：产品定位为"班级内部事务工具/效率工具"，明确**不面向学校、不面向家长、不提供教学内容、不做家校互动**，类目选"工具"而非"教育"；页面不出现"教育""教学""学习""家校"等表述；不接学校采购/不进入学校官方渠道。**但定义是功能导向的，不能仅靠自我定位规避——建议主动向福建省教育厅（教育信息化处）书面咨询**，并保留答复记录。
- **确认路径**：教育部教育移动应用备案平台 `http://app.eduyun.cn`（有"备案查询"入口与技术支持 4001910910）；或福建省教育厅教育信息化相关处室；或通过微信小程序备案客服转问。

### 7.5 公安联网备案

- 【硬性】依据《计算机信息网络国际联网安全保护管理办法》（公安部 33 号令）：使用计算机信息网络国际联网的法人和其他组织，应自网络正式联通之日起 **30 日内**到公安机关指定受理机关办理备案。
- 【官方口径·高】入口：**全国互联网安全管理服务平台** `https://beian.mps.gov.cn/`（"联网备案登录"→网站用户注册→填写网站基本情况及开办者信息→属地公安审核）。[深圳公安-新办网站备案专题](https://ga.sz.gov.cn/ZT/HLWSYSQ/)
- 【官方口径·高】阿里云 App 备案指南：App 自开通之日起 30 日内需完成**公安联网备案**。
- 【经验·中】个人网站在各地执行不一（法规措辞为"法人和其他组织"），但**ICP 备案通过后再做公安联网备案是通行做法**；小程序一般不需要单独公安备案（小程序备案已含主体信息）——**需咨询属地公安网安确认**。

## 8. 结论与行动清单

### 8.1 三条可选路径（按合规成本从低到高）

**路径 A：只保留 H5（香港），不发布小程序/App**
- 合规成本最低：香港托管**无需 ICP 备案**（官方口径），不做小程序/App 就不触发小程序备案与 APP 备案。
- 但：无法上架小程序/App；若未来想上架，必须回到路径 B；且"境内提供服务但服务器在境外"在法律解释上仍有争议空间（**建议保持非公开、仅班级内部使用**）。
- 风险：个人合规压力主要落在 §5 个人信息（尤其群消息抓取必须停）。

**路径 B（推荐）：小程序 + 内地备案**
1. **先做个人信息整改**（§5.6 🔴 项）——这是任何路径的前置。
2. **决定小程序后端接入方式**（二选一）：
   - B1：**改走微信云开发/云托管私有协议**（`wx.cloud`/`callContainer`/AnyService）→ 免服务器域名、免域名备案（官方口径），但需技术改造与验证 CloudBase 个人版兼容性；
   - B2：**绑定已备案自定义域名**（如 `api.furina.fun`）：把 API 域名接入内地（阿里云内地 ECS/OSS 或腾讯云云开发），完成 **ICP 备案**（用腾讯云云开发环境作备案资源是官方支持的路径，见 [CloudBase-为域名完成备案](https://docs.cloudbase.net/icp/domain)），再在 CloudBase HTTP 网关绑定该域名。
     - ⚠️ 注意：`furina.fun` 是主域名，**备案主域名后所有子域名自动覆盖**；但**备案期间该主域名下不得有网站可访问** → 需要停机或改用新域名。
3. **做小程序备案**：mp 后台 → 备案 → 选"工具"服务内容 → 平台初审 → 12381 短信核验 → 管局审核 → 发布。
4. **类目**选"工具-信息查询/办公/预约报名"；名称避开教育词。
5. **配置隐私指引** + 小程序内隐私政策。
6. 发布后 30 日内评估公安联网备案（咨询属地公安）。

**路径 C：做原生 App（含 WebView 壳）**
