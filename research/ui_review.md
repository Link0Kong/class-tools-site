## 0. 结论摘要（TL;DR）

1. **现状不是"卡片小"，是"信息太少 + 排版没有纵向结构"**：桌面卡片 1178×216（宽高比 5.45:1），只占视口面积 20%，下方 662px 纯空白；移动端卡片 360×267，下方 718px（约 65%）空白。单纯放大卡片没用，必须把「趋势 / 指标 / 提示」这三类新内容做成有排布的结构，并让仪表盘**按视口高度撑满**。
2. **v3 任务书的方向正确**（环 + 趋势 + 指标 + 低电条 = 一眼回答"还剩多少 / 用多快 / 够几天"），但任务书缺了两件关键规格：**① 环的"分母"没有定义（不定义就是画假数据）；② 桌面"铺满"没有给高度规则（只做两栏，216px 的卡变 400px 卡，下面仍然空）**。这两点必须补进实现。
3. **配色不要再用 AGENTS.md 里的旧色值**：站点 v2.0.0 实际已被 Monet 调色板覆盖（`index.html` L576–617），电费页继承的是 `--surface:#FFFFFF` / `--line-strong:#E0D2BC` / `--cy:#5E8F87` / `--ink3:#8B948B`。新组件一律用 `var(--…)`，不要新增 `#F7F8F8` 这类历史硬编码 hex。
4. **对现有实现做体检后发现 2 个"必须修"的硬伤**：小字对比度不合格（`--ink3` 11px 仅 3.06:1，AA 需 4.5:1；状态 pill 3.22:1）、解释性文案共 4 处（违反 §1「不写解释性长段落」）。v3 若原样沿用这些样式等于把问题放大到更多元素。
5. 交付按「手机单列三段 → 平板横排 → 桌面 5:7 两栏并撑满视口」三档给到可落地数值（§B/§C），并附「上线前必须检查清单」（§E）。

## A. 改版前问题清单（10 条，按严重度）

> 格式：**现状** → **为什么是问题** → **具体改法（带数值）**。P0=用户主诉/必须修，P1=专业评审必须修，P2=建议修。

### A1【P0】空间利用率接近零，页面像"一张告示卡"

- **现状**：390 档卡片 267px 高、下方 718px 空白；1280 档卡片 216px 高、下方 662px 空白；桌面卡片宽高比 5.45:1。
- **为什么**：用户原话就是"充分利用空间"；视觉上页面重心堆在顶部 1/5，下面 2/3 是纯色背景，会被读成"没做完"。这不是移动/桌面某一端的问题，两端同时成立。
- **改法**：
  - 桌面（≥960）：仪表盘用「左 hero 卡 + 右趋势/指标」两栏，**整块 `min-height: max(620px, calc(100vh - 170px))`，两栏 `align-items:stretch`**；让 hero 环在左栏剩余空间垂直居中、右栏趋势图吃满剩余高度。1280×1000 下仪表盘高 830、1280×800 下 630，页面基本刚好一屏。
  - 手机（<720）：三段卡片流（hero → 趋势 → 指标 2×2），390×844 下总高约 890，**滚动约 1 屏多一点**，第一屏能看到 hero + 趋势 + 指标第一行，信息密度问题解决。
  - 中档（720–959）：hero 改为「左环 + 右信息」横排 + 趋势全宽 + 指标一行 4 格，768×1024 下整块约 854 高（`calc(100vh-170px)`），不留大洞。

### A2【P0】信息维度只有一个数字，回答不了"还够用多久"

- **现状**：页面唯一有效信息是 `382.02 度` + 「充足」+ 更新时间。
- **为什么**：学生看电费的决策问题是"要不要现在充值"。剩余度数单独看无意义（300 度可能是 5 天，也可能是 3 个月；还要看室友用电速度）。用户要的"视觉效果"本质是「信息可视化」——没有可比数据，画什么都会空。
- **改法**：用云端新增的 `power_history` 提供三件套（任务书已定，这里给口径）：
  - **近 24h 趋势**：折线 + 面积；不足 2 个采样点时显示"数据积累中"占位（固定高度，不塌）；
  - **估算可用天数**：`days = q / rateDay`，`rateDay = 区间用电 / 区间小时 × 24`（区间 <6h 不出天数，显示 `—`）；
  - **近 24h 用电**：`used = q₀ - q_now`（24h 内无充值前提下等于消耗；跨充值则需过滤，见 §C6 备注）。
  - 数值精度：主数值建议 `q>=100 → 整数（382 度）`、`q<100 → 1 位小数（22.3 度）`；趋势差值 2 位小数（−2.15 度）。**当前固定 2 位小数属于假精度**，且多出的字符挤占字号。tile 数值 1 位小数。

### A3【P1】视觉层级扁平：三种"白"叠在一起，没有主角

- **现状**：页面奶油底 `linear-gradient` → 白卡 `#FFFCF6` → 内嵌面板 `#FBF6EC`（L776），三层都在同一色相/明度带；唯一对比来自 44–58px 的数字。桌面 hero 面板 720×127，没有背景/渐变/装饰，数字几乎"浮"在面板里。
- **为什么**：视觉层级不是靠字号一个维度撑起来的；没有"容器层级 → 焦点区 → 状态色"的三级结构，放大字号只会显得空。当前卡片与页面背景的对比只有一层 1px 边框 + 极浅投影（`--elev-card` 在 1280 下几乎看不出）。
- **改法**：
  - hero 区给"焦点面板"：`border-radius:18px; background:linear-gradient(160deg,#FFFFFF 0%,#F6FAF7 100%)`（低电切到 `linear-gradient(160deg,#FFF8F6,#FFFCF6)`）；面板内上 12 / 左右 18 / 下 16 的内边距；环为唯一大图形。
  - 卡片层级固定为 3 档：页面底（奶油渐变）→ 数据卡（`--surface` 白 + `1px --line-strong` + `--elev-card`）→ 卡内面板/环（`--tint-panel` 或浅渐变）。**同一页面不要再出现第 4 种白**。
  - 桌面下 hero 面板建议改为「无边框、直接融入 hero 卡」，把"面板"层级让给环本身，减少一层边框（见 §B2）。

### A4【P1】状态语义弱 + 状态 pill 对比度不合格

- **现状**：正常态 `.pw-state` = 11px / `--cy #5E8F87` on `#E9F3F0`，**实算 3.22:1（AA 小字需 4.5:1，不合格）**；低电 pill `--danger #B87870` on `#FBECEA` 也仅 ~3.2:1。低电时只是数字变红 + 一个 11px 小胶囊，没有（任务书要加的）提示条。
- **为什么**：用颜色表达状态时，文字本身必须可读；11px + 3.2:1 在手机微信 WebView 的灰度/弱光环境下几乎看不清。且"低电"对用户是需要行动的信号，视觉权重却低于"充足"，语义反了。
- **改法**（全部通过 AA）：
  - 状态 pill：`充足` → 文字 `#2F6555` on `#EAF2EC`（**5.91:1**）；`偏低` → `#8A6A3E` on `#FAF3E6`（**4.52:1**）；`低电` → `#8F5550` on `#F7EDEB`（**5.10:1**）。字号 12–12.5px / 700。
  - 状态三档阈值（建议写进代码常量并在 `sync_power_cloud.py` 注释同源）：`q<30` 低电（红）、`30≤q<60` 偏低（暖沙）、`q≥60` 充足（雾青）。低电时**数字 + 环 + pill + 提示条同时变红**，权重最高。
  - 低电提示条：`#F7EDEB` 底 / `#EEDBD7` 边 / `#8A5049` 文字（**5.50:1**）/ 13px 700，高 48–52。

### A5【P1】小字系统性低对比（多处不达 AA）

- **现状**（实算，背景取现行 token）：`--ink3 #8B948B` on `--surface #FFFCF6` = **3.06:1**；on 页面底 `#F4F0E6` = **2.75:1**。使用位置：`lgsub`（11.5px）、`pw-upd`（10.5px）、`pw-foot`（11px）、`pw-guide`（13px）、`.stsum` 标签（11px，全站同类）、`.rollstat` 标签（11px）。`--danger #B87870` on 白 = 3.44:1（大字可、小字不可）。
- **为什么**：这是全站性问题，但电费页 v3 会**新增更多小字**（轴标签、tile 标签、delta chip），如果不先换色，新页会继承并放大问题。
- **改法**：
  - 有信息量的正文/标签统一改用 `--ink2 #5C6860`（on 白 **5.69:1**、on `--tint-panel` 5.41:1），`--ink3` 只用于纯装饰/禁用态（或字号 ≥18.66px 的大字）。
  - 字号下限：正文/说明 ≥12px（12px 600 可读），轴标签 ≥10.5px 且用 ink2；**不要**再把关键信息做成 10.5–11px ink3。
  - 数字类一律 `font-variant-numeric: tabular-nums`（现状主数值已加，保留）。

### A6【P1】同一信息重复出现，页面"看着短"却还冗余

- **现状**：房间名出现 2 次（`lgsub` 副标题、hero 内 `.pw-roomname` 13px）；更新时间出现 2 次（`lgsub` 的「更新 11-05 22:45」+ hero 内 `.pw-upd` 10.5px）。桌面 1280 截图中同一行文本来回出现。
- **为什么**：重复让信息密度"虚高"——看起来有两行信息，其实只有一行；同时挤占了本可以放趋势/指标的空间。也违反"不堆砌"。
- **改法**：**一个信息只出现一次**：房间名只在下拉（选中值）与 hero 的大字区上方出现（若保留 `lgsub` 就删 hero 里的 `.pw-roomname`，二选一）；更新时间只在 hero 状态行出现（`更新 06:12`），`lgsub` 改为空或房间名，**不再重复时间**。

### A7【P2】解释性文案 4 处，直接违反 §1 设计红线

- **现状**：`lgsub`「关注一个宿舍，查看剩余电量」、`pw-guide`「选择你要关注的宿舍，只看这一间」、`pw-foot` 未选择「选择保存在账号里，换设备登录会同步」、`pw-foot` 已选择「剩余电量 < 30 度标红 · 数据来自完美校园，约每小时同步」。
- **为什么**：`web/AGENTS.md` §1 明确「不要多余的说明文字：能用标签、占位符、`<b>` 表达的信息，就不要写成句子」。4 句里没有一句是必须的：阈值可以做成一个 tile，同步频率可以做在时间旁边的小 chip，未选择态用下拉 placeholder 表达。
- **改法（逐条）**：
  - 删 `lgsub` 副标题（标题只留「宿舍电费」）；
  - `pw-guide` → 环中心显示 `—` + 下拉自身 placeholder「选择你要关注的宿舍…」（已存在），不再另起一句；
  - 未选择的 foot → 删除（信息在 placeholder 里）；
  - 已选择的 foot → 改为 tile「低电阈值 30 度」或 `(<30 度)` 的 11.5px ink2 小标签，不要再写成完整句子。
  - **保留**唯一的"提示"是低电提示条，且写成数据句（「剩 22.25 度 · 约 1 天」），不是说明句。

### A8【P2】加载/刷新/切换反馈弱，布局会跳

- **现状**：`POWER.pull()` 里刷新按钮只做 `disabled=true + opacity .55`（L3340/L3357），无文案变化；切换宿舍立即 `POWER.row=null` 再 `render()`，hero 变成「加载中…」（`pw-guide`），**内容高度从 70/96px 起跳**；错误态只把一行字变红。全站已有 `.skel` 骨架组件（L451–458）和 `--ui-dur` 动效变量，但电费页没用。
- **为什么**：刷新按钮按下去"没反应"（尤其 1 秒内返回时），用户会重复点；切换宿舍时高度跳动 + 空白占位是典型的廉价感来源。v3 的环/图占位更大，跳变更明显。
- **改法**：
  - 刷新按钮：加载中 `disabled + aria-busy="true"` + 文案「刷新中」，**按钮宽度固定 min-width 72px 防抖**；结束恢复「刷新」。
  - 切换宿舍：不清空为一行文字；hero 保持环轨道 + `—`，趋势/指标保持高度显示静态占位（不上 shimmer 循环动画，遵守 task-8"不动画循环"，用 180ms 淡入即可），数据回来后填值——**DOM 高度全程不变**。
  - 错误态：hero 保持占位，提示行 `--danger` 13px + 刷新按钮可点；不要整块消失。

### A9【P2】空状态（未选择）是"最空的一屏"，没有为选择做视觉引导

- **现状**：未选择时卡片 267px 高，内只有一行 `pw-guide`（13px ink3 3.06:1），下方 718px 空白；下拉默认项「选择你要关注的宿舍…」。截图 `power_unselected_390.png` 里页面几乎全空。
- **为什么**：未选择是**新用户第一屏**，最需要引导；现在它比已选择状态更空，且下拉本身没有视觉强调（看起来像普通输入框）。
- **改法**：
  - 未选择时保留完整仪表盘骨架：hero 环用虚线轨道 + 中心 `—`；趋势卡显示「数据积累中」空基线；指标 tile 全部 `—`。**页面高度与有数据时一致**（无跳动）。
  - 下拉加"待选择"强调：`border-color: var(--cy)` 40% 或左侧 3px 雾青竖条 + 首次进入时 `:focus-visible` 提示（不弹窗、不加说明句）。
  - 已选择后下拉恢复常规边框。

### A10【P2】断点行为粗糙：768 无专属布局、≥1440 卡片不随容器、时间语义缺失

- **现状**：只有 720/960/1200/1440 的字号变化（44→54→58→64→70，L735/746/754/778/834/841）；**768 平板与 390 手机完全同一单列布局**；`#s-power .card{max-width:1180px}`（L835）而 `.wrap` 在 ≥1440 是 1292 宽（1440）→ 卡片左右各缩 56px，与上方 tabs 不对齐；≥1440 只是把数字放到 70px，布局没变化。时间只显示绝对 `MM-DD HH:mm`（L3327–3332），没有"多久前"。
- **为什么**：平板是真实使用场景（宿舍 iPad/笔记本 768–1024），单列会把内容拉得很长；宽屏错位会被用户看成"没对齐"；数据每小时同步，用户需要判断"这点数是不是几小时前的"。
- **改法**：
  - 断点：`<720` 单列；`720–959` hero 横排 + 趋势全宽 + 指标一行 4 格；`≥960` 5:7 两栏；`≥1440` 仪表盘 `max-width:min(1320px,100%)`（与全站 `#allCards` 的 1320 上限一致），环 224 / 数字 72。
  - 桌面容器：删掉 `#s-power .card` 的 1180 限宽，改仪表盘容器 `max-width:min(1320px,100%)`；1280 下与 tabs 对齐（内容宽 1188），1440 下也对齐（1292）。
  - 时间：`更新 06:12` + 相对 chip「*2 小时前*」；>90 分钟用 `--warn` 沙色小圆点提示延迟；跨天显示「昨天 22:45」。不要加长句。

### C5 电量环（v3 核心组件）

**必须先定"分母"**（这是任务书里缺的，不定义就是画假数据）：

> v3 现状（06:45 落盘代码）：已采用 `PW_REF=400` 的**固定度刻度**（`arc = q/400` 封顶），但页面/无障碍都没有标注"满环=400 度"——见 §F2/N2。下面的方案仍作为修正方向，二选一即可，**不能维持"无说明的固定刻度"**。

- **推荐：环 = 估算可用天数仪表，刻度 0–30 天封顶。**
  - `days = (q) / rateDay`，`rateDay = 区间用电 / 区间小时 × 24`（区间 ≥6h 才显示；否则 `—`）
  - `arc = clamp(days / 30, 0, 1)`；`days ≥ 30` → 满环，环内小字「≥30 天」
  - 环色 = 状态色（充足雾青 / 偏低暖沙 / 低电红），**不按 arc 大小改色**（避免"22 度但 11 天"绿色环与低电红 pill 打架）
  - 环内大字 = 剩余电量（主角），下方 11.5px「≈163 天」；aria-label =「剩余 382.02 度，估算可用约 163 天」
- **备选 A（不依赖历史，当天可用）**：环 = 0–100 度刻度（`arc = clamp(q/100,0,1)`，30 度低电 = 刻度 30%）。优点：无历史也有意义；缺点：「满环=100 度」是人为约定，需写进注释/aria。
- **备选 B（不推荐）**：纯装饰环（固定弧长）——等于伪造数据，评审不建议。

### C6 趋势折线（近 24h）

- 容器：`position:relative`，`height:132(390) / flex-fill(桌面)`；SVG `width:100%;height:100%;preserveAspectRatio="none"`（横向拉伸可接受）或 `viewBox="0 0 340 132"`。

### G6 最终三档结论（给 Lead）

#### 必须修（阻塞上线，仅 1 条）

**M1 桌面右栏比例失衡**（1280/1440：趋势卡 700/600px、图 ~620/520，tiles 仅 72px）。
- 位置：@media(min-width:960px) 的 .pw-side / .pw-trend-card / .pw-tiles，以及 @media(min-width:1200px) 里的 .pw-tiles{grid-template-columns:repeat(4,…)}（L829）。
- 改法（约 8 行）：
`css
@media (min-width:960px){
  .pw-side{display:grid;grid-template-rows:minmax(320px,1.3fr) minmax(240px,1fr);gap:12px}
  .pw-tiles{grid-template-columns:repeat(2,minmax(0,1fr))}   /* 删除 ≥1200 的 4 列规则 */
  .pw-trend-card{height:100%}
  .pw-tile{min-height:120px;display:flex;flex-direction:column;justify-content:center}
}
`
- 效果：1280×1000 时 trend≈440（图≈360）、tiles≈340（每格≈163）；1440×900 时 trend≈390（图≈320）；仍满屏、比例正常。
